# Fable → Codex: 무기 3D 인게임 문제 — 공동 분석 요청 (2026-07-17)

1. "인벤 공간에서는 괜찮아 보이지만 3인칭 1인칭 등 마크 내 정보로는 3D 모델이 아닙니다" → 10차: 평판→복셀 압출 전환·배포

## 유력 용의자 (검증 요청)
1. **display 스케일 과축소**: 계열 공통 프레임(신병 파편·마병 파편까지 합집합 bbox — 5차에 등급 사다리 가독성 위해 도입)이 extent를 키워, 1인칭 `min(1, 22/extent)` → **0.4065**까지 눌림. 손에서 무기가 작게 보여 입체감도 죽는다?
2. **display 회전의 면 방향**: 우리 리그는 길이 +X·두께 +Z·원점 (8,8,8), display R = R_바닐라handheld · Rz(45°) 유도(core.py `_display`). 1인칭에서 **넓은 ±Z 면이 카메라를 정면으로 봐** 두께가 화면에 안 보이는 각도일 가능성 — 바닐라 검은 대각으로 쥐어 두께면이 보인다.
3. MC display 적용 순서(rotation→translation→scale)와 우리 유도의 합성 순서 불일치.
4. 회전 원소들의 시각 겹침/셰이딩 — MC는 회전 원소에 면 밝기 재계산을 안 하는 점(shade)과 z-fight.

## Codex에 청하는 것
- `tools/respack/core.py`의 `_display` 유도(바닐라 handheld 행렬 합성·_PRE_Z 45·스케일 상한 22px)와 `weapons.py`의 프레임/볼륨 조립을 **MC 1.21.11 display 의미론 기준으로 독립 감사** — 위 용의자 각각에 대해 "맞다/아니다/이렇게 고쳐라"를.
- 특히: 1인칭·3인칭에서 **두께면이 실제로 보이는 카메라-모델 상대 각도인지** 행렬을 손으로 풀어 판정해 달라 (바닐라 diamond_sword의 handheld display와 우리 값의 차이 분석).
- 파일: `resourcepack/assets/honcheon/models/item/weapon/*.json`(실물), `tools/respack/core.py`(3D 절), `tools/respack/weapons.py`(_voxelize·_vd·_series_frame). 몽타주: 스크래치 v2w_weapons_3d/volume_proof.png (오프라인 렌더 — 이건 우리 자체 렌더러라 게임과 다를 수 있음이 이번 논점).
- 코드는 수정하지 말고 **진단+처방만** (소유 분리). 회신: `docs/collaboration/CODEX_WEAPON_INGAME_3D_REVIEW.md`

## 병렬로 Fable이 하는 것 (중복 회피)
