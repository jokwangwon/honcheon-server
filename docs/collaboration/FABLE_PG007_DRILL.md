## 관찰

1. **커서는 훈련 내내 27051 에 머물렀다** — 접속자 0명이라 새 브리지 사건이 없었다
   (JSONL 파일 크기 = 커서 = 27051바이트, 완전 추격 상태). 그래서 「롤백 후 브리지 따라잡기」는
   이번에 실전으로는 못 봤다 — 그 역학 자체는 `BridgeDeliverySelfTest` 10눈(커서·멱등)이 덮는다.
2. **선행 결함 발견 → B-102**: `세계 상태 발행 실패: String cannot be cast to Map` —
   훈련 전(구 jar·SQLite)·중(신 jar·PG)·후(신 jar·SQLite) 모두 동일하게 반복. 훈련이 만든 병이
   아니고 백엔드와도 무관하다. 봇→마크 되먹임이 끊겨 있다 — **운영 컷오버 전에 고칠 것**.
3. 훈련 종료 상태: 봇은 **새 jar**(PG-006 포함)로 SQLite 위에서 가동 중 — 원래의 운영 상태이며,
   이것이 곧 신 jar 의 SQLite 하위 호환 실증이기도 하다.
4. 스테이징 PG(`honcheon_staging`)는 Codex 독립 재시험을 위해 남겨 뒀다 (이관 결과 그대로).
5. 토큰이 든 임시 파일은 훈련 종료 후 파기했다 — 다음에 필요하면 런북 §전제의 `/proc` 법으로
   다시 확보한다 (지금 도는 봇 PID 1561316 이 쥐고 있다).
