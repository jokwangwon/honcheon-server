# 상호 검토와 단독 인계 규약

## 상호 파악

- 소유자는 시작, 재현, 첫 수정, 검증 완료마다 자신의 작업 로그를 갱신한다.
- 검토자는 상대 로그와 diff를 읽고 자신의 `*_REVIEW.md`에 사실 확인, 위험, 제안을 남긴다.
- 소유자는 제안을 `수용`, `보류`, `거부`로 답하고 근거를 작업 로그에 남긴다.
- 검토자는 소유 중인 프로덕션 파일을 직접 수정하지 않는다.

## 단독 작업

- 상대가 접속하지 않았거나 검토하지 못해도 소유자는 작업할 수 있다.
- 이 경우 수정 전 재현, 관련 self-test, 수정 후 관련 감사, `backlog_audit.py`를 모두 기록한다.
- 인게임 검증이 필요한 항목은 정적 검사만으로 닫지 않는다.

## 인계와 인수

- 작업 로그에는 항상 재현 명령, 현재 가설, 수정 파일, 미실행 검증을 포함한다.
- 넘기는 쪽은 `ACTIVE_V2.md` 상태를 `인계 가능`으로 바꾸고 편집을 멈춘다.
- 받는 쪽은 소유자를 자신으로 바꾸고 자신의 로그에 인수 사실을 기록한다.
- 예상하지 못한 상대 변경이 보이면 양쪽 모두 멈추고 충돌을 문서화한다.
- 사용자가 한쪽만 작업하도록 선택하면 같은 절차로 모든 활성 작업을 그 주체가 인수할 수 있다.

## 검토 로그 형식

```markdown
## YYYY-MM-DD HH:MM - 대상 작업
- 읽은 로그와 diff:
- 확인한 사실:
- 위험:
- 제안:
- 인수 가능 여부:
```
