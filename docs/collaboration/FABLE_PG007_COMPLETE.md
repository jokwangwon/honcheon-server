- **컷오버**: 실 봇 정지(확인) → 정지 시점 기록 → 백업 → PG-005 도구로 이관(검산 다섯 축 ✅)
  → PostgreSQL 백엔드 기동(`DB: postgresql` · JDA 로그인) → 사람 눈(디스코드 `/혼천 정보` 응답).
- **롤백**: PG 봇 정지(확인) → SQLite 백엔드 재기동(`DB: sqlite`) → 상태 5/5 완전 일치
  (커서·현재일·bridge_inbox·characters·events — 정지 시점 기록 그대로).

  실전에서도 지켜졌고, 롤백의 근거가 그래서 살아 있었다.
- 절차의 급소가 런북에 박제됐다: **죽이기 전에 토큰 확보**(`/proc/<pid>/environ`) ·
  **정지 확인 없이 다음 단계 없음** · 이관 실패 시 대상은 도구가 이미 롤백함 · 중단 기준 3종.

## 남은 위험 (운영 컷오버 전 필독)

1. **★ B-102 를 먼저 고쳐라**: 세계 상태 발행(봇→마크 `world_state.json`)이 ClassCastException
   으로 계속 실패 중이다 — 훈련 전부터 있던 선행 결함(백엔드 무관). 되먹임이 끊긴 채로
   운영 전환하면 안 된다.
2. **운영 PG 는 영속이어야 한다**: 훈련은 `--rm` 컨테이너로 했다. 운영은 볼륨 있는 인스턴스에만.
3. **브리지 따라잡기는 실전 미관측**: 훈련 중 접속자 0명이라 새 사건이 없었다. 역학은
   `BridgeDeliverySelfTest` 가 덮지만, 운영 컷오버는 사건이 흐르는 시간대를 피하거나
   (정지 중 유실 없음 — JSONL 은 쌓인다) 컷오버 후 커서 전진을 반드시 확인하라.
4. **관찰이 짧을수록 롤백이 싸다**: PG 기간의 디스코드 직접 쓰기는 롤백 시 SQLite 에 없다
   (브리지 사건만 따라잡힌다). 전환 선언 전 관찰 창을 짧게.
