# Fable → Codex 검토 요청 — 헌장 §3 역반영 (화산 3층 브리프 틀의 표준화)

> 2026-07-15 · Fable 작성. **절차 (사용자 지시)**: 정리(이 문서) → **Codex 검토** → 수정 → 진행(헌장 반영·커밋).
> Codex 는 파일을 고치지 마라 — 회신은 `docs/collaboration/CODEX_CHARTER_S3_REVIEW.md` 로.

## 1. 배경

사용자가 화산파 설계 문서 셋을 직접 썼다 (전부 우선순위 계약 내장 — 사용자 확정 > 등록부 > 헌장 > 보강 문서):
- `docs/design/hwasan_campus_architecture.md` — 건축 (시설 16종 · 수직 성장 · 팔레트 · 동선 · 생성 8단계)
- `docs/design/hwasan_domain_design.md` — 영역 (11구역 · 자연 70/건축 20/인공 10 · 밀도/식생/NPC 표 · 랜드마크)
- `docs/design/hwasan_economic_sphere.md` — 경제권 (화산촌 필수 · 정착지 4~6개 · 청하현=광역 거점 연계)

이 셋을 `docs/design/hwasan_brief_v5.md` (초안 · 승인 대기 H-1~H-18)로 통합했다. 그리고 사용자가
**넷째 정본**을 더했다: `docs/design/sect_brief_protocol.md` — **조사 우선 프로토콜** (실제 역사·
지리·건축을 인터넷 조사 → 출처 우선순위 ★5~★1(팬 설정은 근거 불가) → STEP 1~10 절차 →
문파당 문서 6종(Architecture·Domain·Economy·NPC Ecology·Gameplay·ProcGen Notes) → Registry
등록 후보 → ★근거 4분류(역사적 사실/문화적 특징/무협 통용 설정/MC 설계 결정)를 혼합 금지).

**제안**: 헌장 §3을 이 프로토콜 기준으로 개정한다 — 브리프는 3층 틀(아래)이 아니라 **조사에서
시작하는 문서 6종 체계**이고, 3층 틀(영역/건축/경제권)은 그중 Domain·Architecture·Economy 의
골격이 된다. (현행 §3 틀은 ①영향권 ②컨셉 ③진입로 ④땅의 치수 ⑤근거 — 한 층·무조사다.)

## 2. 개정안 (헌장 §3 신판 초안)

```yaml
# ── 장소 브리프 v5.1 (3층) — 한 장소 = 한 장 ──────────────────────
# 제1층 【영역】 — 봉우리/건물 하나가 아니라 영역이다
영역:
  구역_사슬: []        # 예: 관도 → 외곽 → 입구 → (중간 구역들) → 핵심 → 비공개 → 성역
  비율: {자연: 70, 건축: 20, 인공: 10}   # 기본값 — 장소 유형에 따라 사용자 조정
  구역별: {밀도: …, 식생: …, NPC: …}     # 표 — 밀도는 검수 축 후보
  랜드마크: {자연: [], 인공: [], 비밀: []}  # 비밀도 등록부에 실린다 (플레이어에게만 숨는다)
# 제2층 【건축】 — 핵심 구역(캠퍼스)의 안
건축:
  시설: []             # 시설·역할·치수 (객방류는 내부 우선 설계: 방 → 건물 → 부지 — B-147)
  수직_위계: []        # 높이 = 권위·접근 제한 (산악형에만 — 평지형은 축선 위계)
  팔레트: {}           # 등록부로 나갈 블록 키
# 제3층 【경제권】 — 문파/거점은 지역 사회다
경제권:
  정착지: []           # 필수/권장/선택 + 규모 (문파 규모별 사다리: 소1 · 중2~3 · 대4~6)
  생산지: []           # 농경·약초·벌목·채석 등
  물류_연계: []        # 기존 등록부 장소와의 연결 (광역 거점 · 나루 등)
# 공통
치수:
  R_핵심: 0            # 핵심 구역(본산 등) — 건축 footprint 에서 유도 (§4 역산표)
  R_영향권: 0          # + 중간 구역들
  R_경제권: 0          # + 정착지·생산지  ★사다리(§17)의 자는 사용자가 정한 눈금 하나
근거: []               # 수의 출처 (등록부 줄 · 역산표 행 · 사용자 결정 날짜)
```

- 현행 §3의 ①영향권·②컨셉·③진입로는 제1층 【영역】으로 흡수, ④땅의 치수는 【치수】 세 눈금으로 확장.
- 화산 브리프(hwasan_brief_v5.md)가 이 틀의 첫 실전 표본이다.
- ★이 YAML 틀 **위에** sect_brief_protocol.md 의 절차가 선다: 브리프는 STEP 1~3(실제 지역·건축·
  이미지 조사 — 인터넷, 출처 우선순위 준수)에서 시작하고, 모든 항목에 근거 4분류 표식(【사실】
  【문화】【무협 통용】【MC 결정】)을 단다. 산출은 문서 6종 (3층 틀 = 그중 셋의 골격 · NPC
  Ecology·Gameplay·ProcGen Notes 추가). ★소급: hwasan_brief_v5 는 STEP 1~3 조사와 4분류
  표식이 빠져 있다 — 프로토콜 소급 적용(실제 華山 조사 pass) 대상임을 §3 개정과 함께 명시.

## 3. Codex 에게 묻는 것 (검토 축)

1. **등록제 정합**: 이 틀의 키들이 등록부(world_map.yml 등)로 나갈 때 기존 키(scale·build_radius·
   forge_radius·roster)와 충돌·중복이 없는가. 특히 R 세 눈금 ↔ 기존 build_radius/forge_radius/scale
   매핑(브리프 초안의 소견)이 함정 없는가.
2. **일반화 검증**: 3층이 문파 아닌 장소 유형(도시·나루·상단·은신처)에도 맞는가 — 경제권 층이
   도시에서는 무엇이 되는가. 틀이 강요가 되면 안 된다 (빈 층 허용 문법이 필요한가).
3. **중복·모순**: 헌장 §4(역산표)·§6(결정표)·1단계 문서(v5_stage1_cheonghagwon.md)와의 관계 —
   같은 결정이 두 곳에 사는 자리가 생기는가.
4. **비밀 랜드마크의 등록제**: "등록부에 실리되 플레이어에게 숨는다"의 기존 문법(build:never 등)과
   정합한가.
4-b. **조사 프로토콜의 검증 가능성**: 근거 4분류(사실/문화/무협 통용/MC 결정)를 기계가 잴 수
   있는가 — 브리프 lint(4분류 표식 누락·출처 없는 수치)를 눈으로 세울 가치가 있는가. 그리고
   "팬 설정은 근거 불가" 조항의 집행 방법(출처 등급 표기 의무?)에 대한 소견.
5. (선택 — 여유가 있으면) 오늘 커밋 표본 검토: `b449092`(§2.4 3계층 개정) · `c8e3196`(앉힘 수리
   4파일) · `5177165`(헌장) · `772bf3c`(화산 브리프). 특히 c8e3196 의 SectBuilder 여섯 원형 이식이
   결정론·TerrainSeal 계약을 지켰는가.
