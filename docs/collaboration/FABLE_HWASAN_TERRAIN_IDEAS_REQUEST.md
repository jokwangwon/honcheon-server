# Fable → Codex 요청: 화산 산세 「돌산 인상」 — 접근 아이디어 (2026-07-16)

> **사용자가 화산 산세를 도보로 세 번 보고 「인상이 이상하다」고 한다.** 세 번 반복 재설계했으나
> 아직 안 잡힌다. 코드 튜닝이 아니라 **생성 접근 자체**에 대한 신선한 아이디어를 청한다.
> (설계 판단·초안 — 규약대로 정본에 절 추가 또는 `CODEX_*` 문서로. 지어내지 않는다.)

## 0. 목표 — 무엇을 만들려는가

**화산(華山) 산세** = 무협 문파 화산파의 근거지. 사용자가 말하는 레퍼런스:
- 실제 **華山**: 다섯 봉우리(東朝陽·西蓮花·南落雁·北雲台·中玉女)의 **가파른 화강암 첨봉**들이
  좁은 능선(蒼龍嶺 칼능선)으로 이어짐. 전각이 봉우리 아래 능선·단에 얹힘.
- **화산귀환(만화)**: 그 돌산 군집의 무협적 형상.
- 사용자 원문 요구(도보 피드백 3회): ① 「돌산」(바위산·가파름·울퉁불퉁) ② 「**여러 산이
  조율적으로 붙은**」(큰 산 하나에 봉우리가 붙은 게 아니라, 여러 독립 산이 이어진 지대)
  ③ 건물 부지는 꼭대기가 아니라 **살짝 아래, 조그만 봉우리들이 감싸 안은** 자리.

## 1. 불변 제약 (envelope — 사용자 확정 · 바꾸지 말 것)

- **밑감 superflat** (평지). 바닐라 지형 없음 — 산·바위·나무 전부 절차 생성.
- **결정론 헌법**: 난수 0. 모든 흔들림은 **좌표 해시 보간 + 저주파 사인/가우시안**(같은 좌표 →
  같은 땅, 타일 무관). `config/terrain_grain.yml` 격자 잡음 문법.
- **B-155 z=0 연속성**: 인접 블록 급단차 상한(자기시험 SEAM_STEP_MAX=6). 벼랑 금지(자연면).
- **치수 확정**(H-6·H-7·H-8): lift(최고 높이) **160** · footprint_radius_min 124 · build_radius
  128 · domain_extent 294 · economy_extent 444 · 물매 계약 1:1 안 · 8칸 격자.
- **보행/건축 자리는 평탄해야** — 건물 단·능선 보행선·등산로는 crag 끔(calm). 험한 건 사면.
- 순수 함수 `reliefAt(x,z)→높이`, `zoneAt(x,z)→구역`, `surfaceY`. Bukkit 무의존(오프라인 렌더 가능).

## 2. 지금까지의 여정 (무엇을 시도했고 사용자가 뭐라 했나)

| 회차 | 모델 | 사용자 반응 |
|---|---|---|
| 1 | 단일 원뿔(radialBody) + 오목 프로파일(1−t^0.85) | "너무 완만·매끈해 산이 멀어 보인다" |
| 2 | 발치 볼록((1−t)^0.85)으로 산기슭 경사↑ | "돌산답지 않게 완만·곡선. 울퉁불퉁 유지 원함" |
| 3 | crag 진폭 7.5→19.7(5옥타브) + 곁능선 위 봉우리 4 (단일 돔 위에) | "**큰 산에 봉우리가 붙은** 느낌. 여러 산이 붙은 걸 원함" |
| 4 (현재) | 단일 돔 폐기 → mesa 캡 + soft-max 첨봉 5 + 중앙 낮은 court | "**인상이 이상하다**" (아직 안 잡힘 — 무엇이 어긋나는지 사용자도 콕 집진 않음) |

## 3. 현재 모델 (회차 4) — 기술 구조

정본 코드: `server-mvt/src/main/java/com/honcheon/mvt/forge/RangeField.java` (커밋 최신). 합성:
```
H(x,z) = clusterCap( mesaCap(max(radialBody, mainRidge, sideRidges…) − gorge), 봉우리들, court ) + crag
```
- **mesaCap**: 옛 세 항(중앙에서 crest→lift=160)을 `min(88, ·)`로 캡(88=crest(honsanR)). 중앙
  최고 돔 소멸, 바깥 skirt(r≥124)는 옛 그대로 → 등산로·곁구역 무영향.
- **clusterCap**: mesa 대지(88) 위에 **가파른 원뿔 첨봉 5개**(높이 148~157·반경 σ44~50) +
  **중앙 court**(118, 평탄반경 30) 를 **soft-max(log-sum-exp, α=0.45)** 로 합성. soft-max가
  인접 봉 만남선을 들어 올려 **안부(바깥보다 높은 능선)**로 봉을 잇는다.
- 봉 배치: 서 −100°/동 +100°/북 180°/남서 −50°/남동 +50° (남축 비워 등산로·조망 개구).
- **crag**: 5옥타브 사인, 진폭합 ~19.7. 봉 사면·안부만 거칠고 court·능선·등산로는 calm.
- 오프라인 렌더 수치: 중앙(0,0)=**118** · 봉 5개 **148~157**(편차 8) · 봉 사이 안부 97~104
  (바깥 r85의 +6~10). 상단뷰: **봉 링 + 중앙 어두운 낮은 품**(단일 돔 삼각형 아님).

## 4. 청하는 것 — 「인상이 이상하다」의 진단과 접근 아이디어

사용자가 콕 집진 않았으니 **당신이 무엇이 인위적으로 읽히는지 진단**해 달라. 후보 가설(우리 짐작):
- **너무 규칙적** — 봉 5개가 균등 방위·균등 높이(편차 8)라 자연 산이 아니라 「배열」로 읽히나?
- **봉이 원뿔** — 가우시안/원뿔 첨봉이라 실제 화강암 첨봉의 **날·벽·비대칭**이 없다.
- **능선이 약함** — soft-max 안부가 「봉을 잇는 날카로운 능선」이 아니라 「봉 사이 완만한 둔덕」.
- **스케일** — economy_extent 444(지름 ~888칸)에 봉 5개면 봉이 너무 크고 뭉툭? 華山은 첨봉이 날카롭다.
- **중앙 court가 인위적** — 원형 평탄 court가 「자연이 판 골」이 아니라 「인공 원반」으로 보이나?

청하는 아이디어 (코드 아니어도 됨 — 접근/원리):
1. **생성 원리** — 봉-원뿔 합성이 옳은가? 대안: **ridged multifractal noise**(능선형 프랙탈 —
   결정론 좌표 해시 위에서), **도메인 워핑**, **보로노이 산등성이**, **침식 근사**(경사 누적으로
   골을 파 능선을 날카롭게) 중 무엇이 「화강암 다봉」에 맞나. 우리 제약(난수0·해시 결정론·
   B-155 연속성·평탄 건축 자리·envelope) 안에서 실현 가능한 것으로.
2. **자연스러운 불규칙** — 봉 수·방위·높이·날의 비대칭을 어떻게 「배열 아닌 자연」으로 (결정론
   유지하며). 華山 5봉의 실제 배치를 근거로 제안 가능(출처 표기).
3. **능선·안부** — 봉을 잇는 능선이 「걸을 수 있되 아찔한 날」(蒼龍嶺)로 읽히게 하는 방법.
4. **건물 품** — court가 인공 원반으로 안 보이게 (자연 안부/분지로).
5. **검증 가능한 기준** — 「자연스러운 다봉」을 오프라인 렌더로 재는 척도(능선 날카로움·봉
   비대칭·안부 대비 등) 제안.
