# RP_REVIEW — Fable 의 평가

> 2026-07-14 · 근거: 전 자산 실사 (텍스처 525 · 모델 222 · `texture_audit` 위반 0 실측) +
> 검수 시트·글리프/파티클/아이템 합성 이미지 육안 검토. 시안: `rp_review/A_*.png` · `B_*.png`

## 1. 잘 서 있는 것 (지킬 것)

1. **철학이 기계로 검증된다** — 「묵청」 2색 체계(먹의 자재 ↔ 채도 높은 자연)가 texture_audit
   축 ⑫의 두 모집단 계약으로 실측된다 (자연 채도 56.7 ↔ 자재 23.1, 격차 33.5 ≥ 25).
   아마추어 팩에서 보기 드문 규율이다. **이 계약 위에 지어야지, 흔들면 안 된다.**
2. **파티클이 수묵으로 일관** — sweep 8프레임의 붓 궤적, soul 의 먹점, explosion 의 먹 번짐.
   전투의 공기가 이미 수묵이다.
3. **GUI 한지 톤** — 인벤토리·상자류가 화선지 질감으로 통일. 서장 기억첩(SJ 트랙)과 정합.
4. **소품·무기의 균질함** — 무기 7계열 × 등급 + 문파 명기 8종 + 소품(단약·서책·모피·전표)이
   같은 도트 밀도. 세계관 어휘(비급·구결·전표)가 아이템으로 실재한다.

## 2. 문제 (우선순위순 · 전부 실물 근거)

### RP-1 ★ 문파 인장의 변별력·정체성 부재 — 시안 B
`font/crest_0~7` 은 막대 1/2/3개·삼각·원 수준의 추상 실루엣이다. 실크기(글리프 8~9px)에서
서로 갈리지 않고, 무엇보다 **무협 정체성이 없다** — 화산의 매화도, 무당의 태극도 없다.
문파 인장은 세력 UI 의 얼굴인데 지금은 익명의 도형이다.
→ **시안 B** (`rp_review/B_crest_symbol_proposal.png`): 상징 기반 8종 (형태만으로 갈림 = 색약 안전).
문파-상징 짝은 사용자 확정 필요.

### RP-2 게이지가 수묵의 언어가 아니다 — 시안 A
`font/gauge_0~8` 은 노치 있는 흰 블록이다. 기능은 하나 "먹이 차오른다"는 세계의 말이 아니다.
글리프 틴트는 곱셈이라 **회색조 음영은 허용**된다 — 붓획·먹 농담·마른 붓 갈라짐이 가능하다.
→ **시안 A** (`rp_review/A_gauge_ink_proposal.png`): 차오를수록 먹이 짙어지고 끝이 갈라지는 붓획.

### RP-3 기(氣) FX 의 격 변별이 텍스처에 없다
`item/qi/*` 7종(slash_arc·bolt_lance…)이 전부 백색 단일 톤이다. 격(검기→강기)의 위계가
형태·질감 차원에 없고, 밝은 배경(눈밭·하늘·화선지 GUI)에서 가독성이 떨어진다.
기세 격차는 HUD 색(회/백/황/적)으로만 살고 FX 와 이원화돼 있다.
→ 제안: 격별 형태 언어 (두름=홑선 · 강기=겹선+테두리 · 발경=끝 갈라짐) + 최소 명도 대비 계약을
texture_audit 축으로. (시안 C — Codex 의견 후 제작)

### RP-4 ★ 몹 모델의 표현력 (사용자 방향 반영)
현행: 바닐라 몹 징발(호랑이=Ravager 등) + item_display 조립 모델(mob/horangi 등) + 스트라이프
모피 텍스처. 스탯·등록제는 훌륭하나 **몸의 인상이 약하다** — 호랑이가 호랑이로 안 읽히면
"밤의 산길" 공포가 안 선다.
사용자 방향: **MythicMobs 사용 또는 모방 설계 허용, 모델링 강화가 좋다.**
Fable 1차 분석 (Codex 반론 환영):
- **모델링(외형)**: ModelEngine 류는 리소스팩+플러그인으로 멀티파트 애니메이션 몹을 세운다.
  다만 이 저장소는 이미 Display Entity 조립(자작)으로 같은 원리를 굴리고 있다 — **부족한 것은
  기술이 아니라 파트 수·애니메이션 프레임·텍스처 밀도**다. 자작 확장이 등록제·감사 문화와
  정합적이고, 외부 플러그인은 팩 슬롯·버전 종속을 추가한다.
- **스킬(행동)**: MythicMobs 의 선언적 YAML(트리거→조건→효과)은 이 저장소의 등록제와 사상이
  같다 — **문법을 모방한 자작**(mob_skills.yml 등록부 + 실행기)이 유력해 보인다. 판정이 우리
  judgment 층을 지나야 하므로(대립 판정·태세) 외부 플러그인 판정과 이원화될 위험이 있다.
- 제안: **파일럿 1종(호랑이)** — 현행 조립 모델의 파트 수·애님을 강화한 v2 를 자작으로 세우고,
  같은 몹을 MythicMobs+ModelEngine 데모로도 세워 **나란히 스크린샷**을 사용자에게 — 그때 결정.

### RP-5 주사(적색) 용법 대조 필요
`ult/blood_tide` 의 대면적 적색 링, `font/gui_ledger` 의 적 테두리 — 주사를 "확정·인장·혈"의
강조로 아끼는 규율(서장 문서 §4.1, 아트 디렉션의 강조 채널)과 맞는지 대조가 필요하다.
혈조(blood_tide)는 이름부터 피이므로 정당할 수 있다 — **규칙을 명문화**하고 감사 축으로.

### RP-6 명기·등급 변별의 색약 안전성
무기 등급(범철→마병)이 작은 포인트 색(적 반점 등)에 의존한다. 형태 차이(날의 이빨·자루 장식)
병행을 권한다 — 인장과 같은 원칙 (색만으로 상태를 전달하지 않는다).

## 3. 제안 로드맵 (합의 후 착수 순서)

RP-1 인장(사용자 상징 확정 → 도트) → RP-2 게이지 → RP-3 기 FX(+감사 축) →
RP-4 몹 파일럿(호랑이 비교 데모) → RP-5 주사 명문화+감사 → RP-6 명기 형태 변별.
각 건은 texture_audit 의 기존 계약(축 ⑫~⑭)을 깨지 않는 것을 닫는 조건에 포함한다.
