# 혼천 봇 알파 — 기동 가이드 (관리자 1인 검증)

> 단계 Ⅱ(interface_decision.md)의 첫 실물. 범위: **생성 문답 → 서장 스레드 → 판정 턴 루프 1인 완주**.
> 출도(공유 세계·지역 채널·파티)는 봇 베타에서 열린다.

## 0. 준비물

- Java 21+ (MVT와 같은 요구 — `run/jdk-21` 폴백도 동일하게 동작)
- 디스코드 계정 + 테스트용 서버(길드) 1개 — 관리자 권한 보유

## 1. 봇 생성과 토큰 발급 (1회)

1. https://discord.com/developers/applications → **New Application** → 이름 `혼천` (아무거나 가능)
2. 왼쪽 **Bot** 탭 → **Reset Token** → 표시된 토큰 복사
   - 토큰은 **비밀번호다.** 깃에 커밋하지 말 것 — 환경 변수로만 전달한다.
3. 같은 Bot 탭에서 **Privileged Gateway Intents는 전부 꺼진 상태 그대로** 둔다
   - 알파는 슬래시 명령·버튼만 쓰므로 특권 인텐트가 필요 없다 (`JDABuilder.createLight`)

## 2. 봇 초대 (1회)

1. 왼쪽 **OAuth2 → URL Generator**
2. Scopes: `bot` + `applications.commands` 둘 다 체크
3. Bot Permissions 체크:
   - View Channels, Send Messages, **Send Messages in Threads**
   - **Create Private Threads**, Embed Links
4. 생성된 URL을 브라우저에 붙여넣어 테스트 서버에 초대

## 3. 기동

```bash
export DISCORD_TOKEN='발급받은 토큰'
./scripts/run_bot.sh
```

- 빌드 → 기동까지 자동. `혼천 봇 기동 — …` 로그가 뜨면 준비 완료
- 슬래시 명령은 **글로벌 등록**이라 첫 반영에 최대 1시간 걸릴 수 있다
  (급하면 봇을 서버에서 내보냈다 재초대하면 보통 즉시 뜬다)
- DB: `run/bot/honcheon.db` (SQLite 단일 파일). 초기화하려면 봇을 끄고 파일 삭제

| 환경 변수 | 기본값 | 뜻 |
|---|---|---|
| `DISCORD_TOKEN` | (필수) | 봇 토큰 |
| `HONCHEON_CONFIG` | `config` | 룰 config 디렉터리 — 단일 진실 원천 |
| `HONCHEON_DB` | `run/bot/honcheon.db` | SQLite 경로 |
| `HONCHEON_SCHEMA` | `db/schema.sql` | 스키마 원천 |

## 4. 검증 시나리오 (알파 체크리스트)

서버의 일반 텍스트 채널에서:

1. `/혼천 도움말` — 안내 embed가 뜬다
2. `/혼천 시작` — 유년의 기억 5문항이 버튼으로 진행된다 (본인에게만 보임)
3. 5문항 종료 → 출생 embed: 성향(동점이면 `·` 병기) + 무작위 집안·나이·발단
4. **서장 프라이빗 스레드**가 자동으로 열리고 본인이 초대된다
5. 3장면(그날 밤 → 길 위에서 → 낯선 고을 청하현) 각각:
   - 서사 본문에는 **수치가 없다** (7계: 수치 은닉)
   - 선택 버튼 → **판정 embed 공개**: 능력치+2d6 vs 저항, 마진, 등급
   - 직전 판정 등급이 다음 장면 도입부 이음새에 반영된다
6. 3장면 종료 → 에필로그 (마지막 등급이 첫 정착의 온도를 정한다)
7. `/혼천 원장` — 능력치 7종·전낭(집안 배율 반영)·발단 확인
8. `/혼천 시작` 재시도 → "이미 살아 있는 캐릭터가 있다" 거절 (계정당 한 삶)

## 5. 알파의 알려진 한계 (베타 과제)

- **서장 진행 상태는 메모리에만 있다** — 봇 재시작 시 진행 중이던 서장은 끊긴다
  (캐릭터 자체는 DB에 있으므로 원장은 유지). 베타에서 scenes 테이블로 영속화
- 서사는 폴백 템플릿 — LLM 렌더러(llm.yml)는 베타에서 결선
- 서장 종료 후 콘텐츠 없음 — 출도·청하현 지역 채널은 베타 범위
- 이름은 디스코드 표시 이름을 그대로 쓴다 — 개명은 베타에서

문제 발견 시: 재현 절차와 함께 기록 → F 채번 (막 프로토콜)
