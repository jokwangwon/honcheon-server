# 혼천 봇 알파 — 기동 가이드 (관리자 1인 검증)

> 단계 Ⅱ(interface_decision.md)의 첫 실물. 범위: **생성 문답 → 서장 스레드 → 판정 턴 루프 1인 완주**.
> 출도(공유 세계·지역 채널·파티)는 봇 베타에서 열린다.

## 0. 준비물

- Java 21+ (MVT와 같은 요구 — `run/jdk-21` 폴백도 동일하게 동작)
- 디스코드 계정 + 테스트용 서버(길드) 1개 — 관리자 권한 보유

## 1. 봇 생성과 토큰 발급 (1회)

1. https://discord.com/developers/applications → **New Application** → 이름 `혼천` (아무거나 가능)
2. 왼쪽 **Bot** 탭 → **Reset Token** → 표시된 토큰 복사
   - 토큰은 **비밀번호다.** 깃에 커밋하지 말 것 — 환경 변수로만 전달한다.
3. 같은 Bot 탭에서 **Privileged Gateway Intents는 전부 꺼진 상태 그대로** 둔다
   - 알파는 슬래시 명령·버튼만 쓰므로 특권 인텐트가 필요 없다 (`JDABuilder.createLight`)

## 2. 봇 초대 (1회)

1. 왼쪽 **OAuth2 → URL Generator**
2. Scopes: `bot` + `applications.commands` 둘 다 체크
3. Bot Permissions 체크:
   - View Channels, Send Messages, **Send Messages in Threads**
   - **Create Private Threads**, Embed Links
4. 생성된 URL을 브라우저에 붙여넣어 테스트 서버에 초대

## 3. 기동

```bash
export DISCORD_TOKEN='발급받은 토큰'
./scripts/run_bot.sh
```

- 빌드 → 기동까지 자동. `혼천 봇 기동 — …` 로그가 뜨면 준비 완료
- 슬래시 명령은 **글로벌 등록**이라 첫 반영에 최대 1시간 걸릴 수 있다
  (급하면 봇을 서버에서 내보냈다 재초대하면 보통 즉시 뜬다)
- 기본 DB는 `run/bot/honcheon.db` SQLite 단일 파일이다. PostgreSQL은 아래 환경 변수로 명시적으로 선택한다.

| 환경 변수 | 기본값 | 뜻 |
|---|---|---|
| `DISCORD_TOKEN` | (필수) | 봇 토큰 |
| `HONCHEON_CONFIG` | `config` | 룰 config 디렉터리 — 단일 진실 원천 |
| `HONCHEON_DB_BACKEND` | `sqlite` | `sqlite`, `postgresql` 또는 `postgres` |
| `HONCHEON_DB` | `run/bot/honcheon.db` | SQLite 경로 |
| `HONCHEON_DATABASE_URL` | (PostgreSQL 필수) | `jdbc:postgresql://호스트:포트/DB` 형식 JDBC URL |
| `HONCHEON_DATABASE_USER` | `honcheon` | PostgreSQL 사용자 |
| `HONCHEON_DATABASE_PASSWORD` | 빈 문자열 | PostgreSQL 비밀번호 |
| `HONCHEON_SCHEMA` | 백엔드별 자동 선택 | SQLite는 `db/schema.sql`, PostgreSQL은 `db/postgresql/schema.sql` |

PostgreSQL 기동 예시:

```bash
export DISCORD_TOKEN='발급받은 토큰'
export HONCHEON_DB_BACKEND='postgresql'
export HONCHEON_DATABASE_URL='jdbc:postgresql://127.0.0.1:5432/honcheon'
export HONCHEON_DATABASE_USER='honcheon'
export HONCHEON_DATABASE_PASSWORD='비밀번호'
./scripts/run_bot.sh
```

PG-004 시점의 PostgreSQL 초기화 백업은 반복 읽기 트랜잭션에서 표별 CSV를 담은
`honcheon-postgresql.zip`을 만든다. PG-005 import 도구가 완성되기 전에는 자동 복원이
지원되지 않으므로 운영 PostgreSQL에서 `/초기화`를 실행하지 않는다.
또한 단일 연결과 전역 직렬화는 PG-006까지 유지되므로 아직 동시성 확장 효과가 없다.
PG-007 전환·복귀 훈련이 끝나기 전에는 PostgreSQL 경로를 개발·검증 용도로만 사용한다.

## 4. 검증 시나리오 (알파 체크리스트)

서버의 일반 텍스트 채널에서:

1. `/혼천 도움말` — 안내 embed가 뜬다
2. `/혼천 시작` — 유년의 기억 5문항이 버튼으로 진행된다 (본인에게만 보임)
3. 5문항 종료 → 출생 embed: 성향(동점이면 `·` 병기) + 무작위 집안·나이·발단
4. **서장 프라이빗 스레드**가 자동으로 열리고 본인이 초대된다
5. 3장면(그날 밤 → 길 위에서 → 낯선 고을 청하현) 각각:
   - 서사 본문에는 **수치가 없다** (7계: 수치 은닉)
   - 선택 버튼 → **판정 embed 공개**: 능력치+2d6 vs 저항, 마진, 등급
   - 직전 판정 등급이 다음 장면 도입부 이음새에 반영된다
6. 3장면 종료 → 에필로그 (마지막 등급이 첫 정착의 온도를 정한다)
7. `/혼천 원장` — 능력치 7종·전낭(집안 배율 반영)·발단 확인
8. `/혼천 시작` 재시도 → "이미 살아 있는 캐릭터가 있다" 거절 (계정당 한 삶)

## 5. 알파의 알려진 한계 (베타 과제)

- **서장 진행 상태는 메모리에만 있다** — 봇 재시작 시 진행 중이던 서장은 끊긴다
  (캐릭터 자체는 DB에 있으므로 원장은 유지). 베타에서 scenes 테이블로 영속화
- 서사는 폴백 템플릿 — LLM 렌더러(llm.yml)는 베타에서 결선
- 서장 종료 후 콘텐츠 없음 — 출도·청하현 지역 채널은 베타 범위
- 이름은 디스코드 표시 이름을 그대로 쓴다 — 개명은 베타에서

문제 발견 시: 재현 절차와 함께 기록 → F 채번 (막 프로토콜)

## 7. 베타 — 출도·청하현·LLM 렌더러

> 알파 한계 1(서장 휘발)·2(폴백 서사)·3(서장 이후 콘텐츠 없음)과 F24를 해소한 증분.
> 기동 방법은 동일 (`./scripts/run_bot.sh`) — 아래만 새로 안다.

### 새 환경 변수 (선택)

| 환경 변수 | 효과 |
|---|---|
| `ANTHROPIC_API_KEY` | 서장 장면·에필로그 서사를 **LLM 렌더러**(llm.yml turn_renderer, claude-haiku-4-5)가 쓴다. 없거나 호출 실패 시 자동으로 폴백 템플릿 — 봇은 LLM 없이도 완전히 돈다. 기동 로그에 `LLM 렌더러: …` 로 상태가 찍힌다 |

### 새 명령

- `/혼천 지역등록` — (서버 관리자) 실행한 채널을 **청하현**으로 등록. 사냥·비무는 이 채널에서만
- `/혼천 사냥` — 뒷산 조우(여우=하수/늑대=동수/곰=상수 무작위) → 접근 3택 → 판정 → 화후 적립(감쇠·일일 상한) + 부산물 즉시 매각(시세 50%)
- `/혼천 비무 @상대` — 수락 시 **양측 2d6 대립 판정**(pvp direct_opposed): 동점 = 상쇄 무승부, 쌍륙 ⚡ = 등급 1단 상승, 쌍일 💥 = 1단 하락 (F24 배선). 승패 무관 양측 화후 적립(비무 0.5배)

### 베타 검증 시나리오

1. **재시작 생존**: 서장 2장면까지 진행 → 봇 재시작(`pkill -f server-bot` 후 재기동) → 스레드의 남은 버튼 클릭 → 이어서 진행되는지 (직전 등급 이음새 포함)
2. **출도**: 서장 완주 → 에필로그에 출도 안내가 붙고, `/혼천 원장`에 신분 `강호` · 위치 `청하현`
3. **지역 게이트**: 지역등록 전 `/혼천 사냥` → 안내 거절 / 등록 후 다른 채널에서 → 청하현으로 안내
4. **사냥 루프**: 같은 짐승 연속 사냥 → 적립 감쇠(-25%/회), 성공 시 가죽 매각 +N문, 실패 시 소득 없음
5. **비무(2계정 필요)**: 신청 → 대상만 수락 가능 → 양측 굴림 공개 → 무승부/승자 판정 → 양측 화후. 쌍륙·쌍일이 뜨면 ⚡/💥 표기와 등급 이동 확인
6. **LLM 렌더러**: `ANTHROPIC_API_KEY` 넣고 재기동 → 서장 서사가 템플릿과 다른 문장으로, **수치 없이** 나오는지 (7계). 키를 빼면 다시 템플릿
7. **버튼 잠금**: 남의 사냥 버튼·남의 비무 수락 버튼 클릭 → 거절

### 베타의 알려진 한계

- 사냥·비무 **대기 중 버튼**(조우/신청)은 메모리 없이 버튼 ID로만 동작하나, 서장과 달리 재시작 후에도 그대로 눌린다 — 문제없음
- 화후 원장은 쌓이기만 한다 — 승급(경지 돌파) 배선은 다음 증분
- 비무 실행력 = 근력·민첩 중 높은 쪽 (무공 숙련 미반영 — 베타 단순화)
- 세계일(현재일)이 1에 고정 — 일일 상한·감쇠 리셋은 시간 진행 배선 후 실효

## 8. 베타 2차 증분 — 시간·승급·수련

> 2차 검증에서 도출된 잔여("화후가 쌓이기만 한다", "세계일 1 고정") 해소.

### 시간 진행

- **자정(한국 시간)마다 세계일 +1 자동** — 청하현 채널이 등록돼 있으면 "N일차 아침" 알림
- `/혼천 정산` — (서버 관리자) 세계일을 수동으로 +1. 감쇠·일일 상한·수련 리셋을 기다리지 않고 테스트할 때
- 세계일이 바뀌면: 일일 적립 상한(16일치) 리셋, 연속 사냥·비무 감쇠 카운터 리셋, 수련 1회 재개

### 수련

- `/혼천 수련` — (출도 후, 지역 채널) 하루 한 번, 화후 **+1.00일치** (기초 단련)

### 승급 — 범인 → 삼류 (cultivation_stages, trigger 자동)

### 흐름

## 14. 개화 축 (단계 2) — 취걸개 기연 → 심법 → 운기·축기 → 일류

> 일류 승급 요건(cultivation_stages): 주력 숙련 3 + **개화(단전 개방 + 심법 축기
> 시작)** + 실전 마크 3 — "개화가 사실상의 관문". 심법의 원천은 등록 기연
> **폐사당의 취걸개**(fortune_encounters chuigeolgae_master) — 등록제·1회성(서버
> 전체 선착순)·시험 필수·대가 필수의 5대 규칙 그대로 배선.

### 흐름

1. `/혼천 탐방` (출도 후, 하루 1회) — 폐사당 방문 적립. **발견 조건**: 방문 3회 +
   의뢰_완수 2건(선행 기억의 알파 대체) + 이류 이하 → 걸인이 말을 건다
2. 발견 후 매일 탐방 시 **끼니 선택 버튼** (밥을 나눈다/혼자 먹는다) — 시험임을
   알려주지 않는다(선택_시험). **사흘 연속** 나누면 전수: 심법 현천토납법 + 개방
   인연 태그 + 대가(발설 금지·원수 상속 — events 기록). 하루 거르면 연속 리셋
3. `/혼천 운기` — 첫 운기 = **개화**(현천토납법은 실패 없음, 수명 무관) →
   이후 매일 좌공 축기 +1일치. 내공 실수 = 화후 규칙 (0→1 = 1년 = 360일,
   n→n+1 = n년), 표시는 "0단계 3성" + 내력 = round(실수×3)
4. 승급: 숙련 3 + 개화 + 마크 3 → **일류** 자동 (운기·수련·사냥·의뢰 어디서든 체크)
5. 1회성 집행: world_meta `기연:chuigeolgae_master` — 한 명이 전수받으면 다른
   캐릭터에겐 폐사당이 빈다 (공유 세계 선착순)

### 검증 시나리오 (9차)

1. 탐방 1·2회 — 빈 사당 서사 변주 (밥그릇 복선), 하루 1회 게이트
2. 의뢰 완수 2건 채우고 탐방 3회째 — 걸인 등장 (미충족 시: "네 얼굴엔 아직
   이야기가 없군" 힌트 확인)
3. 끼니 버튼: 나눔 1~2일 → 서사 누적, 하루 거른 뒤 → 연속 리셋 확인, 사흘 연속 →

6. 부계정으로 탐방 → 빈 폐사당 (1회성 선착순 집행)

### 발경 배선 — 내력의 첫 소모처 (봇)

- **자격**: 단전 개화 + 경지 게이트(realm_gates — 삼류부터, 범인 불가) + 내력 ≥ 1.
  자격이 되면 자동으로 기를 싣는다 — 내력 1 소모, 판정 +1 (cost_bands 발경)
- **부족 시 다운캐스트**: 시전 불가가 아니라 맨 기술 — 그냥 보정 없이 나간다
- **회복**: `/혼천 운기`가 운기조식을 겸한다 — 축기 +1일과 함께 **내력 전량 회복**
  (알파: 하루 1회 운기에 통합, 구간제는 3막 전투 엔진 후속)
- **사냥**: 수식에 "⚡발경 1" 표기 + "타격에 기가 실렸다 (내력 -1)" / **비무**: 양측
  각자 자격 판독(대칭 원칙), 이름 옆 ⚡발경 표기 / `/정보`: 내력 **현재/풀** 표시

### 검증 시나리오 (10차)

1. 일류 캐릭터(개화 완료)로 `/혼천 운기` → "내력 n/n (가득 찼다)" — 단, 내공
   0단계 초반은 풀 0 (round(실수×3)) — **시딩**: 축기_원장 60 이상이면 내력 1
   (예: `UPDATE ... 축기_원장=120` → 내공 0.33 → 내력 1)
2. 내력 1 상태로 `/혼천 사냥` → 수식에 "⚡발경 1" + 내력 -1 표기, `/정보`에서 잔량 0/1
3. 내력 0 상태로 사냥 → 발경 표기 없음 (맨 기술 — 다운캐스트)
4. `/혼천 운기` (다음 날) → 내력 재충전 확인
5. 비무: 개화자 vs 미개화자 → 개화자 쪽만 ⚡발경 (비대칭이 수식에 보임)
6. 범인이 개화만 한 상태(가능: 범인도 취걸개 자격)면 발경 없음 — 경지 게이트
   (삼류부터) 확인 [이 DB에선 기연 소진으로 시딩 필요 — 선택]
