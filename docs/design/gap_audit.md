# 실플레이 공백 감사 — 플레이어의 여정을 따라 걷기

> 방법: 실제 플레이어의 하루를 생성부터 죽음까지 걸으며 각 지점을 4단계로 판정 —
> **설계**(룰 문서) → **config**(수치) → **엔진**(코드) → **검증**(PT).
> 기준일: 2026-07-10. 우선순위: P0 = 플레이 자체 불가 / P1 = 첫 시즌 콘텐츠 /
> P2 = 다인 공유 세계 / P3 = MC 트랙.

---

## 2. P0 — 이것 없이는 실플레이가 시작되지 않는다

```text
G4 플레이 인터페이스 미정 ★최우선 결정
   텍스트 RPG를 '어디서' 하는가가 미정 — 디스코드 봇 / 웹 / MC 채팅 통합.
   2단 파이프라인·프리페치·GM 러너의 형태가 전부 이 결정에 종속된다.
   권고: 디스코드 봇 (한국 TRPG 커뮤니티 표준, 버튼=선택지, 스레드=개인 서사,
   MC 서버와 계정 연동 용이). 결정만 하면 프로토타입 범위가 확정된다.

G5 영속화 미설계
   캐릭터 원장·세계 상태(소문/지역/NPC 생애)·세션의 저장 스키마 없음.
   MVT는 메모리 — 껐다 켜면 증발. 공유 세계는 저장이 곧 세계다.
   권고: 단일 SQLite로 시작 (동접 60·자정 배치 규모에 충분, 운영 0비용) —
   원장/세계/이벤트 로그 3테이블 군. 스케일 문제는 스케일이 생긴 뒤에.

G3 죽음 이후 미규정
   빈사→"사망 위기"까지만 있고 그 다음이 없다. 회생(수명 10년)은 있으나
   진짜 죽으면? 공유 세계의 캐릭터 사망은 밸런스이자 서사의 축 —
   유산(전낭 드랍·애병·비급), 세계 기록(소문·NPC 기억), 새 캐릭터 규칙
   (같은 세계 재생성 — 유족? 무관?), 명성의 사후 처리.
   권고: '죽음과 유산' 설계 1편 — NPC 죽음·후계 규칙(이미 있음)의 플레이어판.

G7 2단 파이프라인 프로토타입 (기결정 — LLM 정책이 스펙)
   G4 결정 후 착수. 엔진 JSON → LLM 렌더 실동 + 캐시 히트율 실측.
```

## 3. P1 — 첫 시즌을 버틸 콘텐츠 (룰은 있는데 내용물이 없다)

```text
G1 의뢰 생성기: 보수표·의뢰소 NPC는 있으나 "누가 언제 무엇을 게시하나"가 없다.
   지역 상태·NPC 생애·시세 이벤트가 의뢰를 낳는 규칙 (세계 연동 — template 아님).
G2 문파 생활: 입문 루트(진운·추천)는 있는데 입문 '이후'가 없다 — 직책·임무·
   규율(파문!)·봉록·비급각 접근·사형제 관계. 정파 플레이의 본체.
G6 콘텐츠 볼륨 (실측):
   무공 6종        → 첫 시즌 최소 ~30종 (문파별 기본 세트 — 카탈로그 스키마는 완비)
   지역 1 (청하현)  → 출도 후 세계가 좁다 — 인접 1~2개 승격 (스텁 3개 존재)
   NPC 9명        → 지역당 ~20명 (생애 시뮬 대상 — 스케줄·lifepath 문법은 완비)
   기연 3·오의 4    → 각 ~10종
   장(章) 사건 풀   → 발단 7종(서장용)뿐 — 출도 후 장 템플릿 0. GM이 만들 재료 필요
```

## 4. P2 — 다인 공유 세계의 미검증 지대

```text
G8 동시성 규칙 공백: 두 파티가 같은 NPC를 같은 구간에 찾아오면? 같은 사건에
   반대편으로 개입하면? 기연 선착순(등록제)은 커버되나 '사건 동시 개입' 중재
   규칙이 없다 — 장면 잠금? 실시간 병합? GM 러너 설계와 결부.
G9 다인 실테스트 0회: PT 전부 1인. 최소 2인 동시 세션 PT-008 필요
   (동행 + 배신 + 같은 소문망 공유 검증).
G10 장기 밸런스 시뮬 없음: 게임 1년 경과 후 고수 밀도·화폐 인플레·소문 포화의
   시뮬레이터 미작성 (기존 세계 반응 시뮬 확장으로 가능).
```

## 5. P3 — MC 트랙 (계획대로 후순위)

```text
스킬 8단계 파이프라인 실장 / NPC 엔티티(일과 이동·전투 AI) / M2b(맵 월드 기록 —
로컬) / 서버 모듈 재작성(레거시 원소 문파 잔재) / 계정 연동(G4와 결부)
```

## 6. 권고 순서

```text
① G4 인터페이스 결정 (사용자 결정 사항 — 디스코드 봇 권고)
② G3 죽음과 유산 설계 + G5 영속화 스키마    ← 설계 작업, 지금 가능
③ G7 파이프라인 프로토타입 (①에 종속)
④ G1 의뢰 생성기 + G2 문파 생활 설계        ← 첫 시즌 룰 마감
⑤ G6 콘텐츠 볼륨 생산 (룰 완비 후 — 생성 파이프라인화 가능: "콘텐츠도 컴파일한다")
⑥ G9 2인 PT-008 → G8 동시성 규칙 도출 (실측 기반)
결론: 룰·엔진의 뼈대는 실플레이 수준 — 부족분은 ①인터페이스 결정 ②죽음·저장
③세계를 채울 콘텐츠와 그것을 낳는 생성기다.
```
