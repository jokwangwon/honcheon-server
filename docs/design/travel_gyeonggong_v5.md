## 0. 세 줄 요약

1. **복합은 두 몸짓이다** — 달리면 빨라지고(지속 가속), 달리며 뛰면 날아간다(도약 연쇄).
   콤보 창도 입력 버퍼도 없다 (헌법) — 잇는 것은 **타이밍이 아니라 관성(몸의 상태)** 이다.
2. **순항은 두르고, 도약은 태운다.** 경신 밴드의 정의 그대로다 (하단 1 = 유지·두름, 상단 2 = 발출 —
   `internal_energy.yml cost_bands.경신`). 그러면 **연쇄 도약의 지속 가능 빈도가 조식 수지에서
   저절로 유도된다**: (내공 × 1 − 1) / 2 회/합. 일류는 0 — **일류가 '첫 조각만'인 이유를 연료가 증명한다.**
3. **20분의 4분의 1은 순항만으로 못 만든다.** 걷기 속도 상한(0.6 — 카메라 안전선)의 질주는 16.8m/s가
   한계다. 나머지는 **도약 연쇄가 산다** (도약 초속 24m/s — `dash.max_velocity 1.2` 재사용).
   복합은 장식이 아니라 **계약(5분)을 만족하는 유일한 산술**이다.

## 1. 복합의 구조 — 조작 문법 (몸짓 기반)

### 1.1 세 몸짓 — 전부 기존 문법의 연장이다

현행 등록부의 조작 문법(`gyeonggong.yml mode` — "방패=막기 · 웅크림=흘리기 · 달림=회피 ·
**점프 두 번=경공**")을 한 글자도 깨지 않는다. 새 키도, 새 UI 도 없다.

| 몸짓 | 무엇이 되는가 | 현행과의 관계 |
|---|---|---|
| **공중에서 점프 한 번 더** (더블 점프) | 경공 **발동** — 유일한 발동점 (손가락이 정한다) | **현행 그대로 흡수** (D-2: "첫 조각") — `onAirJump` · `PlayerToggleFlightEvent` 훔치기 불변 |
| **켜진 채 질주 지속** | **지속 가속** — 여행 기어. 질주를 이어 가면 순항 속도까지 점점 빨라진다 | 신설. 단 **발동이 아니다** — 이미 손가락으로 켠 모드의 속성이다 (걷기 보너스 `applyWalk` 와 같은 층 — `no_auto_activation` 계약과 충돌 없음) |
| **질주 중 점프** | **연쇄 대도약** — 현재 관성을 실은 전방 도약. 착지 후 또 뛰면 또 나간다 | 현행 `onJump`(수직만 싣던 자리)에 **수평 관성**이 실린다 |
| **웅크림 / 멈춤 2초** | 꺼짐 | 현행 그대로 (`onSneak` · `idle_off_ticks 40`) |

절벽·계곡·장애물(D-2)은 별도 기술이 아니다 — **연쇄 대도약이 건너고**, 수직 벽은 현행
**벽 딛기**(절정 ∧ 수직 보법)가 그대로 잇는다. 새 동작을 만들지 않았다.

### 1.2 ★ 콤보 창·입력 버퍼 금지 — 어떻게 지키는가 (헌법 준수 설계)

외부 액션 게임의 "착지 후 0.3초 안에 점프하면 가속 유지" 류를 **전부 거부한다**. 그것은
삼문(막기·흘리기·회피)의 자리를 반사신경 미니게임이 잡아먹는 길이다.

- **관성은 상태다, 창이 아니다.** 가속으로 얻은 속도(momentum)는 **몸에 붙어 있고**, 사라지는
  조건은 딱 현행의 것 하나 — **멈춰 서서 2초** (`idle_off_ticks`) 또는 꺼짐. 착지 후 1초를 걸어도,
  5초를 걸어도, 다시 뛰면 그 관성 그대로 나간다. **시계를 이기는 손가락이 없다.**
- **입력은 버퍼링하지 않는다.** 점프는 일어난 그 틱에 `PlayerJumpEvent` 로 읽고 그 자리에서
  판정한다 — 공중에서 미리 누른 점프를 저장했다가 착지 순간 터뜨리는 코드는 금지.
  놓친 점프의 대가는 없음(그냥 계속 달린다)이고, 보상 타이밍도 없다.
- **리듬 게이지·연속 히트 카운터 금지.** "연쇄 n단" 같은 누적 배율 없음 — 도약은 몇 번째든
  같은 도약이다 (빨라지는 것은 질주 가속뿐).
- 감사 계약 신설 제안: `no_combo_window: true` · `no_input_buffer: true` (§6 — 눈이 소스를 읽어
  창·버퍼 패턴을 잡는다. `no_auto_activation` 을 잡는 방식과 같은 결).

### 1.3 무게는 몸이 밀리는 것 — 화면 흔들림 금지 (헌법 준수)

- **카메라 조작 0줄.** 흔들림·틸트·펀치 연출 금지. 무게·속도감은 **속도 벡터**(`setVelocity` —
  물러남·파고듦과 같은 문법)와 파티클(답설무흔 자국·바람 꼬리)로만 말한다.
- **정직한 캐비앳 — FOV**: 걷기 속도 속성을 올리면 클라이언트가 시야각을 **스스로 넓힌다**
  (바닐라 질주의 속도 언어 — 흔들림이 아니라 줌아웃이다). 상한 0.6(`mc.walk_speed_hard_cap` —
  "1.0 은 카메라가 멀미한다")은 그대로 지킨다. 이 확대를 수용할지는 【미결 5】.

## 2. 연료 — 내공/내력 소모 모델

### 2.1 왜 재설계인가 (D-2 가 명시한 딸린 과제)

현행: 경공 유지 = **태움** 1/초(20틱) + "경신은 태우는 것 — 조식이 멈춘다"
(`internal_energy.yml recovery.in_combat.조식 rationale ④`). 그래서 체공·주행 한계는 **내력 풀 = 초**:
일류 3초 · 절정 18초 · 화경 84초 (풀표 `internal_energy.yml pool_table` · 구판 화경 21 이 D-2 의
"21초 한계"다). **5분(300초) 여행은 어느 경지도 불가능하다** — 생사경 풀 165 로도 165초.
풀을 20배 불리거나 유지 간격을 17배 늘리는 수치 왜곡 없이는 여행이 서지 않는다.

### 2.2 ★제안 — 모델 A: 「순항은 두름, 도약은 발출」 (권장 · 승인 대기)

**새 수치를 발명하지 않고 기존 문법 둘을 잇는다**:

- 경신 밴드는 이미 이렇게 정의돼 있다: `cost_bands.경신 [1, 2]` — **"하단 1 = 유지(두름),
  상단 2 = 발출(쏨) — 밴드의 정의 그대로다"** (`gyeonggong.yml` 주석 · internal_energy 밴드 재정의 패스).
- 두름은 태우는 것이 아니다: `조식.upkeep_exempt: true` — "날에 기를 서리게 한 채로도 숨은 쉰다."

이 두 줄을 여행에 적용한다:

| 항목 | 값 | 근거 |
|---|---|---|
| **순항(지속 가속) 유지** | **1/합** (합 = 60틱 = 3초, `combat.yml realtime.round_ticks`) — **두름**으로 분류: 조식과 병행 | 밴드 하단 1 = 유지. "발에 기를 서리게 한 채 달린다" — 검기 두름과 같은 격 문법 |
| **연쇄 대도약** | **2/회** — 발출: 그 합의 조식 대상에서 제외되지 않고 소모만 진다 (여행 기어 중에는 조식을 막지 않는다 — 아래 유도의 전제) | 밴드 상단 2 = 발출. 현행 더블 점프(허공 딛기) 1 은 불변 |
| **조식 (여행 중)** | 내공 × 1 /합 (floor 1) — 전투 조식 공식 그대로, 시계만 여행에도 돈다 | `조식.per_naegong: 1` 재사용 — 새 회복 곡선 없음 |
| **고갈** | 현행 그대로 — 낙법 0 배 · 3초 여운 · 걷기 속도 원복 | `qi.depleted` 불변 — **공중 고갈 = 추락**의 드라마 보존 |
| **전투 진입** | 여행 기어 즉시 해제 → **전투 경신은 현행 그대로** (태움 · 조식 차단) | internal_energy ④ 는 전투에서 참으로 존속 — 개정이 아니라 **국소화**다 |

**이 모델이 사는 것 — 지속 가능 연쇄 빈도가 수지에서 유도된다** (수치 발명 0):

```
합당 수지 = 조식(내공×1) − 순항 두름(1) − 도약(2)×n
지속 가능 n = (내공 − 1) / 2   회/합
  일류(내공 1)   → 0.0  — 연쇄 불가. 순항 수지도 0 (조식1−두름1). ★첫 조각만인 이유
  절정(3)        → 1.0  회/합
  초절정(5)      → 2.0
  화경(7)        → 3.0
  현경(9)        → 4.0
  생사경(10)     → 4.5
```

빈도 천장을 등록부에 손으로 적을 필요가 없다 — **단전이 천장이다.** 수지를 넘겨 몰아 뛰는 것은
허용된다(절벽 구간 돌파): 풀이 줄고, 다 마르면 **떨어진다**. 자원 관리가 곧 조작이다.

- 무한 순항 캐비앳 (정직하게): 절정+는 순항 수지가 양수라 평지 순항은 무한이다. 이것은
  버그가 아니라 **"넘치기 시작하는 자리 = 절정"** 수지 철학의 연장이다 ("검기는 하루 종일
  두를 수 있다" — internal_energy 수지 패스). 비싼 것은 나는 것(도약·발출)이고, `no_free_flight`
  계약(유지 코스트 1 존속 · floor 1)은 그대로 지켜진다.
- **개정 필요 조항**: internal_energy ④ "경공(경신)은 태우는 것 — 조식이 멈춘다"에 **여행 기어
  예외**를 단다 (전투 중 참 존속). `internal_energy.yml` 은 다른 소유자다 — `world_map.yml
  proposed_time_yml` 전례대로 **조각 제안**으로 넘긴다. 【미결 3 — 사용자 + 소유자 승인】

### 2.3 기각 후보 — 모델 B: 태움 유지 + 유지 간격 확장 (기록용)

현행 분류(태움)를 유지하고 여행 중 유지 간격만 1초 → ~17초로 늘리면 절정(풀 18)이 300초를
난다. 기각 근거: ① ×17 은 어떤 등록부에서도 유도되지 않는 발명 수치다. ② 풀이 "여행 타이머"가
되어 노선 중간 고갈 → **앉아서 운기조식**(구간 단위 — `meditation_per_segment`)을 강요한다.
여행의 리듬이 죽는다. ③ 경지별 차등이 풀 크기 하나에 매달려, 연쇄 빈도라는 두 번째 축(§2.2)을 잃는다.

### 2.4 보스바 접점 (★확정 배선과의 이음 — 코드 변경 불요)

내공/내력 별도 바는 이미 섰다: **평시 파랑 · 고갈 빨강** (★사용자 확정 —
`config/skill_motion.yml hud.energy_bossbar` color: BLUE · depleted_color: RED ·
title "내력 {내력}/{내력최대} · 내공 {내공}" · `EnergyBossBar.java`). 여행 경공은 이 바를 **읽지도
쓰지도 않는다** — 같은 원장(`SkillEngine.State.energy`)을 소모할 뿐이고, 바는 저절로 말한다:

- 순항: 파란 바가 **숨쉰다** (두름 −1/합 ↔ 조식 +내공/합 — 절정+는 만충 근처에서 진동).
- 연쇄 도약: 한 번에 −2 씩 눈에 보이게 깎인다. 절벽 돌파 연타 = 바가 뚝뚝 떨어진다.
- 고갈: 바가 **빨갛게** 물들고 (기존 배선), 공중이었다면 낙법 없이 떨어진다 — 화면과 규칙이 같은 말을 한다.

## 3. 속도 산출 — 20분 노선을 5분으로

### 3.1 노선 계약의 산술 (D-1 에서 역산 — 수치 발명 없음)

```
D-1: 직선 3,450~4,490 블록 · 굴곡 1.5 → 노선 길이 = 5,175 ~ 6,735 블록
검산: 도보 20분(1,200초)의 자가
  걷기 4.317 m/s → 노선 5,180 → 직선 3,453  ✓ (하한과 일치)
  달리기 5.612 m/s → 노선 6,734 → 직선 4,489  ✓ (상한과 일치 — mc.sprint_speed_mps 5.6)
→ D-1 의 3,450~4,490 밴드는 곧 「도보의 자 = 걷기냐 달리기냐」의 두 눈금이다.
```

경공 5분 = 같은 길 300초 → **필요 평균 = 도보 속도 × 4** (4:1 은 자와 무관한 불변식):

| 도보의 자 | 노선 길이 | 필요 평균 속도 |
|---|---|---|
| 걷기 (4.32 m/s) | 5,180 | **17.3 m/s** |
| 달리기 (5.61 m/s) | 6,734 | **22.4 m/s** |

**D-2 의 "목표 평균 17~22 m/s"는 바로 이 두 눈금 사이다** — 어느 자인지가 【미결 1】.
이하 산출은 걷기 자(17.3)를 기본으로 한다 (달리기 자를 고르면 §3.3 상수 재산출 — 식은 동일).

### 3.2 왜 복합이어야 하는가 — 순항의 천장

- 현행 최고: 달리기 5.6 × (1 + 0.25 생사경 speed_bonus) ≈ **7.0 m/s** (D-2 의 "현행 최고 ~7m/s" 검산 ✓).
- 순항(걷기 속도 속성)의 물리 천장: `walk_speed_hard_cap 0.6` → 달리기 환산 5.612 × (0.6/0.2) =
  **16.8 m/s**. 카메라 안전선(멀미 헌법)이라 올리지 않는다.
- **16.8 < 17.3** — 순항만으로는 계약에 못 닿는다. 초과분은 **도약 연쇄**가 산다:
  도약 수평 초속 = `dash.max_velocity 1.2` 블록/틱 × 20 = **24 m/s** (기존 눈금 재사용 — 물러남·
  파고듦·허공 딛기와 같은 표다. 새 눈금을 만들지 않았다).

### 3.3 복합 평균의 식과 앵커

```
평균 v = 순항 c × (1 − f) + 도약 24 × f
  f = 체공 비율 = (연쇄 빈도 n/합 × 체공 1.0초) / 3초      ← n 은 §2.2 수지에서 유도
  체공 1.0초 ≈ 도약 초속 0.42×(1+jump_bonus) 의 왕복 시간 (바닐라 물리 — 시험 조성 실측 보정 대상)

앵커 (★제안): 절정 · 보법 숙련 상한 = 정확히 5분.
  절정 n=1 → f=0.333 → 17.3 = c×0.667 + 24×0.333 → c = 14.0 m/s
  → 절정 순항 상한 14.0 은 고른 값이 아니라 계약(17.3)·수지(n=1)·기존 눈금(24)에서 풀린 해다.
```

## 5. 기술 성장과의 관계 — "기술은 써야 는다" (v3 §3)

- **쌓이는 곳은 기술·숙련뿐이다.** 여행 경공의 사용(주행 거리·연쇄 도약 횟수)은 **보법 숙련**에
  적립된다 — 검을 쓴 손에 검술이 늘듯, 달린 발에 보법이 는다. **능력치(민첩)에는 한 톨도 안
  쌓인다** (v3 ③ 영역 분리 — 민첩은 레벨 포인트로만. 눈이 그 선을 지킨다).
- **XP 는 나오지 않는다.** XP 원천은 몬스터·의뢰·일과다 (v3 §1) — 왕복 자동 달리기가 레벨을
  버는 구멍을 처음부터 안 판다.
- 숙련이 사는 것 (기존 눈금 재사용): ① 연쇄 도약 거리 +0.25m/숙련 (`bobeop.mastery_bonus_m`
  현행 그대로 — 이미 `masteryOf` 가 읽는다) ② 가속 램프 단축 ★제안 (숙련 상한에서 2합 → 1합).
  앵커(§3.3)가 "절정 **+ 숙련 상한** = 5.0분"인 이유다 — 갓 승급한 절정은 5분대 초중반이고,
  **써야 5분이 된다.**
- 문파 차등은 현행 그대로 산다: 보법 4종의 distance(매화보 5 · 제운종 8 · 취팔선보 4 · 답운종 10,
  `skill_mechanics.yml`)가 연쇄 도약의 수평 초속을 `dash` 표로 환산 — **발이 다르면 여행이 다르다.**
  곤륜현천공(경신 −2 — 유지 간격 ×3)은 여행에서도 "절세의 경공"이다.
