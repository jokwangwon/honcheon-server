## 0. 문제 — 옛 저울이 못 담는 것

옛 눈금 (`config/judgment.yml`):

| 축 | 눈금 | 비고 |
|---|---|---|
| 능력치 | 1~10 (실전 2~7) | ±1 이 등급 한 칸을 밀 확률 1/6~1/4 — **±1 이 유의미한 TRPG 저울** |
| 기술 | 0~10 | B-134 행위 적립의 것 — **이번 재설계 대상이 아니다** |
| 주사위 | 2d6 (평균 7 · 표준편차 2.42) | 분산이 판정을 지배한다 |
| 상황보정 | 캡 ±5 | |

새 세계 (B-135 확정): **매 레벨 3포인트 × Lv100 ≈ 300포인트** (+생성 배분 11).
이것을 옛 눈금에 그대로 부으면 능력치가 주사위를 수십 배 압도한다 — 등급표 6단·정적
난이도·NPC 수치표·auto_resolution 이 전부 무의미해진다. **저울을 다시 짠다.**

### 0.1 새 저울이 지켜야 할 것 (기존 등록부에서 읽은 제약)

1. **판정 공식의 뼈대** — 실행력 = 능력치 + 기술 + 보정 + 2d6 · 저항 = NPC능력치 + NPC기술
   + 경계도 + 의심도 + 상태보정 + 7 (judgment.yml). v3 헌법: *"찍은 능력치는 판정 공식에
   그대로 — 새 공식 없음."*
2. **화후 규칙** (player_creation.yml:183) — *"능력치는 내부 실수로 적립. 판정 가산은
   정수부, 파생치는 실수치."* **원장과 판정치를 가르는 층이 이미 헌법이다.**
3. **등급표 6단이 전부 굴러가야 한다** — 대등 판정에서 대성공 2.8%~치명 2.8% (judgment.yml
   재설계 주석). 쌍륙·뱀눈이 이름으로 박혀 있다.
4. **성별 ±1 은 "느껴지되 결정하지 않는다"** (player_creation.yml:68 — cap 1 · 히든).
5. **장비의 값은 보정이 아니라 생존** (equipment.yml — 등급 보정 전부 0, 애병 +1 만 ·
   판정 보정 총합 캡 2).
6. **파생치가 능력치 실수치를 읽는다** — 내력 풀 = round(내공(내공+1)/2×3)
   (internal_energy.yml:86) · 이속/도약 = 민첩 × 계수 (gyeonggong.yml:82) · 내구 = 10 +
   체력×2 (combat.yml durability). 저울이 바뀌면 이 셋이 연쇄로 흔들린다.
7. **경지별 능력치 캡** (player_creation.yml attribute_cap_by_realm: 범인 3 … 현경 10) —
   격차 폭주를 막는 기존 못. 새 눈금에서도 살아야 한다.

## 1. A안 — 십진 환산층 (원장 ×10 · 판정은 정수부)

**한 줄**: 포인트는 0~100 원장에 쌓이고, 판정은 그 십의 자리만 본다.
기존 화후 규칙("적립은 실수, 판정은 정수부")을 자릿수 하나 내린 것 — **새 층을 짓지 않는다.**

### 눈금 구조
- **원장(raw)**: 능력치별 0~100+ 정수 눈금. 레벨 포인트 1점 = 원장 1눈금.
- **판정치** = floor(원장 / 10). 옛 눈금과 1:1 대응 — **옛 값 X ↔ 원장 10X.**
- **환산 실수치** = 원장 / 10 (소수 유지). 파생치 공식이 읽는 값.

### 주사위
**2d6 유지.** 판정층의 확률 구조가 한 톨도 변하지 않는다.

### 판정 공식 재환산
```
실행력 = floor(능력치_원장/10) + 기술 + 상황보정(캡 ±5) + 2d6
저항   = NPC능력치 + NPC기술 + 경계도 + 의심도 + NPC상태보정 + 7
```
저항 쪽은 **글자 그대로 무변경** — NPC 표는 이미 판정어(1~10)로 적혀 있고, NPC 는 레벨을
먹지 않으므로 원장이 필요 없다. 등급표·정적 난이도·auto_resolution(±8)·재시도(+2)·경지
격차(+2/단)·optional_extreme_dice 전부 무변경.

### 연쇄 환산

| 대상 | 처분 |
|---|---|
| 플레이어 능력치 원장 | **×10** 1회 마이그레이션 (옛 3 → 원장 30) |
| NPC 수치표 (config/npcs/* · 85항목) | **무환산** — 판정어 그대로 |
| 장비 보정 (애병 +1 · 총합 캡 2) | **무환산** (판정층 수치) |
| 성별 ±1 (B-056) | **무환산** — 판정치 산출 뒤 ±1 로 유지 (원장 ±10 상당. 승인은 B-056 별도) |
| 경지 캡 | **×10** (범인 30 · 삼류 40 · … · 화경 90 · 현경 100) |
| 생성 배분 | ×10 (base 10 · 자유 40 · 상한 20) — 총합 논리 동일 |
| 파생치 (내력 풀·이속·내구·경공) | 공식의 "실수치" = **환산 실수치(원장/10)** — 기존 수치 전부 보존, 매 포인트가 파생치를 조금씩 민다 |

### 레벨 1~100 체감 (포인트 전부 유관 능력치, 캡 미접촉 가정)

10원장 = 판정 +1. 체감이 전 구간 **균질하다** (선형).

| 레벨차 | 판정 우위 | 대등 NPC 상대 성공권(마진 ≥ 0) | 대성공(≥ +4) |
|---|---|---|---|
| 0 | +0 | 41.7% | 2.8% |
| 3~4 | +1 | 58.3% | 5.6% |
| 10 | +3 | 83.3% | 27.8% |
| 20 | +6 | ~100% | 72.2% |

레벨차 20 은 판정을 결정해 버리지만, **경지 캡이 먼저 개입한다**: 같은 경지 안에서 특화
능력치의 격차는 캡(예: 일류 60)에서 멈춘다 — 폭주 방지는 새 수치가 아니라 기존 못이 한다.
전축 분산 시 최종장(생성 110 + 300 = 원장 410): 평균 판정 ~5.9/축 — 현행 NPC 표 최상위
(취팔선보 거지 6·5·5)와 같은 하늘에 선다.

### 장단점

| 장점 | 단점 |
|---|---|
| 판정층 완전 불변 — NPC·장비·등급표·난이도 연쇄 환산 **사실상 0건** | 판정 체감은 10포인트 계단 — 찍는 맛이 뭉툭할 수 있다 (파생치가 매 포인트 움직여 상쇄) |
| 기존 화후 규칙의 확장 — 헌법과 정합, 새로 지어내는 층이 없다 | 선형이라 후반 특화 경쟁이 캡 대기줄이 된다 (캡을 친 뒤엔 분산 강제) |
| 침묵하는 실패 표면적 최소 (건드리는 파일이 적다) | 시트에 원장·판정치 두 숫자를 보여야 한다 (UI 결정 필요) |
| 검증 쉬움 — 옛/새 동등 시나리오가 ×10 으로 기계 대조된다 | |

## 2. B안 — 동형 전면 확대 (전 눈금 ×10 직결 + 주사위 2d6×10)

**한 줄**: 환산층을 두지 않고 세계의 모든 수를 10배로 키운다. 능력치 원장이 곧 판정 수치다.
(B-137 원문의 "능력치 수백 눈금 + 주사위 폭 확대"를 곧이곧대로 세운 안.)

### 눈금 구조
- 능력치 0~100+ 정수, **공식에 직결** (환산 없음). 포인트 1점 = 눈금 1.
- 기술·보정·난이도·등급 문턱까지 **전부 ×10** — 저울 전체가 한 자릿수 커진다.

### 주사위
**2d6 을 굴려 ×10 으로 읽는다** (눈금 20~120 · 평균 70 · 표준편차 24.2).
분포의 꼴(쌍륙·뱀눈 포함)이 정확히 보존된다 — ×10 동형이다.

### 판정 공식 재환산
```
실행력 = 능력치(0~100+) + 기술×10 + 상황보정(캡 ±50) + 2d6×10
저항   = NPC능력치×10 + NPC기술×10 + (경계도+의심도+상태보정)×10 + 70
```
등급표: 대성공 ≥ +40 · 성공 ≥ +20 · 아슬 ≥ 0 · 부분 ≥ −30 · 실패 ≥ −50 · 치명 그 밑.
정적 난이도 100/120/140/160/180. auto_resolution ±80. 재시도 +20. 경지 격차 +20/단.

### 연쇄 환산

| 대상 | 처분 |
|---|---|
| 플레이어 능력치 | ×10 |
| **NPC 수치표 85항목** | **×10 전수 개서** (config/npcs/* 전 파일) |
| 장비 (애병 +1 · 캡 2) | ×10 → 애병 +10 · 캡 20 |
| 성별 ±1 | ×10 → **±10** — "느껴지되 결정하지 않는다" 계약상 ±10 이 옛 ±1 과 동일 무게이나, B-056 재승인 필요 |
| 경지 캡·생성 배분 | ×10 |
| 파생치 | 공식 재정박 필요 (내공(내공+1)/2 류의 비선형은 ÷10 보정항을 심어야 옛 값 보존) |

### 레벨 1~100 체감

확률은 **A안과 계단 단위로 동일**하다 (동형 확대). 다른 점 하나: 주사위 눈이 10 단위로
튀므로 마진의 1의 자리는 능력치 우열만이 정한다 — 10포인트 미만의 격차가 **동률
가르기**에서만 드러난다 (예: 원장 +3 우위는 승률을 못 바꾸고, 동점 상쇄만 가른다).

| 레벨차 | 성공권 | 비고 |
|---|---|---|
| 0 / 3 / 10 / 20 | 41.7% / 58.3% / 83.3% / ~100% | A안과 동일 계단 |

### 장단점

| 장점 | 단점 |
|---|---|
| 환산층이 없다 — 원장 = 판정 수치, 자리가 하나뿐 | **실효 확률이 A안과 같다** — 얻는 것 없이 비용만 낸다 |
| 마진 숫자가 커서 성장이 시각적으로 웅장하다 | NPC 85항목 + 등급표 + 난이도 + 보정 + 문서 주석의 수치 감각 전체를 개서 — 침묵하는 실패 표면적 최대 |
| | 2d6×10 이라는 읽기 규칙이 "2d6"이라는 등록부 언어와 어긋난다 (쌍륙=120?) |
| | 비선형 파생 공식(내력 풀)에 보정항을 지어 넣어야 한다 |

※ 주사위를 진짜로 넓히는 변형(예: 10d6, 평균 35·편차 7.9)도 검토했다 — 능력치 직결 시
레벨차 2 에 성공권이 78%, 5 에 97% 로 치솟아 **주사위가 죽는다** (등급표 전면 재설계 없이는
불가). 본선에 올리지 않고 기록만 남긴다.

## 3. C안 — 제곱 환산층 (원장 = 판정치² · 체감 곡선 내장)

**한 줄**: 판정치 = floor(√원장). 옛 값 X ↔ 원장 X². 한 눈금이 갈수록 비싸진다 —
**체감(遞減)이 환산식 자체에 산다.**

### 눈금 구조
- 원장 0~100+/축. 포인트 1점 = 원장 1. 판정치 = floor(√원장).
- 판정 +1 의 값: 3→4 는 7점, 5→6 은 11점, 8→9 는 17점, 9→10 은 19점 (≈6레벨 전액).
- 옛 캡 10 ↔ 원장 100 — **한 축 전액 특화(포인트 100)가 정확히 현경 캡에 닿는다.**

### 주사위
**2d6 유지.** A안과 같이 판정층 확률 구조 불변.

### 판정 공식 재환산
```
실행력 = floor(√능력치_원장) + 기술 + 상황보정(캡 ±5) + 2d6
저항   = 무변경 (NPC 표는 판정어 그대로)
```
등급표·난이도·auto_resolution·경지 격차 등 판정층 전부 무변경 (A안과 동일).

### 연쇄 환산

| 대상 | 처분 |
|---|---|
| 플레이어 능력치 원장 | **제곱** 마이그레이션 (옛 3 → 원장 9) |
| NPC 수치표·장비·성별 ±1 | **무환산** (A안과 동일 — 판정층 유지) |
| 경지 캡 | 제곱 (범인 9 · 삼류 16 · 이류 25 · 일류 36 · 절정 49 · 초절정 64 · 화경 81 · 현경 100) |
| 생성 배분 | 판정 눈금으로 배분 후 제곱 저장 (1→1 · 2→4) |
| 파생치 | 공식의 "실수치" = **√원장** (실수) — 기존 수치 보존 |

### 레벨 1~100 체감 — 초반은 A처럼, 후반은 눌린다

| 구간 | 레벨차 10 (30점 전액) | 성공권 변화 |
|---|---|---|
| 초반 (판정 4 · 원장 16 부근) | 16→46: 판정 +2 | 41.7% → 72.2% |
| 중반 (판정 5 · 원장 25 부근) | 25→55: 판정 +2 | 41.7% → 72.2% |
| 후반 (판정 8 · 원장 64 부근) | 64→94: 판정 +1 | 41.7% → 58.3% |

후반의 레벨차는 압축된다 — **최종장에서도 주사위가 산다** (대등 6단 등급표가 끝까지
굴러간다). 대신 전액 특화 없이는 판정 9~10 에 못 닿는다 (300점 분산 시 평균 원장 43 ≈
판정 6 — 옛 일류 고수의 전신).

### 장단점

| 장점 | 단점 |
|---|---|
| 판정층 무변경 + NPC·장비 무환산 (A안과 동급의 최소 표면적) | **비선형** — "포인트 1점의 값"이 현재치에 따라 다르다. 설명 부담, 찍는 맛 불균질 |
| 체감 곡선이 내장 — 소프트캡 표를 지어낼 필요가 없다 (√ 하나가 전부) | XP 곡선(후반 무겁게)과 겹쳐 **이중 감속** — 후반 판정 +1 에 6레벨 ≈ 130시간+, 정체감 위험 |
| 끝까지 주사위가 산다 — TRPG 저울의 감각 보존 | 옛 값 대응이 제곱이라 마이그레이션·감사가 A보다 한 눈금 어렵다 |
| 특화가 비싸져 빌드가 자연히 넓어진다 (지배 전략 억제) | 경지 캡의 격차 억제와 역할이 겹친다 (못이 둘) |

## 5. 권고 — **A안** (승인 대상)

근거 넷:

1. **지어내는 층이 없다.** "적립은 실수, 판정은 정수부"는 이미 이 저장소의 법이다
   (player_creation.yml 화후 규칙). A안은 그 법의 자릿수를 하나 내린 것뿐이다 — v3 의
   *"판정 공식에 그대로, 새 공식 없음"* 과도 글자 그대로 정합한다.
2. **침묵하는 실패의 표면적이 가장 작다.** NPC 85항목·장비·성별·등급표·난이도·auto·재시도
   전부 무환산 — 건드리지 않은 등록부는 거짓말할 기회도 없다. B안은 수백 항목을 손으로
   개서하고도 확률이 A와 같다.
3. **격차 폭주는 새 수치가 아니라 기존 못(경지 캡 ×10)이 막는다.** C안의 √ 압축은 그 못과
   역할이 겹치고, XP 곡선의 후반 감속과 겹쳐 이중 감속이 된다 — 사용자가 고른 "찍어서
   올리는 맛"(B-135 원문)을 후반에 무디게 만든다.
4. **검증이 기계적이다.** 옛/새 동등 시나리오 대조 하네스(B-137 검증 조건)가 ×10 선형이라
   전수 자동 대조 가능 — 제곱·전면 개서보다 눈이 서기 쉽다.

C안은 차선이다 — "최종장에서도 주사위가 사는 TRPG 감각"을 캡보다 세게 지키고 싶다면 C.
B안은 권하지 않는다 (비용 최대 · 실효 이득 없음).

## 6. 사용자에게 묻는 것 (근거가 없어 지어내지 않은 자리)

1. **안의 선택** — A / B / C, 혹은 다른 방향.
2. **경지 캡의 존속과 값** — ×10(A·B) 또는 제곱(C) 환산으로 유지하는가. 특히 캡과 XP
   사다리의 교차: 범인 구간(삼류 자격 Lv10 이전)에 전액 특화 시 원장 47 > 범인 캡 30 —
   캡이 먼저 서서 분산을 강제한다. 의도대로인가.
3. **성별 ±1 의 자리** — 판정층 ±1 유지(A·C 권고)인가. B-056(값 자체의 승인)이 아직 열려
   있다 — 이번에 함께 닫는가.
4. **파생치 계약** — 내력 풀·이속·내구·경공이 "환산 실수치(원장/10 또는 √원장)"를 읽어
   기존 수치를 보존하는 방식의 승인.
5. **시트 표기** — `/혼천 정보` 에 원장(0~100)과 판정치를 병기하는가, 원장만 보이는가.
6. **NPC 표의 위쪽** — 현행 NPC 최고치는 판정 6~7 (취팔선보 거지·흑곰). 최종장 플레이어
   (특화 판정 9~10)와 맞설 상위 경지 NPC 수치는 **신규 등록**이 필요하다 — 값은 별도 승인.
7. **몬스터·야수 표** — NPC 와 같이 판정어 유지(무환산)로 두는가.
8. **생성 배분의 입력 눈금** — 생성 UI 는 옛 눈금(1~2 배분)으로 받고 저장만 새 원장으로
   할 것인가, 처음부터 원장 눈금으로 받을 것인가.

# 8. C안 구체화 — 제곱 환산층의 정본 후보 (★확정 후 상세 · 2026-07-15)

> **지위**: B-137 결정 회차에서 사용자가 C안을 확정했다 (BACKLOG B-137 · "고수일수록 한 끗이
> 비싸지는 곡선 내장"). 이 절이 구현의 정본 후보다 — 단, **§8.7 의 수치 전 항목이 사용자
> 승인을 받기 전에는 config·코드 한 줄도 바꾸지 않는다** (등록제 §2.1 · 문서 머리의 계약 그대로).
> 동등성의 눈: `tools/judgment_scale_harness.py` (신설 · 자기 시험 5눈) — 결과는 §8.8.

## 8.1 ① 판정 공식 재환산 — 환산이 서는 자리

```
원장(축)   = 정수 눈금 0~100+/축 (저장되는 유일한 값 — 생성 배분 + 레벨 포인트)
판정치(축) = floor(√원장(축))              ← 환산층. 판정이 원장을 읽는 유일한 문

실행력 = 판정치 + 성별보정(±1 · 히든) + 기술 + 상황보정(캡 ±5) + 2d6
저항   = NPC능력치 + NPC기술 + 경계도 + 의심도 + NPC상태보정 + 7        ← 글자 그대로 무변경
```

- **환산은 한 곳에서만 일어난다** — "판정이 능력치를 읽는 순간". 이것은 새 문법이 아니라
  기존 두 계약의 합류다: 화후 규칙 *"판정 가산은 정수부"* (player_creation.yml:183 —
  정수부를 √의 정수부로 바꾼 것) + 성별 보정의 `applies_to: judgment` (저장하지 않고 읽을
  때만 얹는다). **판정치는 저장되지 않는다** — 원장에서 매번 계산한다 (두 장부의 표류 원천 차단).
- **순서 계약**: `floor(√원장)` → +성별 → +기술 → +보정 → +2d6. 성별·기술·보정이 √ 안(원장)
  으로 들어가면 보정이 증발하거나 왜곡된다 — 하네스 자기 시험 ④가 이 오배선을 잡는 눈이다.
- **판정층 전면 무변경 목록** (전부 judgment.yml 현행 그대로): 등급표 6단(대성공 +4 ~ 치명
  −6) · 정적 난이도 10~18 · auto_resolution ±8 · 재시도 +2 · realm_gap_per_stage 2 ·
  optional_extreme_dice · pvp(direct_opposed·race) · side_risks · action_pairs.
- **기술(0~10)은 이번 재설계 대상이 아니다** (B-134 행위 적립의 것) — 기술에는 원장이 없다.

## 8.2 ② NPC 수치표 연쇄 환산 — 무환산 (원장은 플레이어의 것)

- **계약: NPC 수치는 곧 판정치다.** NPC 는 레벨·포인트를 먹지 않으므로 원장이 없다 —
  `config/npcs/*` 의 능력치 항목 **85건** (`grep -rEo "(근력|민첩|체력|내공|감각|화술|지혜): *[0-9.]+" config/npcs/ | wc -l`)
  은 판정어(1~10) **그대로 한 자도 개서하지 않는다.**
- NPC 의 실수 표기(예: cheongha_npcs.yml:524 흑표 `내공: 3.0`)도 그대로 — **NPC 실수치 =
  등록값** (파생 공식이 읽는 값. 플레이어만 실수치 = √원장 — §8.4·8.7 파생치 계약).
- NPC 파생치(내구 = round(10 + 체력×2 + 경지 + 장비), combat.yml durability)도 등록값을
  읽으므로 **NPC 쪽 연쇄 0건.**
- 남는 것 (§6-6 그대로): 현행 인간 NPC 최고치는 판정 6~7 (취팔선보 거지 · 흑곰 완력 6) —
  판정 9 는 영물 백영묘(민첩·감각 9, cheongha_npcs.yml:524)뿐이다. 최종장 플레이어(특화
  판정 9)와 맞설 **상위 경지 인간 NPC 신규 등록**은 별도 승인 사항이다. 저울이 아니라
  등록부의 빈 칸이다.

## 8.3 ③ 장비 보정 연쇄 — 무환산 (판정층 상수)

- **애병 +1** (equipment.yml `judgment_bonus_owner_only: 1`) · **장비 판정 보정 총합 캡 2**
  (`equipment_judgment_bonus_total: 2`) — 판정층 수치라 `floor(√원장)` **뒤에** 얹는다. 무변경.
- 등급 보정 전부 0 ("등급의 값은 보정이 아니라 생존") — 애초에 환산할 것이 없다.
- 내구 장비 보정(vitality 캡 4)·경감(armor.mitigation)도 무변경 — durability 가 읽는 "체력
  실수치"는 √원장으로 보존된다 (§8.8 파생치 왕복 검산).
- equipment.yml 의 검산 주석(*"2d6 판정에서 +1 은 명중 58.3% → 72.2% + 마진 상승 = 피해
  +28%"*)이 새 눈금에서도 **글자 그대로 유효하다** — 판정층이 한 톨도 안 변했기 때문이다.

## 8.4 ④ 성별 ±1 (B-056) 연쇄 — 판정치 산출 뒤 ±1

- **정본: 판정층 후치(後置)** — `floor(√원장)` 산출 **뒤** ±1. cap 1 · 히든 · 저장 안 함 —
  player_creation.yml gender.gates.attributes 의 기존 계약 전부 그대로.
- *"느껴지되 결정하지 않는다"* 의 보존 증명: 확률 효과가 옛 규칙(능력치에 +1)과 **전 시나리오
  동일** — 하네스 ①이 성별 스윕을 포함해 11,500 시나리오 × 36눈에서 위반 0 (§8.8).
- 비선형의 주석: 후치 ±1 의 원장 환산 가치는 현재치 의존이다 — 판정 X→X+1 상당 = 원장
  2X+1 (초반 ~5점, 캡 부근 ~19점). **히든 보정의 장부 가치는 커지지만 판정층 무게는 불변** —
  이것이 후치를 택하는 이유다 (원장 ±k 로 넣으면 어느 구간에선 0, 어느 구간에선 ±2가 된다).
- B-056(값 ±1 자체의 승인)은 별도로 열려 있다 — 이번 표(§8.7)에서 자리만 승인받는다.

## 8.5 ⑤ 경지 캡 환산 — 제곱표와 XP 사다리의 교차

캡은 **원장에 선다** (포인트가 캡² 를 넘겨 들어가지 못한다). 환산: 옛 캡 c → 원장 캡 c²
(유도: 판정 천장 보존 — floor(√c²) = c, 하네스 ③ 9단 전수 확인).

| 경지 | 옛 캡 (player_creation.yml) | 원장 캡 (=캡²) | 판정 천장 |
|---|---|---|---|
| 범인 | 3 | **9** | 3 |
| 삼류 | 4 | **16** | 4 |
| 이류 | 5 | **25** | 5 |
| 일류 | 6 | **36** | 6 |
| 절정 | 7 | **49** | 7 |
| 초절정 | 8 | **64** | 8 |
| 화경 | 9 | **81** | 9 |
| 현경 | 10 | **100** | 10 |
| 생사경 | 10 | **100** | 10 |

**XP 사다리와의 교차** (근거: cultivation_v3_levels.md §5 확정 사다리 N_k · 레벨당 3포인트 ·
생성 원장 19 — 유년 배분 [2,2,2,2,1,1,1] 제곱합 4×4+3×1):

| 경지 | 자격 Lv (N_k) | 그때 보유 포인트 3(Lv−1) | 전축 용량 7×캡²−19 | 판정 |
|---|---|---|---|---|
| 삼류 | 10 | 27 | 93 | 여유 |
| 이류 | 40 | 117 | 156 | 여유 |
| 일류 | 65 | 192 | 233 | 여유 |
| 절정 | 80 | 237 | 324 | 여유 |
| 초절정 | 90 | 267 | 429 | 여유 |
| 화경 | 100 | 297 | 548 | 여유 |
| 현경 | 105 | 312 | 681 | 여유 |

- **승급이 제때면 포인트는 막히지 않는다** — 자격 레벨마다 보유 포인트 < 전축 용량.
- **정체가 문제다**: 사건 마크 미달로 삼류에 머문 채 레벨만 오르면 **Lv32 에 전축이 캡에
  찬다** (3×31 = 93 = 전축 용량) — Lv33 부터의 포인트는 갈 곳이 없다. **미사용 포인트
  은행(뱅킹) 규약이 필요하다** (신규 미결 — §8.7 표 ⑨. 이중 관문 설계상 정체는 정상 상태다).
- **특화 축의 리듬은 경지가 정한다**: 캡→캡 도약 비용은 9~19점 (16→25 = 9 · 81→100 = 19)
  — 경지 사이 레벨 수 × 3포인트에 비하면 헐값이라, 주 능력치는 **승급 직후 즉시 새 캡에
  닿는다.** √ 압축이 실제로 정하는 것은 주 축이 아니라 **2~4순위 축의 폭**이다 (§8.6).

## 8.6 ⑥ 이중 감속 분석 — 제곱 환산 × XP 후반 하중

근거 수치 (지어낸 것 없음): XP 곡선 확정안 base 20 · growth 1.0565 · R 200 XP/h
(cultivation_v3_levels.md §5 — ★사용자 승인, 실측 재보정 유보 조건부) × C안 제곱 비용 ×
레벨당 3포인트. 계산은 해석적 (`tools/xp_pacing.py` 와 같은 곡선식).

**층별 기여 분해** — 후반 "한 끗(+1)"이 무거워지는 두 겹:

| 층 | 초반 → 후반 | 승수 |
|---|---|---|
| 제곱층 (원장 비용) | 판정 3→4 = 7점 → 판정 9→10 = 19점 | **~2.7×** |
| XP층 (레벨 시간) | Lv2 한 칸 0.11h → Lv100 한 칸 23.1h | **~200×** |

**이중 감속의 주인은 XP 곡선이다** — 제곱층은 그 위의 2~3배 승수다. 이는 설계 의도와
정합한다: 후반을 여정으로 만드는 것은 XP 사다리(사용자 승인 완료)의 몫이고, 제곱층의 몫은
"한 끗의 값어치"(TRPG 저울 보존)다.

**캡 미접촉 가정 — 한 축 전액 특화의 시간표** (생성 2 → 원장 4 시작, 전 포인트 몰빵):

| 판정 도달 | 원장 | 도달 Lv | 누적 시간 | 직전 +1 소요 |
|---|---|---|---|---|
| 4 | 16 | Lv5 | 0.4h | 0.2h |
| 5 | 25 | Lv8 | 0.8h | 0.4h |
| 6 | 36 | Lv12 | 1.5h | 0.6h |
| 7 | 49 | Lv16 | 2.3h | 0.8h |
| 8 | 64 | Lv21 | 3.5h | 1.3h |
| 9 | 81 | Lv27 | 5.6h | 2.1h |
| 10 | 100 | Lv33 | 8.5h | 2.9h |

포인트만 보면 판정 10 이 첫 저녁 이틀거리다 — **그래서 캡이 못이다** (판정 6 은 일류 =
Lv65 자격 + 사건, 판정 9 는 화경 = Lv100 + 사건). 캡 접촉 후의 실제 체감:

- **주 축**: 감속을 느끼지 않는다 — 승급 직후 즉시 캡 (§8.5). 리듬은 경지 사다리 그대로.
- **부축(2~4순위)**: 여기가 √ 가 사는 곳이다. 후반 레벨에서 부축 한 끗의 시간 —
  판정 7→8 (15점 = 5레벨): Lv85→90 = **56.6h** · 판정 8→9 (17점 ≈ 6레벨): Lv94→100 =
  **114.7h** · 캡 미접촉 축의 판정 9→10 (19점 ≈ 6레벨): Lv100→106 = **159.5h**.
  §3 의 "후반 판정 +1 에 6레벨 ≈ 130시간+" 우려가 이 자리에서 실측된다 — 단 **주 축이
  아니라 부축의 이야기**고, 부축 확장은 선택이지 정체가 아니다.
- **최종장 스냅샷** (Lv100 = 생성 19 + 297 = 원장 316): 극특화 = 3축 원장 81(판정 9) +
  4축째 73(판정 8) — 화경 캡이 셋을 허용한다. 균등 = 316/7 ≈ 45 (판정 6.7) — 옛 일류
  고수의 전신. **"특화가 비싸져 빌드가 넓어진다"(§3)의 정량 확인.**

**결론 (제안)**: 제곱층 자체로는 페이싱 재보정이 **불요하다** — 주 축의 성장 리듬은 XP
사다리·경지 관문이 이미 정했고 (그 사다리는 승인이 끝났다), 제곱층은 부축의 폭만 누른다.
후반 정체감 위험의 손잡이는 √ 가 아니라 **growth (XP 곡선)** 하나이고, 그것은 이미 "실측
재보정 유보"로 계약되어 있다 — 이중 감속을 이유로 지금 수치를 더 만들지 않는다.

## 8.8 동등 대조 하네스 — `tools/judgment_scale_harness.py` (신설)

**무엇을 재나**: 같은 판정 상황(능력치 1~10 × 성별 ±1 × 기술 5종 × 보정 5종 × 저항 8~30)을
옛 눈금과 새 눈금(원장 X² → floor(√))으로 굴려 **등급 분포·성공권·기대 마진의 완전 일치**를
잰다. 2d6 36눈 해석적 전수 (몬테카를로 불요 — judgment.yml 등급 재설계와 같은 방법).
등급표·캡·성별 cap·내력 계수는 전부 등록부에서 읽는다 (하드코딩 금지).

실행 결과 (2026-07-15):

```
═══ B-137 C안 제곱 환산층 — 옛/새 눈금 동등 대조 (2d6 해석적 전수) ═══

  판정 전수 대조: 능력치 10 × 성별 2 × 기술 5 × 보정 5 × 저항 23 = 11,500 시나리오 × 36 눈 전수
  ✅ ①② 판정 전수 + 중간 원장: 위반 0건
  ✅ ③ 경지 캡 제곱 환산 (9단): 위반 0건
  마이그레이션 표본 13건 (경계 3.99 · 4.999 · 9.99 포함)
  ✅ ⑤ 마이그레이션 판정치 보존 (실수안·정수안): 위반 0건
  ✅ ⑥ 파생치 실수치 보존 (내력 풀 왕복): 위반 0건

  대표: 대등 판정 (옛 능력치 5 · 기술 0 · 보정 0 · 저항 13 ↔ 원장 25)
    critical_success   옛  1/36   새  1/36
    success            옛  5/36   새  5/36
    narrow_success     옛  9/36   새  9/36
    partial_success    옛 15/36   새 15/36
    failure            옛  5/36   새  5/36
    critical_failure   옛  1/36   새  1/36
    성공권(마진≥0)     옛 41.7%   새 41.7%   ·   기대 마진 옛 -1.00 새 -1.00

  총 위반: 0건 — 옛/새 눈금 동등
```

자기 시험 (`--selftest`) — 일부러 어긋난 환산 4종을 심어 눈이 뜨였는지 본다:

```
  ✅ 바른 환산(X², floor√, 성별 후치)은 위반 0
  ✅ 원장 = 10X 오배선을 잡는다 (floor(√10X) ≠ X)
  ✅ 판정치 = round(√원장) 오배선을 잡는다 (원장 (X+1)²−1 이 X+1 로 넘친다)
  ✅ 마이그레이션 round(x²) 오배선을 잡는다 (x=3.99 가 판정 4 로 승격)
  ✅ 성별 ±1 을 원장에 넣는 오배선을 잡는다 (floor(√(X²+1)) = X — 보정 증발)

  자기 시험: 전부 통과
```

자기 시험이 잡아낸 세 함정은 구현 시 실제로 밟기 쉬운 자리다: **round 가 아니라 floor**
(경계 원장이 판정을 승격시킨다) · **마이그레이션은 round(x²) 금지** (옛 3.99 가 판정 4 로
둔갑) · **성별·기술·보정은 √ 밖** (안에 넣으면 증발·왜곡). 구현이 끝나면 이 하네스가
그대로 회귀 감사가 된다 — B-137 검증 조건("판정 재현 하네스") 충족.
