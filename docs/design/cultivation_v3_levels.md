## 0. 네 기둥 (사용자 결정 2026-07-15 — 전부 확정)

| # | 결정 | 내용 |
|---|---|---|
| ① | **레벨↔경지 = 혼합** | 레벨은 자격, 사건은 문 — 경지 승급은 **레벨 N 이상 + 사건 마크**(기존 battle_marks) 둘 다 |
| ② | **포인트 → 능력치 7종** | 근력·민첩·체력·내공·감각·화술·지혜 (judgment.yml attributes 그대로) |
| ③ | **병행 + 영역 분리** | XP 포인트 = **능력치 전용** · 행위 적립(B-134) = **기술·화후(숙련) 전용**. 같은 원장을 두 손이 안 두드린다 |
| ④ | **시간 헌법 폐기** | 하루 5구간 수련 상한 · 환산표(능력치+1=1년) 폐기 — 성장 속도는 XP 곡선이 정한다 |

한 문장의 계약: **"스탯은 레벨업에서 찍고, 기술은 써야 는다."**

## 1. 경험 층 (신설)

- **원천**: 몬스터 처치 (사냥 등록부의 기존 등급이 XP 눈금의 뼈대) · 의뢰 완수 ·
  일과(B-134 디제시스 — 스승·문파 일과는 XP **보너스**로 편입).
- **레벨업**: 경험이 곡선을 넘으면 레벨 +1 → **스탯 포인트 P 지급** → 능력치 7종에 찍는다.
- **찍은 능력치는 판정 공식에 그대로** (judgment.yml: 실행력 = 능력치 + 기술 + 보정 + 2d6) —
  새 공식 없음.
- **곡선의 산출 (★사용자 확정 2026-07-15)**: 수치를 손으로 짓지 않는다 — **플레이 시간대별
  데이터를 분석해 XP/시간 율을 재고, 경지별 목표 도달 시간에서 곡선·자격 레벨을 역산한다.**
  절차: ① XP 원천 배선에 계측을 함께 심는다 (세션별 획득량·시간) ② 모델 도구
  `tools/xp_pacing.py` (신설됨 · 자기 시험 5눈) — 입력: 실측 XP/시간 + 목표 도달 시간 H_k,
  출력: 곡선·N_k 제안표 ③ 목표 도달 시간 H_k 와 산출표는 **사용자가 승인**한다.
- **★페이싱 앵커 (사용자 확정 2026-07-15)**: **최종장(삼파전 결전) 도달 시 플레이어 기준
  화경~현경.** 이야기는 길다 — 사다리는 막 등록부(world_clock.yml)의 시간표에 정렬한다:
  세계일 = 현실 1일, 막 진입 D1(서장) → D20(마교 암류) → D50(혈교 부상) → D80+(삼파전 ·
  사람 승인) → 결전(최종장). 【제안】 활동 플레이어 2h/일 · 최종장 예상 D≈120 로 환산한
  막↔경지 대응: 서장기 삼류(3h) → 암류기 이류~일류(15~45h) → 부상기 절정(100h) →
  삼파전기 초절정(160h) → **최종장 화경(240h)~현경(320h)**. 생사경(600h)은 시즌 너머의
  전설 — 최종장의 기준이 아니다. base_day 자체가 "실측 보정 대상"이므로 이 사다리도
  같은 실측에서 함께 재보정한다.
- **죽음 (★사용자 확정 2026-07-15)**: **레벨 처분 없음** — 죽음의 대가는 의학당 부활의
  이동시간과 시간이다 (B-111 의 "항상 부활" 계약과 정합. 레벨·경험은 유산 목록 무관).

## 2. 경지 층 (유지 — 관문만 이중)

경지 9단계·이름·순서 불변 (cultivation_stages). 승급 = **레벨 자격 N_k 【미결 ①】 도달 +
기존 사건 마크** (기연·사선·실전 — battle_marks 불변). 레벨 노가다만으로 경지를 못 사고,
사건만으로도 못 오른다 — 숫자와 서사의 이중 관문 (사용자 결정 ①).

## 3. 행위 층 (B-134 — 대상 한정)

`docs/design/training_by_doing.md` 의 문법(행위 → 적립 · 스승·일과 디제시스)은 그대로 살되,
**쌓이는 곳이 기술·화후(숙련)로 한정된다** — 검을 쓴 손은 검술이, 숨은 발은 은신이 는다
(judgment.yml skills · combat_accrual 결). **능력치에는 한 톨도 안 쌓인다** — 그 선을
눈(audit)이 지킨다. B-134 미결 중 "문턱 N"은 남고, "하루 5구간"은 ④로 소멸.

### 4-b. 바닐라 XP바 — 표시 계약 (★사용자 확정 · 캐비앳 둘)

레벨 숫자·게이지는 서버가 원장에서 계산해 그린다 (`setLevel`/`setExp` — 표시 전용이라
"레벨당 경험치량 조절"은 바닐라 제약 없이 자유다). 디자인 개선은 사용자가 리소스팩으로.

- **① 확정 (★사용자 2026-07-15) — 바의 이사**: 바닐라 XP바 = v3 경험/레벨.
  내공·내력은 액션바에서도 **분리해 별도의 바**로 띄운다 (커스텀 HUD — 보스바 채널이 1순위
  후보. 디자인은 사용자가 리소스팩으로 다듬는다). 액션바 energySeg 는 별도 바가 선 뒤 철거.
- **② 확정 (★사용자 2026-07-15) — 레벨 소비처 제거**: 모루·인챈트대의 레벨 소모를 걷어낸다.
  **강화·인챈트·수리는 전부 상점(강화소·무기점)에서 돈으로** — 경험은 성장의 것, 돈은 물건의
  것. 수리 가격은 등록부에 이미 있다 (economy.yml 수리_범철 200 · 수리_정련 2000); 강화·인챈트
  가격표는 신설 미결. 몹 오브는 흡수(0) — 원장은 v3 XP 하나다. → **B-136** 트랙.
