# 시스템 점검 — 왜 숫자는 좋아지는데 눈에는 나빠졌나 (2026-08-11)

사용자 지시: 「기존 기능이 있다면 <b>바로 사용하는 게 아닌</b> 해당 기능이나 시스템을
확인하고 분석하고 개선하거나 새로 생성하는 방식으로 진행하고…
<b>눈의 문제가 자주 보이므로</b> 개선책을 제시하고 판단하여 개선」

## ★눈이 실패하는 세 가지 유형

지금까지 자를 <b>스무 번 넘게</b> 고쳤다. 사유를 모아 보니 셋뿐이다.

1. **오늘의 값을 외운 자** — 「깊이−13」·「37×18」·좌표 `(7,8)`.
   도면 치수가 바뀌면 죽는다. → <b>규칙을 물어라</b>. (고치는 법 확립됨)
2. **이름으로 구조를 고르는 자** — `contains("mangrove_log")`.
   팔레트가 바뀌면 죽는다. → <b>구조를 물어라</b>. (확립됨 · `shaftIndex`)
3. **★색만 재는 자** — 평균 명도 · 어두운 면 비율 · 최빈색.
   <b>「무엇으로 읽히는가」를 못 잰다.</b> ← 오늘의 실패. **아직 답이 없었다.**

3번이 위험한 까닭: 1·2번은 <b>헛짖는다</b>(조성은 멀쩡한데 자가 운다). 3번은 <b>안 짖는다</b> —
잘못 만든 것에 최고점을 준다. 오늘 `red_nether_bricks` 기둥이 색 지표 만점이었고 실물은
조적 기둥이었다.

## 고친 것 ① — 색표를 <b>손에서 뺐다</b>

`blueprint_draw.py` 는 <b>손으로 적은 17종</b> 표를 갖고 있었다. 팔레트가 바뀌어도
안 따라 적으면 아무도 안 죽으니 조용히 낡았다 — 재 보니 64%를 모르고 있었다.

→ `tools/block_palette.py`: 클라이언트 jar 의 <b>실제 텍스처</b>에서 뽑는다.
리소스팩이 덮은 블록은 <b>팩 것을 쓴다</b>(게임에서 보이는 것이 그것이다).

```
블록 색표 1110종 (팩이 덮은 것 236종) · 본전이 쓰는 재료 13종을 <b>전부</b> 안다
```

- 선형(sRGB→linear) 평균 — 감마 공간에서 평균 내면 어두운 텍스처가 밝게 나온다
- 알파 128 미만은 색이 아니다 (살창의 빈 곳)
- 불투명 비율을 함께 낸다 (성긴 것을 도면이 알아야 한다)
- <b>모르는 재료는 자홍색으로 칠하고 이름을 세어 보고한다</b> — 조용히 안 넘어간다
- 눈의 눈 10개 (선형 평균 검증 포함) — `--selftest`

## ★남은 구멍 — 도면이 실물의 <b>절반</b>만 그린다

색표를 물리고 다시 그리니 정면도·측면도가 제대로 나온다. 그런데 <b>지붕이 없다.</b>
도면은 `plan`+`columns` 만 그리고, <b>지붕·공포·간포·처마·소품은 조성기가 만든다</b> —
그래서 도면에 안 보인다. 실루엣의 절반이 지붕인데.

<b>그래서 이 도면으로는 오늘의 문제를 못 잡았을 것이다.</b>

## ③ 완료 — 읽힘 자 (2026-08-11)

### 무엇을 재나 — <b>결</b>

색만 재는 자는 「무엇으로 읽히는가」를 <b>영영 못 잡는다</b>. 색 분포가 같아도 무늬가 다르기 때문이다.
그래서 <b>변화의 방향</b>을 잰다. 텍스처는 타일링되므로 가장자리는 감싸서 잇는다.

```
Ex = 가로로 갈 때의 변화량  →  <b>세로선</b>이 만든다 (나무결·세로살)
Ey = 세로로 갈 때의 변화량  →  <b>가로선</b>이 만든다 (벽돌 줄눈·단 이음)

방향 = (Ex−Ey)/(Ex+Ey) ∈ [−1,+1]     + 세로결 · − 가로줄눈
세기 = (Ex+Ey)/2/255                  0 이면 민판
```

★<b>세기를 먼저 본다.</b> 무늬가 약하면 방향은 뜻이 없다 —
`red_terracotta` 는 방향이 −0.184 지만 세기가 0.007 이라 <b>민판</b>이다.
이걸 「가로줄눈」이라 부르면 자가 헛짖는다.

★이것은 <b>재료의 성질</b>이라 사진도 카메라도 필요 없다. 눈이 즉석에서 부른다.

### 자를 검증했다 — 세 갈래가 깨끗이 갈린다

```
통나무 옆면   oak +0.422 · dark_oak +0.416 · spruce +0.432 · birch +0.424 · cherry +0.469
             stripped_oak +0.307 · stripped_dark_oak +0.295        → 8종 중 <b>6종 세로결</b>
조적         bricks −0.197 · stone_bricks −0.207 · red_nether_bricks −0.321
             nether_bricks −0.318 · mud_bricks −0.191 · blackstone −0.163  → <b>7종 전부 가로줄눈</b>
민판         red_terracotta 0.007 · white_concrete 0.003 · polished_andesite 0.009
```

예외 둘(`mangrove_log` −0.390 · `stripped_mangrove_log` −0.210)은 <b>자가 맞다</b> —
그 텍스처가 실제로 가로 띠다. (우리가 오래 쓰던 기둥 재료도 그랬다는 뜻이다.)

### 박은 눈 다섯

```
★★★적주가 <b>조적으로 안 읽힌다</b>           (red_terracotta = 민판 → 통과)
★★[눈의 눈] red_nether_bricks 는 잡힌다
★★[눈의 눈] 통나무는 안 잡힌다 (헛짖지 않는다)
★★살창에 <b>결이 있다</b>                     (dark_oak_trapdoor 세기 0.0351)
★★공포와 창방이 <b>명도로 갈린다</b>           (114.5 대 74.2 · 차 40)
```

### ★끝까지 확인했다

도면에 `red_nether_bricks` 를 실제로 넣고 눈을 돌렸다:

```
✗ ★★★적주가 조적으로 안 읽힌다 (red_nether_bricks = 가로줄눈)   → 507/508
되돌린 뒤                                                    → 508/508
```

<b>어제의 실패를 오늘의 눈이 짓기 전에 잡는다.</b>

### 아직 못 재는 것 (정직하게)

- <b>「와플처럼 보인다」</b> — 격자의 <b>주기</b>가 굵어 촌스러운 것은 방향이 0 이라 「격자」로만 읽힌다.
  주기(공간 주파수)를 재면 되지만 이번엔 안 넣었다
- <b>배치의 읽힘</b> — 「공포가 통짜 판으로 뭉친다」는 재료가 아니라 <b>이웃과의 관계</b>다.
  명도 차 자를 하나 넣었지만 이건 시작일 뿐이다
- <b>그늘</b> — 실제 화면의 어두움은 재료 명도가 아니라 빛이 만든다. 그건 사진의 몫이다
