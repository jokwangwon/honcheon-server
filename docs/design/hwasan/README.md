# 화산파 — 설계 문서 체계

사용자 확정 (2026-08-06): 「콘셉트 이미지를 **실제 블록 설계도로 번역**하는 단계」.

이 폴더는 그 번역의 자리다. 콘셉트 이미지를 더 만드는 곳이 아니다.

---

## 0. 왜 이 체계인가 — 그리고 어디를 바꿨는가

제안된 방법론을 거의 그대로 받았다. **두 곳만 다르게** 한다. 둘 다 이 저장소가
이미 데어 본 자리라서다.

### ㉠ 최종 산출물은 `.schem` 이 아니라 **도면 yml** 이다

제안: 「최종 목표는 이미지 파일이 아니라 `.schem` 또는 좌표 기반 구조 데이터」.

좌표 기반 구조 데이터라는 목표는 옳다. 그런데 `.schem` 은 **이진 파일**이라
`git diff` 가 안 되고, 감사(눈)가 안 읽고, 무엇이 왜 바뀌었는지 남지 않는다.
우리는 이미 그 자리에 `config/blueprints/*.yml` 을 두고 있다 — 평면 ASCII 한 장 +
문자별 y 단면. **사람이 읽고, git 이 diff 하고, 눈이 잰다.**

    plan     : 평면 한 장 (1문자 = 1칸)   ← 무엇이 어디 있는가
    columns  : 문자 → y 단면 (아래→위)    ← 그것이 위로 어떻게 서는가
    roof     : 코드 문법 호출              ← 압출로 못 만드는 것

필요하면 여기서 `.schem` 을 뽑을 수 있다. 반대는 안 된다.

### ㉡ 도면 5종은 **손으로 그리지 않는다 — 정본에서 뽑는다**

제안: 「정면도·측면도·평면도·지붕 분해도·블록 팔레트가 있어야 한다」. 옳다.

그런데 도면을 따로 그리면 **도면과 실물이 갈라진다.** 이 저장소가 여러 번 데인
병이다 — 신고표(`palette()`)가 실물보다 넓어서, 이미 폐기한 재료를 눈이 계속
지키고 있었던 일이 있다 (2026-08-05).

그래서 도면은 `tools/blueprint_draw.py` 가 **도면 yml 에서 뽑는다.**
여기 있는 그림은 언제나 실물과 같다. 갈라질 수가 없다.

    python3 tools/blueprint_draw.py hwasan_gate docs/design/hwasan/01_산문

    화산파 정면 = 남쪽 · 본전 남향 · 주축 남북
    좌측(서) 생활구역 · 우측(동) 수련구역 · 후산 북쪽

    정면도 : 남에서 북을 봄
    측면도 : 동에서 서를 봄

## 3. 순서 — 건물보다 지형이 먼저

제안의 4단계를 우리 명령에 대응시키면:

| 단계 | 제안 | 우리 명령 | 상태 |
|---|---|---|---|
| 1 | 회색 박스 배치 | `혼천 캠퍼스시험` 의 패드 + 검수 | ✔ 돌고 있다 |
| 2 | 지형·옹벽 | `혼천 산세시험` → `산군시험` | ✔ 돌고 있다 |
| 3 | 건물 외형 | `혼천 도면시험 <이름>` | 진행 중 (산문·본전) |
| 4 | 디테일·생활감 | GREEN·PROPS 스위치 | **꺼져 있다** |

「건축보다 지형을 먼저」는 이미 그렇게 하고 있다. 화산파의 인상이 건물보다
절벽과 단에서 온다는 판단도 실측이 뒷받침한다 — 2026-08-06 에 주상절리와
대(臺) 실루엣을 넣자 구도가 크게 달라졌다.

## 4. 이미지 AI 의 자리 — 실측으로 확인했다

제안: 「생성형 이미지 AI 는 정확한 블록 배치를 유지하기 어렵다」.

**우리가 그것을 쟀다.** 진짜 마인크래프트 렌더는 같은 블록이 같은 빛을 받으면
픽셀까지 똑같은 조각으로 되풀이된다. 무작위 조각 420개를 서로 견주면:

| 대상 | 가장 닮은 두 조각의 차이 | 「거의 같음」 쌍 |
|---|---:|---:|
| 우리 스크린샷 (절벽) | 0.05 | 64 |
| 우리 스크린샷 (건물) | 0.91 | 5 |
| 레퍼런스 성벽 | 5.43 | **0** |
| 레퍼런스 절벽 | 3.48 | **0** |

되풀이가 하나도 없다. **레퍼런스는 마인크래프트 스크린샷이 아니다** (파일명도
`ChatGPT Image`, 고유 색 272,001). 그러니 「어떤 블록을 썼나」에는 답이 없다 —
블록을 쓴 적이 없기 때문이다.

레퍼런스에서 읽을 수 있는 것과 없는 것:

| 읽을 수 있다 | 어떻게 |
|---|---|
| 치수·비율 | 블록 격자 (한 칸 14~18px) |
| 재료의 **수** | 색 무리 (색도 같고 밝기만 다르면 한 재료다) |
| 색 계열 | 그늘 무리의 색도 (온기는 햇빛이다 — 상관 +0.94) |
| 배치 리듬 | 되풀이 주기 |
| 옆모습 | 실루엣 추적 |

**읽을 수 없는 것: 정확한 블록 이름.** 우리가 고른 블록은 「레퍼런스가 쓴 블록」이
아니라 「레퍼런스의 색·비율에 가장 가까운 바닐라 블록」이다. 이 구분을 흐리면
없는 정답을 쫓게 된다.
