# 화산파 모델링 계약 (D2) — 가까이서 봤을 때 무엇이 있어야 하는가

> **사용자 확정 2026-08-09.** `contract.md` 가 **공간/구조** 계약이라면 이 문서는 **모델링** 계약이다.
>
> ```
> 지금까지 : 무슨 건물인가 · 얼마나 큰가 · 어디에 서는가 · 어떤 지붕인가
> 이제부터 : 그 건물이 가까이서 봤을 때 얼마나 정교한가
> ```
>
> ★**「예쁘게 해라」를 계약으로 만들지 않는다.** 예쁘다는 건 검사할 수 없지만
> 「창이 벽보다 한 칸 들어가 있는가」 · 「기둥 아래 주초가 있는가」 ·
> 「처마 밑에 서까래가 있는가」는 **검사할 수 있다.** 지금까지의 방법론과 같다.

## 0. 시험체는 강당 한 채다

전 건물에 동시에 넣지 않는다. **강당**을 「화산파 디테일 시험체」로 삼는다 —
새 `assembly` 유형의 첫 건물이고, 크기가 넉넉하고, 단층이라 구조가 읽히고,
`sweep` 지붕과 적주·회벽·격자창이 다 있다. 산문보다 단순하고 행각보다 복잡하다.

```
강당에서 시험 → 전·후 사진 비교 → 만족하면 이 문서 확정
→ 본전 / 산문 / 생활관 / 암자 / 창고 순으로 전파
```
★**전파 전에 고치는 것이 전파 후에 고치는 것보다 훨씬 싸다.**

## 1. 입면 깊이 — 한 면에 다 붙이지 않는다

★**프로파일로 둔다** (사용자 2026-08-09). 적주 +1 과 격자창 −1 사이는 실제로 **2칸 차이**라
강당처럼 큰 집에서는 그림자가 잘 생기지만, 생활관·암자처럼 작은 집에 그대로 전파하면
창이 지나치게 움푹해 보일 수 있다. 값을 건물마다 흩지 말고 **프로파일**만 고른다:

```yaml
facade_depth_profile:
  full:    {column: 1, plaster: 0, lattice: -1}   # 강당 · 본전 · 산문
  compact: {column: 1, plaster: 0, lattice:  0}   # 작은 생활관 · 암자 (필요할 때)
```
★강당의 값이 곧 `full` 의 기준이다 — **지금 값은 바꾸지 않는다.**

색이 아무리 좋아도 **한 평면에 붙어 있으면 평평하다.** 칸마다 앞뒤를 준다
(도면의 `depth:` 절 · 부호는 **바깥이 +**):

| 요소 | 깊이 |
|---|---:|
| 적주 | **+1** |
| 창틀(인방) | +1 |
| 회벽 | 0 |
| 격자창 | **−1** |

## 2. 기둥은 막대기가 아니라 구조체다

```
   도리 / 창방
  ═══════════
      █ 기둥
      █
     ▓▓▓  주초
```
필요한 것: **주초 · 기둥 · 창방/인방 · 도리 · 처마 연결**. 실제 전통 결구를 복제할 필요는 없다.

## 3. 처마 밑 — 가장 크게 갈리는 곳

지붕을 「검은 덩어리」에서 나눈다: **기와면 · 처마 끝 · 서까래 · 도리 · 추녀**.
★**아래에서 올려다봤을 때 서까래가 보여야 한다.**

## 4. 창호는 최소 셋 — 모양과 개수를 <b>가른다</b>

★`family`(모양)와 `density`(개수)를 한 규칙으로 묶으면 생활관과 창고가 둘 다 W1 이라는
이유로 다시 비슷해진다. **갈라 둔다.**

```yaml
window: {family: W2, density: medium}
```

| usage | family | density |
|---|---|---|
| residence | W1 | high |
| storage | W1 / none | low |
| hermitage | W1 | low |
| assembly · corridor | W2 | medium |
| council · main_hall | W3 | medium |
| pavilion | none | none |

우선순위: **`usage` 기본값 → `rank` 보정 → `bay role` 최종 결정.** 해시는 어디에도 안 낀다.

| 창호 | 결 | 쓰는 곳 |
|---|---|---|
| `W1` | 세로살 | 생활 · 창고 |
| `W2` | 사각 격자 | 강당 · 행각 |
| `W3` | 복합 격자 | 본전 · 장로회 |

★`usage` / `rank` / 칸의 역할이 정한다. **해시로 고르면 그건 잡티다** (바닥에서 배운 자).

## 5. 기단 — 무게감은 여기서 온다

```
벽 · 기둥
──────────
석재 기단      ← rank 가 층수를 정한다
████████
한 단 돌출
██████████
마당
```
| 위계 | 기단 |
|---|---:|
| auxiliary | 1 |
| secondary | 2 |
| principal | 2 |
| ceremonial | 3 |

## 6. 공포 — 이름보다 <b>자리 계약</b>이 먼저다

> **공포는 적주의 머리 위에서만 시작한다.**

적주가 없는 곳에 붙으면 그건 공포가 아니라 「처마 밑에 블록을 막 붙여놓은 것」이다.
그리고 공포는 **처마를 받친다** — 기둥 머리 *위*가 아니라 **지붕 바로 아래**에 앉는다.

검사: `공포 anchor == 적주 상단` · `개구를 침범하지 않음` · `지붕 위로 안 튐` ·
`회전 시 outward 도 함께 회전`.

| 위계 | 공포 | 화산파 |
|---|---|---|
| auxiliary | `none` | 행각 · 암자 |
| secondary | `simple` | 생활관 · 정자 |
| principal | `medium` | **강당** · 장로회 |
| ceremonial | `elaborate` | 산문 · 본전 |

## 7. LOD — 모든 곳에 근경 디테일을 넣지 않는다

넣으면 오히려 지저분해지고 서버 자원도 낭비한다.

```
원경 : 지붕 실루엣 · 폭/높이 · 적백 대비 · 층수
중경 : 기둥 간격 · 창호 · 기단 · 처마 · 난간
근경 : 서까래 · 공포 · 문살 · 주초 · 현판 · 등롱 · 작은 장식
```

## ★남은 것 — 하층 정면이 「벽」이 아니라 「주랑」으로 읽힌다

REF-1 을 세우고 정면에서 보니 하층이 열려 보인다. 실측이 까닭을 정확히 짚는다 (y=61 · z=53 정면 평면):

```
col  4 (P)  air          ← 적주가 +1 로 나가며 **벽면에 제 폭만큼 구멍을 남겼다**
col  5 (W)  bone_block

→ **사용자 결정거리**: 「적주는 옮기지 않고 한 겹 덧댄다」로 갈지, 툇간으로 받아들일지.

# REF-1b — 본전 조형 교정 (2026-08-09 · 사용자 확정)

REF-1 의 치수·패드는 승인·유지. 재료도 그대로(`cobbled_deepslate` 계열). **형태만** 고쳤다.

## ★깊이는 「옮기는 양」이 아니다 — D2 계약의 의미 보정

정면 사진이 드러낸 것: `+1` 을 **이동**으로 구현하니 적주가 나가면서 **벽면에 세로 구멍**을 남겼고,
하층이 **폐쇄 전각이 아니라 주랑**으로 읽혔다. 레퍼런스의 하층은
「붉은 목구조가 흰 회벽·창호 **앞에 덧대어진** 폐쇄 전각」이다.

**부호가 방식을 정한다** — 도면에 새 글자를 안 늘린다:

| 부호 | 방식 | 뜻 |
|---|---|---|
| `+` | **overlay** | 기준면은 **배경(회벽)으로 채우고** 한 칸 밖에 덧댄다 |
| `0` | base | 기준면 그대로 |
| `−` | **recess** | 기준면엔 **창틀만** 남기고 **채움 켜만** 안으로 물린다 |
| — | carve | 개구는 처방의 `air` 켜가 이미 판다 |

배경 글자는 **깊이 0 이면서 회벽을 쓰는 처방**을 찾아 쓴다 (`Blueprint.backingChar()`).
★이 보정은 본전만이 아니라 **깊이를 쓰는 모든 도면**에 적용된다 (현재 강당·본전).

실측 단면 — D칸(x−12) 기준면 z53 / 한 칸 안 z52 (y56→67):

```
z53   ####...#####      창틀은 남고 창만 3켜 뚫렸다
z52   ###.###....#      살창이 그 뒤에 선다
```

## ★grand 물매는 오목하다

REF-1 로 지붕 **상자**는 맞췄는데 화면은 여전히 달랐다. 까닭은 물매다 —
한 켜에 한 칸씩 곧게 좁히면(1:1) 외피가 **계단식 피라미드**로 읽힌다.
`mainhall_ref.png` 의 지붕은 **처마 쪽이 완만하고 용마루로 갈수록 급하다**.

```
바깥 1/3 : 두 칸에 한 켜   (넓고 완만한 처마)
그 안    : 한 칸에 한 켜   (용마루로 갈수록 급해진다)
```

★한 켜에 **두 칸 이상 뛰지 않는다** — 뛰면 외피에 세로 구멍이 생긴다.
★평탄 구간의 바깥 켜는 **반블록**이다 — full block 이면 그 켜가 통째로 테라스 한 단이 된다.
★기존 `sweep`(산문 등)은 이 식을 **안 탄다**. 그대로 1:1 이다.

실측 물매 (남쪽 처마 z55 → 안으로) = `[0,0,1,1,2,3,4,5,6]` — **설계식과 같다.**

## 그 밖

## ★★★진범 — 「밝은 갈색 3단 띠」는 재료가 아니라 **공포**였다

**공포가 정면 전 폭에 깔려 있었다.** 까닭 둘 —

1. **「적주인가」 판정이 너무 넓었다.** 조건이 「처방에 `mangrove_log` 가 **들어 있는가**」였는데,
   본전은 **회벽·격자의 인방도 mangrove 한 켜**다. 그래서 **모든 벽 칸이 적주로 세어졌다.**
   → 적주는 **세로로 이어진 기둥**이다: `count >= POST_MIN_COURSES(3)`.
   ★강당은 회벽에 목재가 없어 **우연히** 멀쩡했다 — **우연은 계약이 아니다.**
2. **공포가 좌우 ±1 로 번졌다.** 본전 적주는 3칸 주기라 ±1 이면 3칸을 다 덮어
   **이웃 공포끼리 손을 잡았다.** → 공포는 **적주 위에서만**. 번지면 제가 만들려던 리듬을 지운다.

★**옛 눈은 소스에 조건이 적혀 있는지만 봤다.** 조건은 적혀 있었고, 다만 **너무 넓었다.**
  이제 눈이 **실제로 몇 칸이 골라지는지를 센다** — 글자가 아니라 결과를 묻는다.

```

고친 뒤     기와 184 · 조약 심층암 <b>0</b>

**계단·반블록·담장·귀솟음·용마루로 형태를 썼기 때문**이다. 몸체에도 그것이 필요했다.

★**성공 조건**: 스크린샷을 **흑백으로 바꿔도** 기둥·창·보·공포·기단·중앙문이
서로 다른 부재로 읽힌다. 색을 다 빼고도 전·후가 달라야 한다.
★재료·팔레트·bbox·bay·기단 단수·지붕은 **한 칸도 안 건드렸다** — 무엇이 형태 때문인지 갈리게.

| | 무엇을 | 어떻게 |
|---|---|---|
| **S1** 기둥 | 통나무 한 줄 → **작은 모델** | 주초 `stone_brick_wall`(통나무보다 가늘다) → 몸통 → 주두 |
| **S2** 창 | 네모 구멍 → **창턱·상인방** | 창턱 `mangrove_slab` — 살창 아래에 턱과 그늘 |
| **S3** 보 | 통짜 판 → **반블록 단면** | 도리 `dark_oak_slab` — 정면을 가로지르는 **기하가 만든 그림자 골** |
| **S4** 공포 | 판재 더미 → **계단형 받침** | 계단 → 반블록 → 계단. 위로 갈수록 밖으로 받쳐 나간다 |
| **S5** 기단 | full block 케이크 → **몰딩** | 맨 밖에 `stone_brick_slab` 치마 한 바퀴. 단 높이·문지방 불변 |
| **S6** 중앙문 | 한 겹 → **세 겹 깊이** | 벽 0 · 문설주 +1 · **문두 처마 +2** (`dark_oak_slab`) |

## ★계단의 방향도 「자리가 정한다」

도면 한 장이 네 벽에 다 쓰이므로 도면은 방향을 못 적는다. 살창과 같은 규약으로,
**계단은 오르는 쪽이 안쪽**을 향한다 — 높은 면이 벽에 붙고 낮은 단이 밖으로 나와
처마 밑에 그늘이 지는 몰딩이 된다 (지붕 `putRoofStair` 와 같은 규약).

# REF-2C — 회벽·창호 최종색 (2026-08-10) · **측정으로 끝냈다**

사용자: 「REF-2C 에서 또 여러 색 후보를 시험하며 시간을 많이 쓰면 안 된다.
현재 가장 큰 품질 상승 여지는 색이 아니라 REF-3 형태에 있다.」

그래서 후보를 렌더해 비교하는 대신 **지금 화면을 재서** 무엇이 실제로 안 갈리는지부터 봤다.
정면 사진을 구간별로 색 양자화해 **명도·채도**를 뽑았다.

```
회벽 판          명도 41   채도  3   ← 화면에서 <b>유일한 무채색 밝은 면</b>
주두 (밝은 점)   명도 50   채도 11
상부 띠 목재     명도 32~37 채도 15~16   ← 넷이 Δ5 안에 몰려 있다
적주             명도 24   채도 31~38
창살·실내        명도 16~17
```

## 세 질문에 대한 답

| 질문 | 답 | 근거 |
|---|---|---|
| `bone_block` 유지 vs 대체 | **유지** | 회벽은 화면에서 **유일한 무채색(채도 3) 밝은 면**이다. 목재는 전부 채도 15 이상이라 **채도로 갈린다.** `white_terracotta` 는 더 어둡고 붉어 목재 무리로 내려앉고, `calcite` 는 사용자 지적대로 석재로 읽힌다. |
| 창호 명도 | **유지** | 창살·실내 16~17 vs 적주 24 → Δ8. 갈리고, 더 죽이면 살창 결이 사라진다. |
| 밝은 베이지 accent | **주두는 통과 · 상부 띠는 색 문제가 아니다** | 주두 50 vs 띠 36 → Δ14 로 점이 살아 있다. 남은 것은 **띠 안의 목재 넷이 Δ5 안에 몰린 것**인데, 이는 처마 그늘이 색상차를 눌러 생긴 것이라 **재료를 바꿔도 안 갈린다.** |

## ★결론 — 색은 바꾸지 않는다

띠가 아직 한 덩어리로 보이는 까닭은 **재료가 아니라 그 자리의 빛**이다.
처마 밑 깊은 그늘이 채도차를 눌러, 서로 다른 네 목재가 같은 명도로 수렴한다.
**색 후보로는 못 고친다** — 켜 수를 줄이거나 골을 더 깊게 파는 **REF-3 형태의 일**이다.

그래서 REF-2C 는 **변경 없음**으로 닫는다. 이것이 이 회차의 결과다.

# REF-2.5-S1R — 기둥 재역설계 (2026-08-10 · 사용자 지적)

> 「현재 기둥은 아래가 `stone_brick_wall` 이라 몸통보다 확 가늘어져서, 전통 목조건축의
> 기둥이라기보다 **회색 금속 다리나 촛대 위에 붉은 기둥을 얹은 모습**으로 읽힙니다.」

## ★★합격 기준을 한 단계 올린다

```
① 색을 빼도 형태가 읽히는가          ← REF-2.5 는 통과했다
② 그 형태가 레퍼런스와 같은 방향인가  ← 기둥은 여기서 떨어졌다
```
**흑백에서 달라진다 ≠ 레퍼런스와 닮았다.** 앞 판의 담장 주초는 ①만 통과하고 ②에서 떨어졌다.
앞으로 조형 회차는 두 관문을 다 넘어야 한다.

레퍼런스(`화산파/…07_09_25 (4)` 근경)를 다시 보면 기둥은 **굵기가 그대로 내려와 석재 바닥에서
끝나고**, 머리 위는 밝은 석재 캡이 아니라 **어두운 목재 구조가 벌어지며 처마를 받는다.**

## 고친 것

| | 앞 판 | S1R |
|---|---|---|
| 주초 | `stone_brick_wall` — **몸통보다 가늘다** | `polished_andesite` — **같은 폭 · 낮다** |
| 몸통 | 통나무 5켜 (실은 4켜만 남았다) | 통나무 **5켜 온전** |
| 주두 | `cut_sandstone` 밝은 점 | **목재** `mangrove_stairs` — 공포의 첫 단이 곧 주두 |

★**공포가 적주 몸통을 먹고 있었다.** 그림자 골을 한 켜 비우느라 공포 아랫단이 적주 평면(+1)에
앉았고, 그 자리가 몸통의 맨 윗칸이었다 — 붉은 켜가 5가 아니라 **4**였다. 차례도 뒤집혀
`적주 → 공포 → 주두` 였다. 골을 0 으로 내려 `적주 → 주두 → 공포 → 도리` 로 바로잡았다.

★**골은 사라지지 않는다.** 아랫단만 적주 평면(+1)이고 위 단들은 처마 평면(+2)이라,
처마 평면의 그 아래 칸이 비어 그늘이 진다 — **켜로 비우는 대신 윤곽이 스스로 만든다.**

## 실측

```

몸통 적주 5켜 온전        8/8      주두 mangrove_stairs 8/8

## ★남은 것 — 공포 3단이 서까래와 자리를 다툰다

`elaborate` 는 3단인데 맨 윗단이 `y=처마−1` 로 가고, 그 켜는 **서까래**가 이미 쓰는 자리다.
지붕이 나중에 놓이므로 서까래가 이긴다 → **눈에 보이는 공포는 사실상 2단**이다.
처마가 2 라 세 단을 다 드러내려면 처마를 키우거나(REF-1 에서 실측으로 막힌 값) 서까래와
공포를 한 부재로 합쳐야 한다 — **REF-3 결정거리.**

## 눈도 틀린 조형을 지키고 있었다

앞 눈은 「담장 블록이 있는가」를 물었다. 그 담장이 바로 기둥을 촛대로 만든 범인이었으니,
**눈이 틀린 조형을 지키고 있었던 것**이다. 이제 묻는 것은 「주초가 몸통보다 가늘지 않은가」다.

# REF-3A — bay 역할별 형태 차이 (2026-08-10 · 사용자 확정)

**확대는 미룬다.** 사용자 판단: 「지금은 건물이 실제보다 작다기보다 **같은 형태의 반복이 많아서**
규모감이 충분히 표현되지 않는 부분도 크다.」 그래서 크기가 아니라 **반복**을 먼저 깬다.

★**랜덤이 아니라 자리가 깬다** — 기존 계율 「위치가 정하면 구조, 해시가 정하면 잡티」 그대로.

```
전   P W D P W D P W D P W D P J O O O J P D W P D W P D W P D W P
후   C W D P W D P W D P W D A J O O O J A D W P D W P D W P D W C
     └모서리                └입구 옆      입구 옆┘            모서리┘
```

| 역할 | 처방 | 왜 |
|---|---|---|
| **C** 모서리 | 주두 **두 켜** (`mangrove_stairs` + `dark_oak_slab`) | 머리가 굵어 **귀마루로 이어지는 끝**을 잡는다 |
| **A** 입구 옆 | **보조 인방** 한 켜 (`mangrove_planks`) | 중앙으로 갈수록 켜가 늘어 **중심을 예고**한다 |
| **P** 일반 | REF-2.5-S1R 기본형 | |
| 중앙 | 문설주 · 문두 · 현판 자리 · 관 | 이미 있다 (REF-1c-B) |

그래서 정면이 **강한 모서리 → 반복 → 강한 중앙 → 반복 → 강한 모서리** 로 읽힌다.

★셋 다 **켜 수는 11 로 같다** — 다르면 지붕이 기운다. 형태만 다르고 높이는 하나다.
★셋 다 몸통이 3켜 이상이라 **공포 계약이 그대로 걸린다.**

## ★★같은 병이 <b>세 번째</b>다 — 눈이 이름을 세고 있었다

`3칸 주기` 눈이 **글자 `P`** 를 세고 있었다. 역할을 나누자 기둥이 10 → 6 으로 줄어 보였다 —
조성은 멀쩡한데 눈이 글자를 센 것이다. 앞서 두 번과 같다:

```
① 공포 판정    「mangrove_log 를 포함하는가」  → 인방까지 적주로 셌다
② 문설주 판정  「mangrove_log 를 포함하는가」  → 팔레트가 바뀌자 0 을 셌다
③ 주기 판정    「글자가 P 인가」               → 역할을 나누자 6 을 셌다
```
**이름이 아니라 구조로 세라.** 세로로 이어진 통나무가 곧 적주다.

## 확대는 아직 안 한다 — 하게 되면 이렇게

패드 폭이 38 이라 층간 지붕 37 이 이미 한계다. **패드를 안 건드리면 본전은 더 못 커진다.**
REF-3 까지 하고도 원경에서 왜소하면 그때 **패드째** 넓힌다 (사용자 1차 목표):

```
하층 몸체 31 → 35~37    상층 25 → 29~31    층간 지붕 37 → 43~45
대지붕 33 → 39~41       기단 3단 유지 · 폭만 확대
정면 bay 9 <b>유지</b>  ← 11 로 늘리면 다시 촘촘해진다. 한 칸의 호흡을 넓힌다
패드 38×32 → 46~48 × 34~36   (장문인 정원·망루 재배치가 딸린 큰 회차)
```

## 순서 — 형태가 먼저, 리소스팩은 나중

```
Shape  →  Material  →  Texture
블록 모양으로 형태 · 블록 종류로 색/재질 · 리소스팩으로 미세 질감
```
★**리소스팩에 의존하면 안 된다.** 바닐라로 봐도 본전다워야 하고, 리소스팩은 그 위에
고급스러움을 더하는 것이어야 한다. 「팩을 껴야만 그럴듯한」 상태는 유지보수도 설계 기준도 흐린다.
