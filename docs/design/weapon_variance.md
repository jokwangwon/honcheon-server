# 병기 개체차와 강화 — 치우침(偏) · 품(品) · 이력(歷)

> "무기에 따라 당연히 공격력이 변화함. 같은 범철 무기여도 어떤 무기는 공속에 조금 더 치중되어
> 있다거나 등 무기에도 능력치가 붙어야 함. 대신 무기의 특성상 사거리는 계열이 정해진다"
> — 사용자 요구 (원문)
>
> "무기 강화 시스템도 존재하여야 한다는 말임" — 사용자 추가 요구

구현: `server-mvt/src/main/java/com/honcheon/mvt/Weapons.java`
정본: `config/equipment.yml`(등급·각인·애병) · `config/combat.yml`(위력) · `config/economy.yml`(값)

---

## 0. 병기의 다섯 축

이전까지 병기는 두 축이었다 — **계열**(공격력·공속·사거리)과 **등급**(감당 격·내구).
그래서 "범철 검"은 전부 똑같았다. 세 축을 더한다.

| 축 | 값 | 무엇을 정하는가 | 언제 정해지는가 |
|---|---|---|---|
| **계열(系)** | 검·도·창·권갑·단검·부·겸·월아산·구 | 공격력·공속의 골격, **사거리** | 고를 때 |
| **등급(級)** | 범철·정련·보병·신병·마병 | **감당 격 · 내구 · 각인 슬롯** | 재질이 판다 |
| **치우침(偏)** | 경·예·균·후·중 | 공격력 ↔ 공속 (**합 보존**) | 벼려질 때 · **불변** |
| **품(品)** | 조잡·보통·정품·명공 | 공격력·내구의 미세 보정 | 벼려질 때 · **재련으로 오른다** |
| **이력(歷)** | 격돌 수 · 애병 단계 | **주인 한정 판정 +1** | 함께 산 시간 · **살 수 없다** |

**사거리는 계열만이 정한다.** 치우침도 품도 재련도 사거리를 건드리지 않는다 (사용자 규정).

## 1. 치우침(偏) — 같은 계열 안의 변주

같은 범철 검이라도 **가벼운 검**과 **무거운 검**이 있다.

| 치우침 | 한자 | 부제 | 공격력 배율 | 공속 배율 |
|---|---|---|---|---|
| 경 | 輕 | 가볍다 | ×0.857 (`1.08⁻²`) | ×1.166 (`1.08⁺²`) |
| 예 | 銳 | 날렵하다 | ×0.926 (`1.08⁻¹`) | ×1.080 |
| 균 | 均 | *(부제 없음)* | ×1.000 | ×1.000 |
| 후 | 厚 | 묵직하다 | ×1.080 | ×0.926 |
| 중 | 重 | 무겁다 | ×1.166 (`1.08⁺²`) | ×0.857 |

### 합의 보존 — 상위 호환이 규칙적으로 불가능하다

공속 배율은 **공격력 배율의 정확한 역수**다 (`1.08ⁿ` × `1.08⁻ⁿ` = 1).
따라서 `공격력 × 공속`(= 초당 피해)이 치우침에 대해 **불변**이다.
한쪽으로 치우친 병기는 다른 쪽을 **정확히 그만큼** 잃는다.

**검산** (전 9계열 × 5치우침 × 4품 = 180조합 전수):
- 같은 품 안에서 어떤 치우침이 다른 치우침을 **공격력·공속 모두에서 이기는 조합: 0건**
  (출하된 코드를 헤드리스 실행해 검산)
- 같은 품 안 DPS 편차: **최대 0.59%** (소수 2자리 반올림 오차뿐)

### 설계 결정 두 가지 (검산이 강제한 것)

**① 배율은 표시 총합에 건다 — 위력에만 걸지 않는다.**
공격력 = `(맨주먹 1.0 + 계열 위력) × 치우침 × 품`.
위력에만 걸면 맨주먹 몫 1.0 이 배율 밖에 남아 **가벼운 병기가 공짜 DPS를 얻는다** —
그 형태에서 같은 품 안 DPS 편차가 **11.5%** 로 벌어졌다 (경이 일방적으로 이득).
총합에 걸어야 곱이 정확히 보존된다.

**② 표시는 소수 2자리다 — 1자리로 자르면 합 보존이 깨진다.**
부(斧)의 공속은 0.9 대역이라 0.1 의 반올림이 **11% 오차**다.
소수 1자리에서는 실제로 **예(銳) 부가 경(輕) 부를 공격력·공속 모두에서 이기는** 지배 조합이
**12건** 생겼다 (전부 부·월아산 — 공속 1.0 이하 계열). 2자리에서 **0건**이 된다.
→ 툴팁·attribute 모두 2자리로 굳힌다 (끝의 0 은 지운다: `5.00` → `5`, `1.60` → `1.6`).

### 무엇이 나은지는 상대가 정한다

- **중(重)** — 방어구 감쇄(`armor.mitigation`)는 **한 합마다** 깎는다. 한 방이 무거울수록 덜 손해다.
- **경(輕)** — 기(氣) 축적·경직 누적은 **타수**를 센다. 합이 잦을수록 이득이다.

### 치우침이 계열을 넘지 않는다

치우침 최대폭 ±17% (경↔중) < 계열 폭 33% (단검 4.0 / 검 5.0 / 부 6.0).
**무거운 단검이 표준 검이 되지 않는다** — 계열의 정체성이 유지된다.

## 2. 품(品) — 같은 등급 안의 만듦새

같은 범철이라도 **잘 벼린 것**과 **조잡한 것**이 있다.

| 품 | 한자 | 공격력 | 내구 | 각인 슬롯 소모 | 서사 |
|---|---|---|---|---|---|
| 조잡 | 粗製 | ×0.94 | ×0.80 | — | "급히 두들긴 쇠 — 날에 결이 남았다." |
| 보통 | 常 | ×1.00 | ×1.00 | — | "장인의 평범한 하루가 낳은 물건." |
| 정품 | 精品 | ×1.04 | ×1.15 | — | "잘 벼려진 날 — 손이 가볍다." |
| 명공 | 名工 | ×1.08 | ×1.30 | **1칸 (명공각인)** | "명공의 각인 — 이 쇠는 백 년을 간다." |

**품은 감당 격과 판정에 손대지 않는다.** 등급이 파는 것은 여전히 감당 격과 내구다.

### 명공은 각인이다 — 그래서 범철은 명공이 될 수 없다

`equipment.yml special_properties.명공각인` 이 **이미 등록돼 있다** (중복 정의 금지).
명공 품 = 그 각인을 보유한 상태이고, 각인은 `property_slots` 를 **한 칸 먹는다**.

그런데 `equipment.yml weapon_grades` 에서 **범철에는 `property_slots` 키가 없다** (= 0칸).

> **∴ 범철은 원리적으로 명공이 될 수 없다.**
> "명공 범철이 정련을 이긴다"가 밸런스 조정이 아니라 **규칙 차원에서 불가능**하다.
> 범철의 천장은 **정품(精品)** 이다.

이것이 이 설계의 주춧돌이다. 숫자를 깎아서 막은 것이 아니라, 등급표가 이미 그렇게 말하고 있었다.

### 등급 침범 검사 (내구 사다리)

| 아래 등급 최강 품 | 내구 | | 위 등급 최약 품 | 내구 | 판정 |
|---|---|---|---|---|---|
| 범철 **정품** (명공 불가) | 288 | < | 정련 **조잡** | 640 | OK |
| 정련 **명공** | 1040 | < | 보병 **조잡** | 1600 | OK |

**어떤 재련도 한 급 위의 가장 조잡한 것을 넘지 못한다.** 감당 격은 아예 건드리지도 않는다.

### 명공의 기회비용 — 상위 호환이 아니다

명공각인이 슬롯 한 칸을 먹으므로, **명공 정련(슬롯 1칸)은 파사를 새길 칸이 없다.**

> 마공 상대라면 **정품 + 파사(위력 +2)** 가 **명공(공격력 +4%)** 보다 낫다.

품은 스탯 축에서 단조 증가하지만(그것이 "만듦새"의 정의다), **슬롯 경제**와 **가격**
(조잡 ×0.6 / 정품 ×1.8 / 명공 ×5.0)에서 값을 치른다.

## 3. 결정론 vs 굴림 — 병기는 고르는 것이다

| 출처 | 치우침·품 | 근거 |
|---|---|---|
| **상점 진열** | **진열 시점에 씨앗으로 고정** (`makeSeeded`) | 무협의 감각은 **"진열대에서 병기를 고른다"**. 사는 순간 굴리면 고르는 행위가 사라지고, **진열된 검과 산 검이 달라진다** — 세계가 거짓말을 한다. 씨앗 = 날짜 × 진열칸 → 좌판은 하루 동안 같은 병기를 걸어두고 다음 날 새 물건이 들어온다. |
| **관리자 지급** (`/혼천 병기`) | 명시 지정 (기본 균·보통) | 검증 수단은 결정론이어야 한다 |
| **전리품·기연** | 굴린다 (`makeRolled`) | 주인이 쓰던 검이다 — 제식일 이유가 없다 |
| **마병** | **없다** (균·보통 고정) | 사람이 벼린 것이 아니다. 혈교의 의식이 응결시킨 **등록제 유일물** |

굴림 분포는 종 모양이다 (극단은 드물다): 경 1 / 예 3 / **균 4** / 후 3 / 중 1.
품은 등급이 높을수록 좋다 — 신병을 조잡하게 벼리는 대장장이는 없다.

### PDC 영속 — 한 번 벼려진 값은 영구히 따라다닌다

| 키 | 형 | 내용 |
|---|---|---|
| `honcheon:weapon_bias` | STRING | 치우침 (불변) |
| `honcheon:weapon_craft` | STRING | 품 (재련으로 오른다) |
| `honcheon:weapon_properties` | STRING | 각인 목록 (쉼표 구분) |
| `honcheon:weapon_power_effective` | DOUBLE | 실효 위력 — 판정층이 재계산 없이 읽는 창구 |
| `honcheon:weapon_reforge_count` | INTEGER | 재련 성공 횟수 |
| `honcheon:weapon_owner` | STRING | 주인 UUID |
| `honcheon:weapon_clash_count` | INTEGER | 생사 격돌 횟수 |
| `honcheon:weapon_beloved_stage` | STRING | 애병 단계 |
| `honcheon:weapon_bond_days` | INTEGER | 동행 일수 (**예약** — 게임 내 날짜 축 대기) |
| `honcheon:weapon_bias_shift` | STRING | 통령의 치우침 이동 (**예약**) |

제작은 **순함수**다: `make(계열, 등급, 치우침, 품, 각인)` — 같은 입력이면 같은 아이템이 나온다.
태그가 없는 구(舊) 병기는 균·보통으로 읽는다 (하위 호환).

## 4. 강화(強化) — 병기가 좋아지는 세 갈래

무협에서 병기가 좋아지는 길은 셋이고, 셋의 격이 다르다.

### ① 재련(再鍊) — 명공의 손을 빌린다 · **구현**

야철수(治鐵手)에게 맡긴다. **품이 한 단계 오른다.**

| 목표 품 | 난도 (2d6 + 야철수 솜씨) | 삯 (범철 기준) | 비고 |
|---|---|---|---|
| 조잡 → **보통** | **굴리지 않는다** | 20문 | 벼리기가 아니라 **손질**이다 |
| 보통 → **정품** | ≥ 8 | 150문 | 표준 야철수(+2)면 72% |
| 정품 → **명공** | ≥ 12 | 1200문 | 야철수(+2)로는 2d6 = 10+ 필요 (17%) |

삯 배율: 범철 ×1 / 정련 ×3 / 보병 ×10 / 신병·마병 ×30.

**첫 단계는 안전하다** — 초보가 첫 검을 잃으면 게임을 그만둔다.
그 위부터는 도박이다:
- **실패**: 날에 금이 간다 (최대 내구의 30% 손상). 품은 그대로 — 다시 시도할 수 있다.
- **대실패 (2d6 = 2, 뱀눈)**: 쇠가 갈라진다. **병기가 사라진다.**

**천장**: `Craft.ceiling(등급)` — 슬롯 없는 범철은 **정품에서 멈춘다**.
**치우침은 재련으로 바뀌지 않는다** — 쇠를 다시 벼려도 그 검의 성격은 그대로다.
무게 배분은 만들 때 정해지는 것이지 손질로 옮겨지는 것이 아니다.

**닳은 만큼은 따라간다** — 재련해도 새것이 되지 않는다 (최대 내구만 오른다).

### ② 각인(刻印) — 속성을 새긴다 · **구현**

`equipment.yml special_properties` 에 **등록된 것만** (파사·한철·경명·음양쌍인·탈혼),
등급의 **슬롯 안에서만** (정련 1 / 보병 1 / 신병 2 / **범철 0**).

- **범철에는 아무것도 새길 수 없다** (슬롯 0) — 각인은 정련부터의 사치다.
- **명공각인은 새기는 것이 아니라 벼려지는 것**이다 — `inscribe` 가 거부한다. 재련으로 명공에 이르러라.
- 명공 병기는 이미 한 칸을 쓰고 있다 — 그것이 명공의 값이다.

### ③ 애병(愛兵) — 시간과 피가 벼린다 · **1단계 구현 / 2·3단계 예약**

> **강화의 최고봉은 사는 것이 아니라 함께 산 시간이다.**

`equipment.yml beloved_weapon` 이 이미 3단계를 정의한다. 이력 축을 PDC 카운터로 세운다.

| 단계 | 요구 | 효과 | 상태 |
|---|---|---|---|
| **손에_익다** | 동행 1년+ **또는 격돌 30회** | **주인 한정 판정 +1** | **구현** (격돌 카운터) |
| 명병 | 생사 고비 3회 + 명성 사건 1회 | 명명 · 소문 주체 · 파괴 유예 | **예약** (사건 축 없음) |
| 통령 | 동행 10년+ · 주인 화경 | 감당 격 +1 · 이기어검 궁합 | **예약** (년수·경지 축 없음) |

**세는 것**: `beloved_weapon.history_inputs.생사_격돌_생존` — 죽고 살 만한 싸움을 **살아서** 끝낸 횟수.
MVT엔 게임 내 년수 축이 없으므로 **격돌 30회**만 센다.

**세는 법** (`Weapons.recordClash(item, uuid)`):
- 주인은 **처음 격돌을 함께한 손**이 된다 (첫 격돌에 UUID가 새겨진다).
- **다른 손에서는 카운터가 늘지 않고 보정도 나오지 않는다**
  (`beloved_weapon.principle`: "강탈한 남의 애병은 등급값" — 약탈 메타 차단).
- **호출자가 게이트한다**: 잡몹 학살로 채워지면 애병이 값싸진다.
  권장 = 적대 인간형 처치 또는 **자신이 피를 흘린** 전투의 종료 시 1회. 몬스터 방목 사냥은 세지 않는다.

**툴팁이 자란다** — 검을 쓸수록 이력 줄이 늘어난다:
`생사 격돌 17회 (손에 익기까지 13회)` → `애병(愛兵) · 손에 익다 — 주인의 손에서만 판정 +1`

### 무기가 파는 유일한 판정 보정은 이력이다

`combat.yml` 이 2026-07 전투 정합 패스에서 **등급 `judgment_bonus` 를 전부 0 으로** 내렸다
("병: 보병 한 자루가 강기보다 강했다"). 그 자리를 이력이 가진다:

> 품도 강화도 판정을 주지 않는다. **+1 은 오직 애병이, 그것도 주인의 손에서만 준다.**
> 검의 값은 등급이 아니라 함께한 세월이다.

## 5. 애병 × 개체차 — 직교한다 (판단과 근거)

**질문**: 애병이 되면 치우침이 주인에게 맞춰 움직이는가? 아니면 별개 축인가?

**판단: 직교한다. 애병은 치우침을 바꾸지 않는다.**

**근거**:
- 치우침·품은 **"이 쇠가 무엇인가"** — 제작 시 확정, 불변. 물성(物性)이다.
- 애병은 **"이 쇠와 사람이 서로를 얼마나 아는가"** — 이력. 관계다.
- 검이 사람에게 맞춰 **모양을 바꾸는 것은 강호의 물리가 아니다.** 바뀌는 것은 **사람의 손**이다.
  그래서 애병의 보정은 전부 **주인 한정**이다 — 강탈하면 따라오지 않는다.
  (치우침이 주인에게 맞춰 움직인다면, 그 이득은 검에 붙으므로 **강탈해도 따라온다** — 약탈 메타가 열린다.)

**단 하나의 예외를 통령(通靈)에 예약한다** (`honcheon:weapon_bias_shift`):
십 년을 함께하고 주인이 화경에 이르면, 검이 주인 쪽으로 **치우침 한 칸** 움직인다
(주인의 무공이 속(速) 지향이면 경 쪽으로, 력(力) 지향이면 중 쪽으로).
**합 보존은 그대로**이므로 이것은 **상향이 아니라 적합(適合)** 이다 — 검이 세지는 것이 아니라 맞아지는 것이다.
그 격을 통령에만 준 이유: 강철의 성격을 바꿀 자격은 십 년과 화경뿐이다.

MVT엔 년수·경지 축이 없으므로 **자리만 예약**한다 (PDC 키 · 미구현).

## 6. 툴팁 ↔ attribute 무결성

**표시값을 먼저 굳히고, 그 굳은 값에서 modifier 를 역산한다.**

```java
attackDamage = round2((1.0 + 계열위력) × 치우침 × 품)   // 표시값
ATTACK_DAMAGE modifier = attackDamage − 1.0             // 역산
```

반올림을 표시 쪽에서만 하면 툴팁이 거짓말을 한다 (표시 4.3 · 실제 4.2857…).
역산하면 **툴팁의 숫자가 곧 attribute** 다.

```
정련(精鍊) 검 — 가볍다(輕)
─────────────
공격력 4.29 · 공속 1.87 (초당 1.87회)
사거리 3.0m (검 계열 고정)
감당 격: 검기까지 · 내구 920
품(品): 정품(精品) · 재련 1회
─────────────
생사 격돌 17회 (손에 익기까지 13회)
─────────────
명공의 손을 거친 병기. 검기를 받아낸다.
곧은 양날 — 중용의 병기. 빠르지도 느리지도 않다.
"잘 벼려진 날 — 손이 가볍다."
검기까지 견딘다 — 강기 앞에서는 3합이 한계다.
```

**색맹 대응 유지**: 등급·치우침·품 모두 **색 + 글자 + 한자**로 세 번 말한다 (`colorblind_rule`).
품 색은 등급 색과 겹치지 않게 골랐다 (조잡 DARK_GRAY / 보통 GRAY / 정품 GREEN / 명공 LIGHT_PURPLE).

## 8. 남은 한계

- **판정층 미배선** — `SkillEngine` 은 여전히 `weapon_class`(계열 표준 위력)로 판정한다.
  치우침·품은 **바닐라 기본 공격(attribute)** 에만 실효한다.
  창구는 열어 뒀다: `honcheon:weapon_power_effective` (DOUBLE) · `Weapons.effectivePowerOf(item)`.
  `SkillEngine`·`SkillListener` 는 다른 에이전트 소유라 손대지 않았다.
- **애병 판정 +1 미배선** — `Weapons.belovedJudgmentBonus(item, uuid)` 는 있으나
  `SkillEngine` 의 판정 합산에 더해지지 않았다 (같은 소유 문제).
- **격돌 카운터 미배선** — `recordClash` 를 부르는 곳이 없다.
  `SkillListener`(전투 종료 훅) 소유가 달라 `/혼천 격돌` 검증 명령만 제안한다.
- **재련 NPC 미구현** — 야철수 상호작용 GUI 없음. `/혼천 재련` 명령이 먼저다 (검증 수단).
- **재련 재료 미구현** — 삯(문)만 있고 재료(철·영철·한철)는 없다. `economy.yml` 등록 후.
- **동행 일수·명병·통령** — 게임 내 날짜·사건·경지 축이 MVT에 없다. PDC 키만 예약.
- **상점 개체 고정 미배선** — `makeSeeded` 는 있으나 `WeaponShop` 이 아직 `make`(균·보통)를 쓴다.
  `WeaponShop` 소유가 달라 diff 만 제안한다.
- **팩 게이트 — 해소됨** (같은 사이클, 팩 담당이 처리). 커밋 `1a415a6` 이 18반 병기 4계열 텍스처를
  굽고 `Series.modelId` 를 `"bu"`·`"gyeom"`·`"wolasan"`·`"gu"` 로 점등했다.
  이제 9계열 전부가 팩 모델을 갖는다 — 개체차·강화가 전 계열에 실효한다.
