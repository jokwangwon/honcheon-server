# 몹 형체 — 바닐라 몸을 감추고 커스텀 3D 를 태운다

> 등록부: `config/mob_models.yml` · 엔진: `server-mvt/.../MobDisplay.java` · 검산: `tools/mob_model_audit.py`
> 스폰 훅: `HuntingGrounds.spawn()` · 관련: [mob_spawning.md](mob_spawning.md) · [skill_motion.md](skill_motion.md)

## 1. 문제 — 호랑이는 라바저다

우리 적은 **바닐라 몸을 빌려 쓴다** (`HuntingGrounds.DEFAULT_ENTITY`).

| 적 | 징발한 몸 | 왜 그 몸인가 | 눈에 보이는 것 |
|---|---|---|---|
| 호랑이 | `RAVAGER` | 큰 몸집·적대·근접 AI·돌진을 다 갖춘 유일한 네발짐승 | **약탈수(뿔 달린 회색 소)** |
| 반달곰 | `POLAR_BEAR` | 근접 AI·덩치 | 북극곰(흰 곰) |
| 멧돼지 | `HOGLIN` | 돌진하는 멧돼지형 적대 몹 | 네더의 털복숭이 |
| 백영묘 | `CAT` | 영물은 고양이여야 한다 | 집고양이 |
| 산늑대 | `WOLF` | 무리·타이가 | 늑대 (맞다) |
| 산적·무인 | `ZOMBIE` | 인간형 + 손에 든 병기가 보인다 | 좀비 (텍스처로 고친다) |

**리소스팩은 텍스처를 바꿀 뿐 지오메트리를 못 바꾼다.** 바닐라 클라이언트에서 몹 모델은 팩으로
교체되지 않는다. 그래서 호피 무늬를 입힌 라바저가 북산의 주인 행세를 했다.

## 2. 답 — 본체를 감추고 그 위에 형체를 태운다

바닐라 클라이언트에서 되는 유일한 길이다.

* **본체는 그대로 둔다** — AI·판정·물리·경로탐색·히트박스가 전부 거기서 돈다.
  형체를 바꾼다고 그 몸을 고른 이유가 사라지지 않는다.
* 본체를 **투명하게** 한다 (`setInvisible(true)`). **명패는 남는다** — 투명한 몸도 이름표는 뜬다.
* 그 위에 **`ItemDisplay`** 를 태워 팩이 구운 커스텀 3D 모델을 실는다 (`item_model` 컴포넌트).

### 불변식 셋

| | |
|---|---|
| **ㄱ. 형체는 덧칠이다** | 이 층의 모든 실패(팩 없음·예산 초과·미등록·볼 눈 없음)는 **본체가 그대로 보이는 것**으로 끝난다. 라바저로 보일지언정 사냥은 된다. `require-resource-pack=false` 는 이 층에도 불가침이다 — 3D 는 특권이 아니라 사치다 (skill_motion 불변식 ㅁ 과 같은 문법). |
| **ㄴ. 판정은 본체다** | Display 는 히트박스가 없다(때릴 수 없는 몸이다). 때리는 것도 맞는 것도 언제나 본체다. 형체가 한 틱 어긋나도 판정은 불변이다. |
| **ㄷ. 형체 교체는 실루엣이 틀린 몸에만 건다** | §3. |

## 3. 갈아탈 몸과 그대로 둘 몸

`ItemDisplay` 는 **골격 애니메이션이 없다** — 뻣뻣한 조각이다. 다리가 걷지 않고 입이 벌어지지
않는다. 우리는 그것을 흔들림·기울기·쓰러짐으로 흉내 낼 뿐이다(§5). 그러므로 형체 교체는 공짜가
아니라 **거래**다: **실루엣을 얻고 골격 애니메이션을 잃는다.**

### replace — 실루엣이 틀린 몸 (4종)

| 적 | 본체 | 근거 |
|---|---|---|
| 호랑이 | RAVAGER | 라바저다. 팩으로는 못 고친다. **이 문서가 태어난 이유** |
| 반달곰 | POLAR_BEAR | 북극곰(흰·길쭉)과 반달가슴곰(검고 둥글고 작다)은 실루엣이 다르다. 팩은 색만 바꾼다 |
| 멧돼지 | HOGLIN | 실루엣은 가깝지만 비율이 다르다 (털·위로 굽은 엄니·어깨혹 없음) |
| 백영묘 | CAT | 영물의 위엄이 집고양이 몸으로는 안 나온다. 흰 표범급(1.5m) |

### vanilla — 그대로 둘 몸 (4종, **등록된 예외**)

| 적 | 본체 | 근거 |
|---|---|---|
| 산늑대 | WOLF | **이미 늑대다.** 게다가 무리 짐승(밤 정원 6). 6마리를 조각으로 바꾸면 골격 애니메이션을 여섯 번 잃는다 — 얻는 것보다 잃는 것이 크다. 팩 텍스처로 족하다 |
| 산적·갈호·곽진 | ZOMBIE | **사람은 조각이 될 수 없다.** ZOMBIE 를 고른 이유가 인간형 골격과 **병기를 휘두르는 팔**이다 (`arm()` — 진짜 범철 도를 들려 스폰한다). 조각으로 바꾸면 산적은 칼을 든 채 미끄러지는 인형이 된다 |

근거 없는 `vanilla` 는 형체가 아니라 **방치**다 — `mob_model_audit` ①이 `reason` 없는 예외를 위반으로 잡는다.
산늑대는 `reserved_model` 을 잡아 두었다: 팩 담당이 구우면 `shape: replace` **한 줄**로 켜진다 (코드 수정 없음).

## 4. 탑승(addPassenger)이 아니라 추종(follow)이다

| | 탑승 | **추종 (채택)** |
|---|---|---|
| 위치 | 공짜 (클라이언트가 탈것에서 보간) | teleport + `setTeleportDuration` |
| 오프셋 | **탈것 종류마다 다르고 API 로 질의할 수 없다** | 등록부의 `offset` 이 그대로 진실 |
| 회전 | 승객은 탈것의 yaw 를 **안 물려받는다** — 결국 매 틱 갱신 | 매 틱 갱신 (같다) |
| 죽음 | 탈것이 죽으면 승객은 **즉시 하차·낙하** | 형체가 남아 **옆으로 넘어진다** |

**근거 넷:**

1. **탑승 오프셋은 질의할 수 없다.** 승객이 앉는 높이는 탈것마다 다르다 (RAVAGER 등 위 ~2.1m ·
   WOLF ~0.9m) — Bukkit API 로 물어볼 방법이 없다. 등록부의 `offset` 이 진실이려면 그 매직 넘버를
   코드에 박아야 한다. **등록제 규약 위반이다.**
2. **회전은 어차피 매 틱 갱신해야 한다.** "탑승은 공짜"의 절반은 거짓이다.
3. **죽을 때 쓰러져야 한다.** 호랑이가 죽으면 옆으로 넘어져야지, 승객이 하차하듯 툭 떨어지면 안 된다.
4. **값이 싸다.** 형체 64개 상한 × (거리 비교 + 벡터 3 + teleport 1) ≈ **0.1ms 미만.**

부드러움은 `setTeleportDuration`(이동 보간, 2틱)과 `setInterpolationDuration`(형체 보간, 3틱)이 낸다.
**이 둘이 0이면 형체가 튄다.**

## 5. 움직임의 표정 — 조각이 살아 있는 척하는 법

| 표정 | 배선 | 원리 |
|---|---|---|
| **걷기** | `walk_bob` · `walk_roll_deg` | 상하 흔들림 + 좌우 기울기. **위상은 시간이 아니라 이동거리로 돈다** — 멈추면 흔들림도 멈춘다. 그것이 걷기다 |
| **꼬리** | `sway_deg` | 걷기 위상에 맞춰 흔들린다. 흰 그림자는 **꼬리가 흔들리는 것**으로 먼저 읽힌다 |
| **머리** | `head_yaw_max` · `head_pitch_max` | 몸이 안 돌아도 **고개가 먼저 표적을 본다** (`Mob.getTarget()`). 호랑이 55° · 곰 40°(뻣뻣하다) |
| **공격** | `attack_lean_deg` · `attack_lean_ticks` | `EntityDamageByEntityEvent` — 칠 때 앞으로 기운다 |
| **돌진** | `charge_lean_deg` · `charge_speed_full` | 속도에 비례해 더 기운다. 멧돼지가 가장 크게 (22°) |
| **사망** | `death_topple_deg` · `death_sink` · `death_ticks` | `EntityDeathEvent` — 몸은 사라지고 **형체만 남아 옆으로 넘어지며 가라앉는다** |

**파츠 분할.** 나누면 살아나지만 엔티티 수가 곱절이 된다. 그래서 **머리·꼬리가 값을 하는 곳에만** 나눴다:

* 호랑이 3 (몸통·머리·꼬리) — 북산의 주인이다. 고개가 돌고 꼬리가 흔들린다
* 반달곰 2 (몸통·머리) — 꼬리가 없는 짐승이다
* 백영묘 2 (몸통·꼬리) — **긴 꼬리가 이 짐승의 전부다**
* 멧돼지 1 — 머리·어깨·몸통이 **한 덩어리**다(쐐기꼴). 나눌 이유가 없다. 통째로 기울어 돌진한다

**몸통의 자세는 모든 파츠가 함께 탄다.** 오프셋까지 함께 회전시킨다 — 그러지 않으면 몸통만 숙이고
머리가 허공에 남는다 (`MobDisplay.apply()`).

## 6. 팩 게이트 — 지는 쪽은 3D 다

### 기술적 사실 (이 절의 존재 이유)

* Display 의 가시성은 **플레이어별로 갈 수 있다** (`setVisibleByDefault(false)` + `showEntity`).
* 본체의 투명(`setInvisible`)은 **엔티티 단위 플래그**다. **플레이어별로 갈 수 없다.**
* 본체를 `hideEntity` 로 플레이어별로 숨기면 — **그 플레이어는 그 몸을 때릴 수 없다.**
  클라이언트에 레이캐스트할 대상이 없기 때문이다. **판정이 무너진다.** 그러므로 쓰지 않는다.

⇒ 팩 있는 눈과 없는 눈이 **한 자리에 섞이면 한쪽은 진다.** 피할 수 없다.

### 판단: 지는 쪽은 3D 다

1. **불가침 규약** — "팩이 없어도 플레이는 가능해야 한다". 본체를 감추면 팩 없는 눈에는 **명패만 뜬
   허공**이 다가온다. 그것은 '가능한 플레이'가 아니다.
2. **선례** — `skill_motion.yml` 불변식 ㅁ: "3D 는 특권이 아니라 사치다". 같은 문법을 지킨다.
3. **비대칭** — 3D 를 잃은 팩 수락자는 **여전히 잘 논다**(라바저를 본다). 본체를 잃은 미수락자는
   **못 논다**. 손해의 크기가 다르다.

### 세 답 (`MobDisplay.verdict`)

| 답 | 조건 | 결과 |
|---|---|---|
| **TEAR** | 관중 중 **하나라도** 팩이 없다 | 형체를 거두고 본체를 되돌린다. 모두가 라바저를 본다 — 덜 아름답지만 **모두가 논다** |
| **BUILD** | 관중이 있고 **전원**이 팩을 받았다 | 본체를 감추고 형체를 씌운다 |
| **HOLD** | 셀 눈이 없다 (아무도 안 보거나 전원 유예 중) | 새로 짓지 않고, 있는 것은 둔다 — 팩 내려받는 사람이 지날 때마다 깜빡이지 않게 |

`grace_ticks`(10초) — 접속 후 팩 상태를 아직 보고하지 않은 눈은 **관중에서 뺀다**. 그가 답하면
그때 센다. 이것이 없으면 접속자가 지날 때마다 형체가 무너졌다 다시 선다.

**모드** (`pack_gate.mode`): `adaptive`(기본) · `forced`(팩 강제 서버 — 불가침 규약과 충돌하므로 기본이 아니다) ·
`off`(형체 층 전면 정지 — 사고 시 되돌릴 손잡이).

> **지금 서버는 팩을 배포하지 않는다** (`server.properties resource-pack=` 빈 값) ⇒ 전원이 미수락
> ⇒ **형체 0개 · 비용 0 · 위험 0.** 팩이 배포되는 날 저절로 켜진다.

## 7. 성능 예산

`performance.yml tick_budget.npc_logic` 6ms 중 이 층의 몫은 **1ms**. `vfx_entities`(무공 획, 120개)와는
**다른 풀**이다 — 형체는 일회성 연출이 아니라 몸에 붙어 사는 것이다.

### 사냥터에 몹 20마리면 디스플레이가 몇 개인가

북쪽 산길 정원 (`HuntingGrounds.POPULATIONS` · `ZONE_ENTITY_CAP` 18):

| | 몸 | 형체 | 내역 |
|---|---|---|---|
| **낮** | 11마리 | **3개** | 멧돼지 3×1 · (산늑대 4 · 산적 3 · 갈호 1 = vanilla, 0개) |
| **밤** | 15마리 | **7개** | 호랑이 1×3 · 반달곰 1×2 · 멧돼지 2×1 · (나머지 vanilla) |
| 최악 (구역 상한 18마리가 전부 호랑이) | 18 | 54개 | ≤ `global_cap` 64 |
| 부하 시험 군집 20마리 전부 호랑이 | 20 | 60개 | ≤ `global_cap` 64 |

**형체 교체가 vanilla 예외를 남긴 덕에 정상 상태는 3~7개다.** 산늑대 6마리를 조각으로 바꿨다면
밤에만 19개였다.

* `global_cap` **64** · `degrade_at` **48** — 넘으면 **새 형체를 붙이지 않는다.** 그 몸은 라바저로 보인다.
  **강등의 종착지가 '보이지 않는 몹'이 아니라 '바닐라 몹'이다** (불변식 ㄱ).
* `view_range` **0.75 × 64 = 48m** — 무공 획(파티클 `cull_beyond` 32m)보다 **멀다**.
  호랑이는 40m 밖에서 **발견되어야** 한다 — 그것이 사냥이다. 본체 `FOLLOW_RANGE`(32)와
  `SPAWN_MAX_DIST`(64) 사이의 눈금이 48m. 백영묘만 1.0(64m) — 흰 그림자는 산등성이 너머에서 먼저 보인다.
* **중앙 티커 1개** (1틱 주기, `performance.yml` F-P2 — 개체별 태스크 생성 금지).
* `attach_scan` (1초, 플레이어 곁 48m) — 청크 재적재·서버 재기동으로 태어난 몸을 줍는다.
  형체는 저장되지 않고(`setPersistent(false)`) 몸만 저장되기 때문이다.

## 8. 유령 청소 — 보이지 않는 호랑이는 버그가 아니라 재앙이다

우리 짐승은 `setPersistent(true)` 다. 크래시로 형체만 사라지면 **보이지 않는 호랑이**가 산길에 남는다.
세 겹으로 막는다:

1. `setPersistent(false)` — 형체는 저장되지 않는다 (첫 방벽).
2. `MobDisplay.start()` — 기동 시 `KEY_RIG` 를 단 Display 를 전부 지우고, **태그 몸의 투명을 전부 되돌린다**.
3. `scan()` — 형체 없이 투명한 몸을 발견하면 **그 자리에서 되돌린다** (자가 치유).
4. `clearAll()` — 정지 시 형체를 걷고 본체를 되돌린다.

## 9. 팩 담당에게 넘기는 계약

```
python3 tools/mob_model_audit.py --pack-list
```

* **키** — `honcheon:mob/<적>/<파츠>` (예: `honcheon:mob/horangi/head`).
  팩은 두 장을 굽는다: `assets/honcheon/items/<경로>.json` · `assets/honcheon/models/<경로>.json`
  (병기·무공 획과 같은 문법).
* **치수 계약** — 모델은 **1×1×1 블록 정육면체**(아이템 모델 표준 16px 그리드)에 맞춰 굽는다.
  엔진이 등록부의 `size` 를 `Transformation.scale` 로 그대로 곱한다 ⇒ **`size` = 실제 미터 치수.**
* **방향 계약** — 코가 **+Z(남쪽)**, 등이 +Y, 오른쪽이 +X. Display 의 yaw 0 이 +Z 다.
  **이 계약이 깨지면 짐승이 옆으로 걷는다.**
* **원점 계약** — 모델 원점은 **네 발이 딛는 바닥의 정중앙**. 엔진은 본체의 발 위치에 형체를 세운다.
* **조명** — `setBrightness` 를 걸지 않는다. 짐승은 스스로 빛나지 않는다(세계의 빛을 받는다).
  예외: 백영묘 — 본체의 발광(검기 두름)을 **형체로 옮긴다**(`body_glow_to_display`).
  【함정】 투명한 몸에 `setGlowing` 을 걸면 **바닐라 모델의 윤곽선이 그대로 빛난다** — 고양이 실루엣이
  허공에 뜬다.
