# 팩 아트 디렉션 — 「묵청(墨靑) 무협」

> 기계 판독용 값(색·문턱·채널)은 `config/resourcepack_design.yml` 에 등록한다.
> **이 문서는 이유를 적고, config 는 값을 적는다.** 코드는 config 로만 팩과 만난다 (등록제).
> 검산: `tools/texture_audit.py` (축 ⑫ 색 · **축 ⑬ 그림** · **축 ⑭ 문파 변별**)

---

## 0. 한 줄

**묵풍(墨風)이 세계의 기반이고, 청량(淸涼)은 희귀함과 신비의 강조다.**
경쟁하는 두 색이 아니라 **역할이 다른 두 층**이다.

> *"오래된 수묵화 속 정통 무림 세계를 걷고 있지만, 높은 산과 깊은 비경에 들어가면
> 청록색 옥빛과 맑은 운무가 나타나는 세계."* — 사용자

### ★ 이것은 우리가 이미 도착한 곳이다

앞 증분이 **청록산수(靑綠山水)** 로 같은 구조를 세웠다: *"먹은 선과 자재를 다스리고, 자연은 선명하게 남는다."*
그리고 `texture_audit` 축 ⑫가 그것을 **두 모집단**으로 이미 재고 있다:

| 계약 | 값 | 실측 |
|---|---|---|
| 자연(물·풀·잎) 평균 채도 | ≥ 46 | **56.7** |
| 자재(목재·돌·땅·회벽) 평균 채도 | ≤ 25 | **23.1** |
| 두 모집단의 격차 | ≥ 25 | **33.5** |
| 자재 평균 밝기 | [128, 172] | **128** |

**이 계약이 곧 「묵청」의 기계적 표현이다.** 새로 짓는 것이 아니라 그 위에 짓는다.

## 2. 가져온 것 — 프롬프트에서 **살아 있는** 부분

**문파 차별화 4순위** (그대로 채택, 그리고 **축 ⑭가 이것을 잰다**):

1. **실루엣** — *"흑백으로 보더라도 문파가 구분되어야 한다"*
2. **재질** — 금속의 밝기·마모
3. **문양** — 단순화. **아이템 전체를 덮지 말고 시선이 모이는 한두 곳에만** (코등이·물미)
4. **포인트 색** — **색은 보조다.** *"색만 바꾸고 같은 모델을 재사용하는 방식은 피하라"*

**등급이 올라도 실루엣과 정체성은 유지된다** — 전설검이 거대 수정검이 되지 않는다.
우리 등급 체계(범철→정련→보병→신병→마병)는 이미 **자루 고리 0~3 + 수실 + 마병 톱니**로 그렇게 하고 있다.

**금지 목록** (그대로 유효): 서양 판타지 · 네온/SF · 과채도 애니풍 · 붉은색·금색 과용 · 황궁 스타일 ·
복잡한 문양 남발 · GUI 장식이 슬롯·글자를 가리는 것 · **화풍과 명암이 불균일한 것** · 모든 요소에 구름·대나무 반복.

### 검증 (축 ⑭ — 흑백으로 보아도 갈리는가)

색을 빼고 **회색조 변별 픽셀 수**를 잰다 (실루엣이 다르거나 휘도 16 이상 차이).

- 최소 **27px** (hwasan ↔ namgung) · 중앙 94px · 최대 169px — **하한 16px 통과**
- 첫 시안은 화산의 매화가 코등이 안에 숨어 **15px** 였다 (= 색을 빼면 남궁과 같은 검).
  **축 ⑭가 그것을 잡았다.** 매화를 코등이 **밖으로** 피워 27px 로 올렸다.

> **왜 자카드가 아니라 회색조 변별인가**: 처음엔 축 ⑨(계열 실루엣 자카드 ≤ 0.65)를 그대로 베꼈다가
> 아홉 쌍이 걸렸다. 그런데 그 잣대를 통과하려면 **검이 검처럼 생기기를 그만두어야 한다** —
> 화산·남궁·점창·종남·무당은 등록부상 **전부 검(劍)** 이다. 축 ⑨는 *도와 비수를 가르는* 자이지
> *같은 계열 안*을 가르는 자가 아니다. 프롬프트가 요구한 것은 **"구분된다"** 이지
> **"윤곽이 다르다"** 가 아니고, 흑백에서 구분을 만드는 것은 윤곽만이 아니라 **명암(문양)** 이기도 하다.

## 6. 그림의 문법 — 「획과 여백」 (축 ⑬)

**색을 고쳐도 그림이 바닐라면 눈은 마인크래프트를 본다.** 이것이 이 증분의 발견이다.

| 지표 | 바닐라 | 이전(우리) | 지금 |
|---|---|---|---|
| σ (소리 크기) | 18.2 | 13.2 | **13.2** ↓ |
| 여백비 | 41% | 35% | **51%** |
| 획 응집도 (난수=1.00) | 1.13 | 1.13 | **1.44** |

- **① 선(線)이 그린다** — 디테일은 **이어진 획**이 나른다 (`level_set` 등고선이 곡선을 보증한다)
- **② 여백(餘白)이 받친다** — 화면의 대부분은 쉬는 면. 획은 적고 **의도적**이다
- **③ 농담(濃淡)이 깊이를 준다** — 계조는 부드럽고 방향이 있다 (난수가 아니다)
- **④ 종이의 결** — 완전한 평면은 종이가 아니라 플라스틱이다. **인지 문턱 아래**(±1.5루마)의 잔결을 깐다

### ★ 법칙 — 「면을 그리는 램프는 단당 루마 ≤ 4」

획의 문턱은 **8루마**다. 그런데 9~11단 램프의 **한 단이 9~11루마**였다
⇒ `step()` 의 **반올림이 단 하나만 건너뛰어도 그것이 '획'으로 세어진다.** **양자화기가 잡티를 제조했다.**
종이결(±1.5루마)조차 ±7루마의 단 넘김으로 증폭됐다.

⇒ 이제 명암을 **단이 아니라 루마로 적는다** (`ink_ramp()`). "줄눈을 -20루마"라 쓰면 팔레트가
무엇이든 그것은 20루마다 — **램프가 굵어서 획이 제멋대로 굵어지는 일이 구조적으로 불가능해진다.**

### ★★ 축 ⑬-d 세포면(細胞面) — **응집도가 구조적으로 못 재는 면이 있다**

**막돌(cobblestone)은 응집도를 영원히 통과할 수 없다.** 기하가 금지한다:
16px 장에 돌이 N개면 줄눈의 총 길이는 `L ≈ 2√(N·256)` (N=16 ⇒ **128px**).
응집도가 요구하는 **2px 두께**를 주면 줄눈만으로 **장의 100%** 다. **줄눈은 두꺼워질 수가 없다.**
얇은 그물은 밀도로 정규화되므로 응집도가 정의상 ≈1.0 이다 (바닐라 막돌 0.99 · 바닐라 자갈 0.94).

**그리고 이것이 증거다.** 응집도를 만족시키려 **줄눈을 문턱 아래로 지웠더니** 응집도가
**1.02 → 1.83** 으로 뛰었다. **검수는 만족했다.** 확대해 보니 돌의 윤곽이 사라진 잿빛 콘크리트였고,
이끼 낀 막돌은 맨 막돌과 **구별조차 되지 않았다.**
**자가 나쁜 그림에 1.83 을, 좋은 그림에 1.05 를 주었다 — 순위를 뒤집은 것이다.**

⇒ 세포면은 **제 자**로 잰다 (잎이 구멍 비율로 재는 것과 같은 이치):

| 잣대 | 계약 | 무엇을 막는가 |
|---|---|---|
| 여백 | ≥ 35% | 바닐라 막돌 29% · 자갈 25% 가 걸린다 |
| **어두운 획의 두께** (2회 침식 생존) | **≤ 3%** | **줄눈은 그물이지 덩이가 아니다** — 검은 얼룩을 줄눈이라 우기면 걸린다 |
| 줄눈 깊이 | ≥ 12루마 | 문턱 아래로 숨기면 걸린다 (**윤곽이 보여야 한다**) |

★ **이 자도 처음엔 틀렸다.** 첫 판(“여백이 돌 [6,28]개로 갈라지는가”)은 아는 답 다섯으로 시험하자
**좋은 막돌을 떨어뜨리고 나쁜 시안을 통과시켰다** — '줄눈 깊이'가 줄눈이 아니라 **검은 얼룩**을 재고 있었다.
진짜 차이는 **두께**였다 (줄눈은 침식하면 사라진다 0.0% · 씻긴 돌은 살아남는다 8.8%).
**자를 만들면 아는 답으로 시험하라.**

## 7. 자바 배선 — **내가 못 하는 것** (코드를 넘긴다)

### ① 명병 item_model 배선 (`Weapons.java`)

명병 PNG·모델·아이템 정의는 **다 구워져 있다** (`honcheon:weapon/myeong/<sect>`).
남은 것은 애병(`Beloved.명병`)이 문파를 알 때 그 키를 박는 것이다.

```java
// Weapons.java — 명병(名兵)은 PDC 태그로만 존재했다 (이름은 붙는데 모양이 안 바뀐다).
// 팩에 문파별 명병 8자루가 구워져 있다: honcheon:weapon/myeong/<sect>
// sect id 는 config/factions.yml 의 member id 다 (hwasan · jeomchang · jongnam · namgung ·
//                                                 mudang · paengga · dangga · sorimsa)
private static final Set<String> MYEONGBYEONG_SECTS = Set.of(
        "hwasan", "jeomchang", "jongnam", "namgung",
        "mudang", "paengga", "dangga", "sorimsa");

/** 명병이면 문파의 얼굴을 씌운다. 아니면 계열·등급의 기존 키를 그대로 둔다. */
private static NamespacedKey modelFor(ItemStack stack, Series series, Grade grade, String sect) {
    if (isMyeongbyeong(stack) && sect != null && MYEONGBYEONG_SECTS.contains(sect)) {
        return NamespacedKey.fromString("honcheon:weapon/myeong/" + sect);
    }
    return NamespacedKey.fromString("honcheon:weapon/" + series.modelId() + "_" + grade.id());
}
// 적용:  meta.setItemModel(modelFor(stack, series, grade, sect));
// ★ 팩 게이트: 팩이 없으면 베이스 아이템(golden_sword 등)이 그대로 뜬다 — 플레이는 된다.
```

### ② 허기 게이지 — **아이콘을 그릴 게 아니라 게이지를 꺼야 한다**

코드에 `setFoodLevel` 이 **한 줄도 없다** → 허기는 완전 바닐라이고 **아무도 안 쓴다.**
안 쓰는 게이지에 만두 아이콘을 다는 것은 **화면이 세계에 대해 거짓말하는 것**이다.

```java
// 무협에 허기 바는 없다. 게이지를 꺼서 화면이 거짓말하지 않게 한다.
// (리소스팩은 HUD 요소를 '숨길' 수 없다 — 텍스처만 바꾼다. 끄는 것은 서버의 일이다.)
player.setFoodLevel(20);
player.setSaturation(20f);
player.setExhaustion(0f);
// + FoodLevelChangeEvent 를 취소해 20 에 고정 (허기 감소 자체를 막는다)
@EventHandler public void onFood(FoodLevelChangeEvent e) { e.setCancelled(true); }
// ⇒ 그러면 닭다리는 화면에 뜨되 **절대 줄지 않는다**. 완전히 없애려면 Paper 의
//    HUD 컴포넌트 숨김(1.21.x: player.hideBossBar 류가 아니라 클라이언트 옵션)은 불가 —
//    ★ 정직한 벽: **바닐라 허기 바는 리소스팩으로도 서버로도 '숨길' 수 없다.**
//      선택지는 둘뿐이다: (a) 20 에 고정해 무의미하게 만든다  (b) 아이콘을 무협의 것으로 바꾼다.
//      (a) 를 권한다 — 그리고 (b) 는 청구서에 남긴다 (둘은 배타적이지 않다).
```
