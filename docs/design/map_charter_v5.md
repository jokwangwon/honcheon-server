## 1. 3계층 헌법 — 지도 → 땅 → 건축 (HANDOFF §2.4 개정 인용)

> ★★ **지도가 정본이다. 지도는 건축물을 포함한 맵 디자인 전체다.**
> **땅은 지도에 맞게 서고, 건축은 그 땅 위에 오른다.** (사용자 원문 — B-147)
> 땅의 치수(봉우리 정상부 폭·단의 넓이·진입로)는 **지도의 건축 footprint 에서 유도**된다.

**폐지된 구판 조항** (묘비 — 다시 세우지 마라):

- ~~"땅에 맞게 건물이 올라가는 것이지, 건축에 맞게 지형이 생기는 게 아니다"~~ — 지도가 건축을
  포함하므로 거짓이 됐다. 이 조항 아래서 봉우리가 건물보다 얇게 서고 건물이 묻히고 떴다 (B-146).
- ~~"건축의 미결이 땅을 막아서는 안 된다 (땅 먼저)"~~ — 지도가 완성되지 않은 곳은 땅도 빚지
  않는다. v4 의 「땅 먼저」 관행이 만든 30곳의 땅은 v5 갈아엎기의 대상이다.

**집행 안전핀** (권위는 지도에 있다 — 핀은 지도를 섬기는 기계로 존속. ★존속 여부 사용자 승인 대기):

> **땅은 한 번만 선다** (`TerrainLedger`) — 같은 지도로 두 번 빚지 않는다. 지도가 바뀌면 그때 다시 빚는다.
> **건축 집행이 선 땅을 임의로 바꾸지 못한다** (`TerrainSeal`) — 지도에 없는 변형은 위반이다.

이 헌장에서의 함의 세 가지:

1. **지도 없이는 땅이 없다.** 장소의 지형 브리프(§3)가 채워지고 승인되기 전에는 그 자리에
   조성을 돌리지 않는다 — 원형 미결(B-047~051·B-094)인 곳의 땅은 지금 서지 않는 것이 옳다.
2. **땅의 치수는 유도값이다.** 정상부 폭·단·진입로는 취향이 아니라 §4 역산표의 함수다.
   현행 코드는 반대로 되어 있다 — 원형 치수가 코드 상수(`R=22`, `UPPER_HALF_*`)에 박혀 있어
   지도(`build_radius`)와 무관하고, 지형 상수(`SUMMIT_R=22`)는 건축을 모른다. v5 는 이 둘을
   지도가 잇는다.
3. **어울림(이음)이 설계 항목이다.** 부지 경계에서 자연으로 나가는 전이 — 벼랑인가 비탈인가,
   숲이 어디까지 오는가 — 를 브리프가 적는다. 지금은 전이대(1-립시츠)가 기계적으로만 잇는다.

## 2. ★★ 세계의 밑감(世界基) — 첫 결정 (B-148)

★ 사용자 제안 (2026-07-15, 원문):

> "바닐라 지형을 확인 후 측정하고 땅을 깎거나 설치하는 게 힘들다고 판단이 되는데,
> **평지 맵에서 처음부터 모든 걸 제작하는 형태**는 어떤지 고려."

이것이 이 헌장의 **첫 결정**이다 — 밑감이 정해져야 브리프(§3)의 `transition`(이음)이 뜻을
갖고, 갈아엎기 절차가 정해진다. **결정은 사용자 몫이고 이 절은 검토표다.**

### 2.1 전제 — 이 서버는 이미 바닐라를 대부분 걷어냈다 (실측)

| 걷어낸 것 | 근거 |
|---|---|
| 자연 스폰 **0** — "허용 목록은 비어 있다. 한 종도, 한 마리도" · 모든 짐승은 등록부(정원·좌표)로만 선다 | `config/world_purity.yml` wild_spawn (:337-360) |
| 자연 동굴 — no_caves 데이터팩 (등록제 편입 B-113) | `config/world_purity.yml:503-504` (`worldgen/honcheon_no_caves`) |
| 바닐라 구조물·스포너 — honcheon_purity 데이터팩 (정본 최소 편집 + 바이트 감사) | `config/world_purity.yml:20` |
| 클라이언트 외양 — **팩이 있어야 플레이 가능** (2026-07-13 헌법 개정) | HANDOFF §2.7 |

바닐라에게 남아 있는 것은 사실상 **지형 밑감 하나**다 — 그리고 그 밑감과의 이음에서
사고가 났다 (2.2).

### 2.2 후보 ① 바닐라 지형 유지 (현행) — 이음 비용이 상수로 남는다

TerrainForge 의 기계 상당수가 「바닐라와의 이음」 비용이다: `naturalTop`(자연 지면 측정 —
파일 전역 약 20개 호출처, TF:2383) · `feather`(계약 ② — 경계를 자연으로 잇는 전이대,
TF:33·297·321·327·587) · `fit`/경계 검수(환경검수 ③ 경계 급단차 ≤8%). 이 비용을 방증하는
사고 이력이 장부에 있다:

| 사고 | 무엇이었나 |
|---|---|
| **B-140** | 경계다듬기가 못 고치는 급단차 — 봉우리·험 계열 6곳 (곤륜 11% · 당가 17% · 팽가 15% · 개봉 22% · 낙양·마교 진입불가). ★마교 본교는 다듬을수록 **악화** (11.9→16.0%) |
| **B-141** | 강가 부지가 **이미 물** — 자연 수면 y62 가 계획 수면 y60 보다 높아 강 파기 거절 (장강수로채·무한) |
| **B-113** | 조성기가 바닐라 숲을 **산 채로 묻었다** — 지하 공동 3.8%, 치유 48,519칸. cheese 동굴 수사에 세션 여러 개가 들었다 |
| **B-139** | 봉인 계측이 물리 정착(모래·물)에 오염 — 건축 없는 조성을 "위반"이라 물었다 |

- 장점: 야생이 공짜다 — 장소 사이의 산·강·숲을 바닐라가 준다. 시드는 이미 검사해 골랐다
  (20260710, 시드검사 90점 — B-113).
- 갈아엎기 절차: 같은 시드로 월드 재생성 → 전 장소 재조성. 월드 타입 변경 없음.

### 2.3 후보 ② 평지 밑감 + **세계 전체 연속 설계** — 지도가 100% 정본

★ 사용자 확정 — ②안의 정의 (2026-07-15, 원문):

> "장소 간 이동은 **직접 뛸 수도 있어야** 합니다 (그러므로 **디자인이 되어야** 합니다).
> **강·산·숲을 직접 설계**하고, 중간중간 **적**과 장소 컨셉에 맞게 **숨겨진 잔재라던가
> 히든 장소**를 배치해도 됩니다. **여백은 — 지역 사이간은 없는 걸로** 제작합니다."

즉 ② = 평지/공허 밑감 위에 **세계 전체를 연속으로 설계**한다 — 양식화된 빈 여백 금지 ·
도보 횡단 가능. 새 §2.4 의 가장 순수한 구현이다: 측정할 자연이 없으니 측정 오차가 없고,
이을 자연이 없으니 이음 사고(2.2 표의 넷 전부)가 **원리적으로 소멸**한다.

**기각된 안** (묘비 — 이 완화론으로 되돌아가지 마라): 조율자의 「여백」 독법 —
"원거리는 여정(오프스크린)이 건너니 아무도 걷지 않는 여백은 안 빚어도 된다 · 수묵의
여백(餘白)이 설계 언어가 된다" — 는 **사용자가 기각했다.** 여정 이동(world_map.yml:374-392)은
존속하되, 그것이 땅을 안 빚을 면허가 아니다.

기존 기계와의 정합 (코드로 확인):

- `raiseMassif` 는 평지에서 **오히려 간섭 없이 돈다** — 자연 프로브가 상수로 답하므로
  "자연이 이미 산을 줬다" 조기 반환(TF:873-874)이 절대 안 걸리고, 채움 고리(TF:1085-1087)는
  평지면까지 균일하게 채운다. `levelField`·`duneField` 는 하는 일이 거의 없어지고,
  `feather` 는 평지↔평지 이음이라 자명하게 통과한다.
- `RiverForge` + `config/rivers.yml` — 선형 물길을 등록부가 계획하고 기계가 파는 **선례**.
  다만 부지 사양(SiteSpec) 뒤에 붙는 장소 반경 안의 손이다 (RiverForge.java 머리 주석).
- `terrain_grain.yml` 격자 잡음(값 잡음 — 좌표의 순수 함수, cell 7~13) — 광역에서도 그대로
  쓰이는 결정론 밑재료다. 그러나 **현행 TerrainForge 는 장소 단위(원, forge_radius 110) 조성이다**
  — 지역 사이를 잇는 광역(노선 단위) 지형 도구는 **없다.** ②를 고르면 신규다 (아래 표).

②의 설계 항목과 비용 (정직하게):

| 설계 항목 | 내용 |
|---|---|
| **이동 회랑** | 지역 간 주요 도보 경로가 설계 단위가 된다 — **회랑 우선 설계** (노선·관문·경유지). 노선 등록부는 이미 있다: `world_map.yml routes:` 12개 노선 · waypoints 좌표 · kind(관도/산길/험산/수로/해로) · danger · hazards |
| **야생 지형** | 회랑을 따라 강·산·숲을 직접 설계 — 장소 원(110)을 노선 따라 늘어놓는 것은 문법 위반이고(장소가 아닌 것을 장소로 등록), **노선 조성기**(RiverForge 의 선형 문법 + terrain_grain 의 결을 노선 폭으로 확장)가 신규로 필요하다. 결정론 헌법(좌표 순수 함수) 은 격자 보간으로 유지 가능 |
| **탐험 콘텐츠 층 — 적** | 기계 재사용 가능: `hunting_grounds.yml` 정원제(`repopulate` — 정원·좌표·재생 주기)가 이미 "세계의 모든 짐승은 등록부에 있다"(world_purity)를 지킨다. 회랑 좌표에 사냥터를 등록하면 같은 기계가 돈다. 노선 조우도 지도에 이미 성립한다 — `routes.*.hazards: [nokrim_jungchae]` (world_map.yml:2103 · "여정 조우가 지도에서 성립한다" :2116) |
| **탐험 콘텐츠 층 — 잔재·히든 장소** | 등록제와의 정합: **히든 장소도 등록부에는 실린다 — 플레이어에게 숨는 것이지 지도에 숨는 것이 아니다** (B-148). `build: never/later`(서사 장소) 문법이 이미 있다 (world_map.yml:759) |
| **바이옴** | superflat 은 단일 바이옴 — 풀색·온도·설선의 지역차가 없다. 바이옴 칠하기(데이터팩/프리셋)가 필요한지, 자재로만 말할지(설선은 이미 `snowlineRegistry` 가 블록으로 놓는다, TF:840-845) — 검토 항목 |
| **물** | 강·호수·바다 전부 설계 몫 — rivers.yml 문법은 있으나 **바다**(B-041 시박사)는 새 설계다. 평지에는 자연 수면이 없으므로 B-141 류의 거절은 원리적으로 없다 |
| **스폰 플랫폼** | 공허(void)형이면 최초 접속·낙사 안전망이 별도로 필요하다 (superflat 이면 불요) |

**설계 분량 추정** (등록부 좌표에서 계산 — 지어내지 않았다):

- 등록 노선 12개의 waypoints 꺾은선 합 = **15,364 km (약 1,536만 블록)**. 수로·해로
  (장강 1,838 · 위수 124 · 동영 해로 2,288 = 4,250 km)를 빼면 **육로 회랑 ≈ 11,114 km**.
  도보 환산 384일(40 km/일, world_map.yml:310) — 청하현→화산 한 노선(148.7 km)만도
  뛰어서 약 2시간 반이다 (world_map.yml:390 원문과 정합).
- 현행 조성 단위로 환산하면: 조성 원 하나가 지름 220블록(forge_radius 110) → 육로 회랑만
  **약 5만 개의 조성 원**에 해당한다. 손 조성(장소 문법)으로는 불가능한 규모다 — 그래서
  ②의 야생은 필연적으로 **결정론 절차 지형(노선 조성기 + 격자 결)** 이 된다.
- 전면(회랑 밖까지) 설계의 상한: 등록 좌표 범위 x 4.49M × z 3.00M (world_map.yml:226)
  ≈ **1.3×10¹³ 칸** — 어떤 방법으로도 전부 손으로 빚을 수 없다. **회랑 밖 원야를 어디까지
  절차 지형으로 채우는가**가 ②의 남는 사용자 결정이다.

- 갈아엎기 절차: **월드 타입 변경** (superflat 프리셋 또는 void) — 시드가 무의미해지고
  (시드검사 폐기), level.dat 신설 + **회랑·야생 조성 도구 개발** + 전 장소 조성.
  월드 신설이므로 백업 규약(§2 헌법)은 동일.

### 2.4 후보 ③ 자체 청크 생성기 (커스텀 worldgen) — 전권 + 자연스러운 야생

플러그인 `ChunkGenerator` 또는 데이터팩 worldgen 으로 지형 자체를 우리가 생성한다.
지도가 생성기의 입력이 되므로 ②의 순수성과 ①의 야생을 이론상 둘 다 얻는다.

- 대가: **큰 엔지니어링이다** (솔로 개발자) — 생성기 개발·시험·성능이 통째로 새 트랙.
  결정론 헌법(§2.5 — 조성기에 난수 금지, 격자점 보간)을 생성기 전체로 확장 유지해야 한다.
- 갈아엎기 절차: 생성기 개발 완료가 선행 — **v5 일정이 생성기 일정에 종속된다.**

### 2.5 검토표 요약과 권고 (②의 확정 정의 기준으로 재평가)

| | ① 바닐라 유지 | ② 평지 + 세계 전체 연속 설계 | ③ 자체 생성기 |
|---|---|---|---|
| §2.4 정합 | 땅의 절반이 지도 밖(자연) | **지도 = 세계 전부** | 지도가 생성기 입력 |
| 이음 비용 | 상수로 지속 (B-140·141·113·139) | **원리적으로 0** | 생성기가 흡수 |
| 장소 사이 | 공짜 (통제 밖) | **설계 몫** — 회랑 11,114 km + 원야 절차 지형 (2.3 추정) | 생성기 몫 |
| 엔지니어링 | 현행 유지 | fit/feather 축소 + **노선 조성기·광역 결 신규** | **크다** (전체 생성기) |
| 갈아엎기 | 같은 시드 재생성 | 월드 타입 변경 · 시드 무의미 · 도구 선행 | 생성기 완성 후 |
| 위험 | 같은 병 재발 여지 | 회랑·바이옴·원야 설계 누락 | 일정·결정론 부담 |

**권고 (조율 소견 — 결정 아님): 여전히 ②** — 다만 확정 정의로 무게가 달라졌다.
근거 — (a) 사고 이력 넷이 전부 이음에서 났고 그 비용이 원리적으로 사라진다,
(b) 이 서버는 이미 스폰·동굴·구조물·외양에서 「전부 세는 세계」를 택했다 — 지형만 예외로
남길 이유가 약하다, (c) 적·잔재·히든 장소의 기계(정원제·hazards·build:never)가 이미 있어
탐험 층은 등록만 늘리면 된다. **정직한 대가**: 여백 기각으로 ②는 「조성기 소폭 정리」가
아니라 **노선 조성기 + 광역 절차 지형이라는 새 트랙**을 품는다 — ②와 ③의 거리가
「미리 빚나 / 청크 생성 때 빚나」의 차이로 좁아졌다. 그래서 순서를 권한다:
②로 시작하되 회랑을 먼저 빚고(노선 조성기), 회랑 밖 원야는 그 도구가 성숙하면 ③(생성기)로
이행할 수 있게 결정론 문법을 공유한다. **회랑 밖 원야의 범위는 ②를 골라도 남는
사용자 결정이다** (2.3 분량 추정 참조) — 브리프 틀(§3)의 `influence`/`transition` 이
그 답을 장소마다 적는다.

## 3. 장소별 지형 브리프 — 지도에 올리기 전에 채워야 하는 틀

한 장소가 지도(정본)에 오르려면 아래 항목이 전부 채워져야 한다. **틀만 여기 세운다 —
내용(각 문파의 컨셉·브리프)은 사용자·설계의 몫이고, 이 문서는 채우지 않는다.**

```yaml
# ── 장소 지형 브리프 (v5) — 한 장소 = 한 장 ──────────────────────
id:                # world_map.yml 의 키
archetype:         # §16 원형 (pending 이면 이 브리프도 미완이다 — footprint 를 모른다)

# ① 영향권 — 봉우리 하나가 아니라 영역 (사용자 원문: "문파 주변의 환경, 영향권 내의 컨셉")
influence:
  surroundings:    # forge_radius(110, world_map.yml land:) 안의 자연 — 산맥의 결·수계·숲·설선
  neighbors:       # 이웃 장소와의 관계 — 어디서 보이고, 무엇과 등을 대는가
  silhouette:      # 멀리서 읽히는 형상 — 이 장소를 처음 보는 자가 무엇을 보는가

# ② 컨셉 — 한 줄 산문 (등록부 산문과 정합해야 한다)
concept:

# ③ 진입로 — 오르는 길이 시험이다
approach:
  bearing:         # 방위 (어느 이웃·길에서 오는가 — faction_entry_routes 와 정합)
  kind:            # 계단 | 산길(carveTrail) | 관도 | 물길
  narrative:       # 걸어 오르는 동안 무엇을 보는가

# ④ ★ 땅의 치수 — 건축 footprint 에서 유도한다 (§4 역산표를 읽고 적는다. 지어내지 않는다)
land:
  profile:         # 봉우리 | 고원 | 중턱단 | 들 | 사막 | 수향(B-094 미구현) …
  lift:            # 산 높이 (terrain.yml lift: — 험산 72 · 산 44 · 고원 24)
  summit_flat_r:   # 정상 평탄부 반경 — ≥ 원형의 모서리 반경(§4) + 설계 여유(사용자 몫)
  tiers:           # 단(터)의 수와 각 단의 최소 폭×깊이 — 원형의 단 요청(§4)에서 유도
  flat_area:       # 필요 평탄 면적 합 (§4 의 합산 열)
  water:           # 물 요건 (수로채·수향 — 물가·수면 폭·수심)
  transition:      # 외곽과의 이음 — ★§2 밑감에 따라 뜻이 달라진다 (①자연과의 전이 / ②여백과의 전이)

# ⑤ 근거 — 이 브리프의 수는 어디서 왔는가 (등록부 줄 · 역산표 행 · 사용자 결정 날짜)
evidence:
```

기입 규칙:

- **④는 §4 역산표에서만 온다.** 표에 없는 원형(§4.5 미역산)은 먼저 역산하고 브리프를 채운다.
- **모르는 것은 모른다고 적는다** (`unresolved`) — scale_systems.md 의 가장 중요한 조항을 따른다.
- 브리프가 채워지지 않은 장소는 **땅이 서지 않는다** (§1 함의 1). 그것이 실패가 아니라 정직이다.

## 5. 봉우리 요건 도출 — "너무 얇다"의 정량화

사용자 판정: 봉우리가 "너무 얇게 지어져 건물을 올려 디자인을 하기 힘들게" 만든다.
코드로 재면 병은 둘이다 — **정상이 얇은 것**과 **본전이 정상에 못 오르는 것**.

### 5.1 현행 연쇄 (화산 기준 — 전부 코드값)

```
lift 72 (terrain.yml:68 험산)
→ 산 반경 massifR = max(SUMMIT_R+28, 0.9×72) = max(50, 64) = 64   (TF:891-893, 물매 1:0.9)
→ 부지 build_radius 64 (world_map.yml:993) = 산 반경 → 부지 전체가 산비탈
→ 봉우리는 중심에서 북으로 8칸 (TF:869-870) → 남진입 기준 peakF = −8
→ 계단 run = (rad−20) − (peakF+11) = 64−20−3 = 41                  (RB:936-940)
→ rise = min(72, run−4) = 37                                        (RB:945)
→ 본전 단이 실봉우리보다 35칸 낮은 원뿔 허리에 선다.
   terrace 는 위로 14칸만 비우므로 (TF:1573) 그 위 산몸이 남는다 —
   마당이 구덩이가 되고, 경사 위 두-평면 근사가 화산 뜸 ↔ 종남 박힘으로 갈린다 (B-146).
```

정상 평탄부 자체: `SUMMIT_R = 22` (TF:1027) 는 본전 단(27×21, 모서리 ≈17)을 기하학적으로
담는다 — 그러나 위 연쇄 때문에 **현행 조성에서 본전은 그 평탄부에 도달하지도 못하고**,
도달해도 처마 밖 여유가 모서리 기준 다섯 칸뿐이다. 그 다섯 칸 뒤는 1:0.9 벼랑이다.

### 5.2 요건 — footprint 에서 거꾸로

**(a) 정상 평탄부 반경.** 유도식:

```
summit_flat_r ≥ (그 장소 원형의 최대 단 모서리 반경) + (설계 여유 M)
도관: 모서리 ≈17 → SUMMIT_R 22 는 M ≈ 5.  M 을 얼마로 하는가 = ★사용자 결정
      (회랑·별채·측전이 지도에 오르면 그 footprint 가 M 을 대체한다 — 여유가 아니라 유도값이 된다)
```

**(b) 본전이 실봉우리에 앉는 조건** (물매 1:0.9 · lift 72 유지 시):

```
rise = 72 이려면 run ≥ 76             (RB:945 — run−4 ≥ 72)
→ rad ≥ run + 31 + peakF = 76 + 31 − 8 = 99                        (RB:936-940 역산)
즉 직선 계단 문법을 유지하면 부지 반경 ≈ 100 이 필요하다 (현행 64 → +35).
그때 산 반경은 여전히 64 (높이가 정한다, TF:887-893) → 문전·산문은 산자락 들에 선다
(코드 주석이 이미 그것을 옳다고 적었다 — RB:890 "부지가 산보다 넓으면 그 바깥은 그냥 들이다").
forge_radius 110 (world_map.yml land:) 안에 들므로 2계층 계약은 지켜진다.
```

**(c) 정상 평탄부를 넓히면 산이 커진다** (연쇄):

```
massifR = max(summit_flat_r + 28, 0.9 × lift)                       (TF:891-893)
lift 72 에서 summit_flat_r ≤ 36 까지는 산 반경 64 로 불변 (0.9×72 가 지배).
summit_flat_r 이 36 을 넘으면 산 반경 = summit_flat_r + 28 로 자란다.
```

### 5.3 선택지 — ★사용자 결정

| 안 | 내용 | 값의 귀결 | 대가 |
|---|---|---|---|
| A | 부지를 키워 직선 계단이 정상까지 오르게 | rad ≈ 100 (5.2-b) · 문전·산문은 산자락 들 | 문파 부지가 소림(80)보다 커진다 — §17 사다리와의 관계를 사용자가 정해야 한다 |

## 7. 이 문서가 참인지 재는 법

- 역산표의 모든 수치는 `file:line` 이 붙어 있다 — 대조가 곧 검증이다.
- 코드가 바뀌면 이 표는 거짓이 된다. **v5 조성 전에 §4 를 코드와 재대조하라**
  (특히 RB:60 R · RB:973-975 UPPER_HALF · TF:1027 SUMMIT_R · TF:891-893 massifR · RB:945 rise).
- §5 의 연쇄 계산은 남진입(peakF=−8) 가정이다. 북진입이면 peakF=+8 → run 25 → rise 21 로
  더 나빠진다 — 가정이 결론을 약하게 만들지 않는다.
- §2 의 실측 근거는 `config/world_purity.yml`(:337 wild_spawn · :503 no_caves) ·
  `config/world_map.yml`(:374-392 이동 문법 · :2087 routes) · 장부 B-113·139·140·141·148 이다.
- §2.3 의 분량 추정(회랑 15,364 km · 육로 11,114 km)은 `world_map.yml routes:` 의 waypoints
  꺾은선 길이 합산이다 — 좌표가 바뀌면 다시 합산하라 (12개 노선 전부, 유클리드 구간합).
