# LLM 런타임 정책 — 백그라운드 모델 선택과 텍스트 생성 원칙

> 질문: 백그라운드에서 돌 LLM 선택과 텍스트 생성 원칙의 규정 — 실 테스트 준비의 마지막 공백.
> 전제: 2단 파이프라인 (엔진이 <10ms에 사실을 계산 → LLM은 그 사실을 서사로 렌더).
> **LLM은 게임 로직에 관여하지 않는다** — MC 전투·성장·경제는 LLM 미개입 (기존 원칙 유지).
> 기계 판독용: `config/llm.yml`. 가격·모델은 2026-07 기준 (Claude API).

---

## 1. 역할별 모델 선택 — 하나의 모델이 아니라 역할의 사다리

| 역할 | 부하 특성 | 모델 | 가격(입/출 $/1M) | 근거 |
|---|---|---|---|---|
| **턴 렌더러** | 고빈도·저지연 (턴마다) | `claude-haiku-4-5` | 1.00 / 5.00 | 엔진이 사실을 전부 주므로 과제가 좁다 — 속도·비용 최우선 |
| **GM 서사** (장 전환·발단 생성·심층 대화) | 중빈도·품질 중요 | `claude-sonnet-5` | 3.00 / 15.00 | 서사 일관성·긴 문맥 (1M) — 렌더보다 드물어 비용 감당 |
| **세계 배치** (계절 정산 서사화·다이제스트) | 저빈도·비실시간 | `claude-sonnet-5` + **Batch API** | 50% 할인 | 자정 배치와 동형 — 지연 무관, 24h 내 완료 |
| **세계급 사건** (창작 오의 심사·세계 이벤트) | 희귀·최고 품질 | `claude-opus-4-8` | 5.00 / 25.00 | 세계 유일 등록물의 심사관 — 빈도가 낮아 비용 무관 |

- 에스컬레이션 규칙: 렌더러가 스키마 불일치를 2회 반복하면 해당 턴만 GM 서사 모델로 승격.
- 모델 ID는 config에 두고 코드에 하드코딩하지 않는다 (모델 세대 교체 대비).

## 2. 지연 예산 — "저지연 한국어 서사"의 실체

```text
목표: 판정 결과 체감 0ms + 서사 첫 글자 <1.5s + 전문 <5s
① 판정은 엔진이 즉시 (LLM 대기 없음) — 결과 요약 한 줄은 엔진 템플릿으로 선표시
② 서사는 스트리밍 — 첫 토큰부터 타자기 출력 (Haiku 첫 토큰이 가장 빠른 선택)
③ 선택지 프리페치 (기존 설계·PT-005 실측 ~90%) — 유력 선택지의 다음 턴을 미리 렌더
   적중 시 체감 지연 0. 미적중 시만 ①②의 실경로
④ 프롬프트 캐싱 — 아래 3장. 캐시 히트 시 입력 처리 지연도 크게 준다
```

## 3. 프롬프트 캐싱 — 비용·지연의 제1 레버

```text
프리픽스 설계 (캐시는 접두사 일치 — 바이트 하나가 전체를 무효화한다):
  [고정] GM 마스터 프롬프트 v2 + 룰 다이제스트 + 은유 사전   ← cache_control (5분 TTL)
  [세션] 캐릭터 시트 + 지역 상태 스냅샷                       ← 세션 갱신 시에만 변동
  [가변] 이번 턴의 엔진 사실 JSON                              ← 캐시 뒤, 매턴 교체
금지: 시스템 프롬프트에 시각·난수 삽입 (침묵 무효화) / 턴마다 도구·모델 변경
주의: Haiku 4.5 최소 캐시 4096토큰 — GM 프롬프트+다이제스트면 충분히 넘는다
효과: 반복 프리픽스 읽기 ≈ 0.1× 요금 — 활성 세션(5분 내 턴 반복)에 정확히 부합
검증: usage.cache_read_input_tokens 모니터링 — 0이면 무효화 원인 추적
```

**턴당 비용 추산** (렌더러, 캐시 정상 가동 시): 캐시 읽기 ~8K + 신규 입력 ~1K + 출력 ~0.6K
≈ **$0.005/턴**. 동접 60 × 시간당 6턴 ≈ $1.8/시간 — 감당 가능. GM·배치는 빈도가 낮아 오차 항.

## 4. 텍스트 생성 원칙 — LLM이 지켜야 할 7계

```text
① 엔진 불가침   수치·판정 결과·자원 변동의 발명/변경 금지. 렌더 입력의 사실 목록이 전부다
              — LLM이 "성공했다"를 정할 수 없다. 성공했다고 '들었을' 뿐이다
② 스키마 강제   출력 = JSON (narration / choices[] / npc_lines[]) — 구조화 출력
              (output_config.format json_schema)로 API 수준 보장. 파싱 실패라는 개념 자체를 제거
③ 수치 은닉    서사에 숫자 노출 금지 — "판정은 서사로" (마진 +2는 '아슬아슬하게'로).
              단전·내공은 은유 사전(dantian_and_simbeop) 경유
④ 정보 경계    플레이어가 모르는 진실 누설 금지 — 소문은 엔진이 준 정확도만큼만.
              비밀(secrets)은 엔진이 해금 플래그를 줄 때만 서사에 등장
⑤ 등록제 명사   NPC·지명·무공명 신조 금지 — 카탈로그에 있는 이름만. 새 이름이 필요하면
              등록 절차(엔진)로 반환하고 이번 턴은 무명으로 서술
⑥ 길이 예산    턴 서술 400~700자, 선택지 3~5개 × 한 줄, NPC 대사 2줄 이내
              — 텍스트 게임의 호흡. 장 전환 등 GM 서사만 상한 완화
⑦ 문체       한국어 무협 문법 — 기존 GM 마스터 프롬프트 v2의 문체 규정 승계.
              과장 억제: 사건의 무게는 엔진 수치(소문 강도·마크)가 정하지 형용사가 정하지 않는다
```

## 5. 실패 처리 — 게임은 멈추지 않는다

```text
스키마 불일치  SDK 재시도 1회 → 렌더러 승격(2장) → 그래도 실패 시 폴백
API 장애/한도  폴백 = 엔진 원시 출력 (판정 결과 표 + 정적 선택지 템플릿)
              — 서사 없는 턴은 심심하지만 유효하다. 규칙은 엔진에 있으므로
과부하(529)   지수 백오프 (SDK 기본) + 프리페치 재활용 (이미 렌더된 분기 우선 소진)
로깅         모든 렌더 호출: (엔진 사실 해시, 응답, usage) — 원칙 위반 감사 재료
```

## 6. 준비도 점검 — "실 테스트 준비가 덜 된 것 아닌지"에 대한 답

```text
MC 관리자 테스트 (MVT)      ✅ 준비됨 — LLM 무관 (엔진 단만 배선, 전투·성장·경제에 LLM 없음)
텍스트 RPG 실테스트:
  LLM 정책·생성 원칙        ✅ 본 문서로 채움 (공백이었음 — 지적이 맞았다)
  GM 마스터 프롬프트        ✅ 있음 (v2) — 렌더 스키마와의 결선만 남음
  2단 파이프라인 프로토타입   ❌ 미구현 — 다음 마일스톤 (엔진 JSON → LLM 렌더 실동 + 캐시 히트율 실측)
  선택지 프리페치 구현       ❌ 프로토타입에 포함
  세션 영속화              ❌ MVT는 메모리 — 텍스트 실테스트 전 필요
결론: MC 체감 테스트는 지금 가능. 텍스트 RPG 실테스트는 프로토타입 1개(2단 파이프라인)가
     선행 조건 — 본 정책이 그 프로토타입의 스펙이다.
```
