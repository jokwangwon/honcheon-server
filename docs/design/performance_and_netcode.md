# 서버 성능·통신 품질 설계 — 다중 스킬 상호작용의 버그·랙 예측과 방어

> 질문: 여러 스킬이 동시에 쓰일 때의 통신 품질, 버퍼링, 상호작용 버그를
> 미리 추측하고 최선의 방법을 모색한다.
> 방법: MC 서버의 물리 법칙에서 출발 → 장애 유형을 열거(F-*) → 각각 방어책을 규정.
> 기계 판독용 예산: `config/performance.yml`

---

## 1. 전제 — 마인크래프트 서버의 물리 법칙

```text
단일 틱 스레드: 게임 상태 변경은 전부 메인 스레드. 20 TPS = 틱당 50ms 예산.
랙의 정체:     ① 틱 초과(MSPT>50 → TPS 하락: 서버 전체가 느려짐)
              ② 패킷 폭주(클라이언트 프레임 드랍·수신 버퍼 적체 — TPS는 멀쩡해도 유저는 렉 체감)
              ③ 동기 I/O(DB·청크 로드가 메인 스레드를 세움 — 스파이크형 멈춤)
철칙:         비동기에서 Bukkit API 호출 금지. 게임 상태의 단일 작성자는 메인 스레드.
```

## 2. 우리 아키텍처의 구조적 이점 — 먼저 확인

```text
세계 반응 루프(소문·세력·지역·수련 정산)는 일(日) 단위 배치다.
→ 실시간 핫패스에서 완전히 분리: 하루 1회 비동기 계산 → 메인 스레드 일괄 반영.
  수천 개 소문·세력 점수가 있어도 전투 프레임에 영향 없음.
판정 엔진은 O(1) 산수다 (맵 조회 + 덧셈). 판정 자체는 랙 요인이 아니다.
→ 성능 리스크는 대부분 '스킬의 시각 효과와 동시성'에 집중된다. 거기에 화력을 모은다.
```

## 3. 장애 유형 예측과 방어책 (F-목록)

### 3.1 성능 (틱·패킷)

| # | 예측 장애 | 방어책 |
|---|-----------|--------|
| F-P1 | **파티클 폭탄** — 10명 동시 시전 → 틱당 수만 파티클 패킷 → 클라 프레임 드랍, 송신 큐 적체 | **파티클 예산 관리자**: 틱당 전역 상한 + 플레이어별 상한, 거리 LOD(16m 밖 절반, 32m 밖 생략), 예산 초과 시 연출 자동 강등 (화려함은 깎여도 판정은 불변) |
| F-P2 | **이펙트 태스크 누적** — 버프/도트마다 스케줄러 태스크 생성 → 수백 개 태스크가 스케줄러를 압박, 사망·로그아웃 시 누수 | **중앙 EffectTicker 1개**: 단일 반복 태스크가 활성 효과 목록을 순회. 효과별 태스크 생성 금지. 사망/퇴장 이벤트에서 일괄 청소 |
| F-P3 | **AoE 전수 스캔** — 광역 무공이 월드 전체 엔티티 순회 (O(N²)) | 청크 기반 근접 조회만 사용, 대상 수 상한(스킬당 max_targets), 반경 상한 |
| F-P4 | **VFX 엔티티 남발** — 검기 표현용 디스플레이 엔티티 무제한 스폰 | 엔티티 풀링(재사용) + 수명 강제(최대 n틱) + 전역 상한. 상한 도달 시 파티클로 강등 |
| F-P5 | **동기 청크 로드** — 경공 돌진·장거리 투사체가 미로딩 청크 진입 → 메인 스레드 정지 스파이크 | 스킬 사거리 ≤ 시뮬레이션 거리, 이동 전 청크 로드 여부 확인, 미로딩이면 벽 판정 |
| F-P6 | **접속 시 동기 DB 로드** — 로그인 스톨 | AsyncPlayerPreLogin에서 비동기 프리로드 → 입장 시엔 메모리 조회만 |

### 3.2 동시성·상호작용 (레이스 컨디션)

| # | 예측 장애 | 방어책 |
|---|-----------|--------|
| F-R1 | **더블 캐스트** — 클릭 연타/패킷 버스트로 같은 틱에 시전 요청 2회 → 쿨다운 검사를 둘 다 통과 | 쿨다운·자원의 **검사와 차감을 같은 틱, 같은 지점에서 원자적으로** (check-and-set 분리 금지). 시전 요청에 틱 스탬프 — 동일 틱 중복 요청 폐기 |
| F-R2 | **유령 대상** — 시전 완료(선딜 후) 시점에 대상이 이미 사망·텔레포트·로그아웃 | 실행 직전 **재검증 단계 의무화**: 생존/거리/시야/월드 일치 재확인, 무효면 자원 일부 환불 |
| F-R3 | **비동기 콜백의 죽은 참조** — DB 응답이 돌아왔을 때 플레이어는 이미 로그아웃 → NPE/메모리 누수 | 콜백은 Player 객체가 아니라 **UUID로 보관**, 실행 시점에 온라인 재조회. 없으면 폐기 |
| F-R4 | **세계 상태 동시 기입** — 배치 루프(비동기 계산)와 실시간 사건이 같은 세력 점수를 수정 | **단일 작성자 원칙**: 세계 상태 변경은 전부 메인 스레드 큐로 직렬화. 비동기는 계산만, 반영은 큐 제출 |
| F-R5 | **효과 중첩 순서** — 같은 틱에 걸린 버프+디버프+부상 페널티의 적용 순서가 실행마다 다름 → 재현 불가 버그 | **효과 적용 순서 명세 고정**: 부상 → 상태이상 → 버프 → 장비 (사전순 아닌 명세순). 같은 계열은 강한 것 우선, 계수는 가산 후 곱산 |
| F-R6 | **NPC 상태 경합** — 두 플레이어가 같은 틱에 같은 NPC와 상호작용 (한 명은 설득, 한 명은 기습) | NPC 상호작용에 **틱 내 선점 잠금**: 먼저 도착한 요청이 그 틱의 NPC 상태를 소유, 후속은 다음 틱에 갱신된 상태로 판정 |

### 3.3 통신·체감 품질

| # | 예측 장애 | 방어책 |
|---|-----------|--------|
| F-N1 | **핑 편차 불공정** — 카운터/패링 윈도우가 저핑 유저에게만 유리 | 서버 권위 판정 + **지연 보상 유예창**: 윈도우 판정에 ±2틱(100ms) 관용. 클라이언트 타이밍은 절대 신뢰하지 않음 |
| F-N2 | **리소스팩 적용 지연** — 팩 로딩 전 스킬 아이콘·모델 깨짐 | 팩 적용 완료 이벤트까지 스킬 사용 게이트 (로비 대기), 미적용자는 바닐라 대체 표시 |
| F-N3 | **패킷 순서 착시** — 넉백·이동 스킬 연속 적용 시 클라 위치 보간 튐 (고무줄) | 이동계 스킬에 틱당 velocity 적용 1회 상한, 연속 이동 스킬 간 최소 간격(2틱) |

## 4. 스킬 시전 파이프라인 (표준 경로)

모든 무공은 이 단일 파이프라인을 지난다 — 우회 경로 금지가 곧 버그 방어다:

```text
① 요청 수신   (클릭/단축슬롯 — 틱 스탬프 부여, 동일 틱 중복 폐기)      [F-R1]
② 검증       쿨다운·내력·상태(부상/기절)·경지 요구 — O(1) 조회
③ 원자 차감   검증 통과 즉시 같은 지점에서 쿨다운 개시 + 내력 차감        [F-R1]
④ 선딜 예약   중앙 EffectTicker에 등록 (개별 태스크 금지)              [F-P2]
⑤ 재검증     실행 직전 대상 생존·거리·월드 재확인, 무효 시 부분 환불      [F-R2]
⑥ 판정·적용   데미지/효과 — 효과 적용 순서 명세대로                     [F-R5]
⑦ 연출       파티클 예산 관리자 경유 (예산 초과 시 자동 강등)            [F-P1]
⑧ 세계 반영   소문 후보·세력 입력은 큐 제출 (일 배치 루프가 소비)         [F-R4]
```

## 5. 측정과 합격 기준 — 추측을 계측으로 바꾼다

```text
상시 계측:   spark/MSPT 프로파일링 상시 가동, 서브시스템별 틱 소요 기록
             (스킬 실행 / EffectTicker / NPC / 세계 배치)
부하 테스트: 가짜 클라이언트 봇 N명이 스킬 난사하는 시나리오를 배포 전 의무 실행
합격 기준(초기): 동시 접속 60명, 초당 시전 30회, 전투 밀집 20명 상황에서
             MSPT < 40 유지 (여유 20%), 파티클 예산 초과율 < 5%
원칙:        "체감 렉 제보 → 계측 → F-목록에 유형 추가" 루프. 추측 목록은 계속 자란다.
```

## 6. 확장 여지

```text
멀티서버 분산: 기존 BungeeCord 구성(허브/메인/문파)이 이미 수평 분산 —
             지역별 서버 분리는 세계 계층 구조(현/지역권)와 자연 정합.
세계 상태 DB: 단일 진실 원천 + 비동기 write-behind 캐시. 서버 간 공유는 DB 경유.
Folia 대비:   지역 스레딩(Folia)은 우리 '지역 단위 세계 구조'와 궁합이 좋다.
             당장은 Paper 단일 스레드로 가되, 코딩 규약을 Folia-호환으로:
             전역 가변 싱글톤 금지(룰 엔진은 이미 인스턴스 기반), 지역 상태의 소유권 명확화.
```

## 7. 요약 — 세 개의 문지기

```text
1. 파이프라인 문지기: 모든 스킬은 8단계 표준 경로만 통과 (우회 금지)
2. 예산 문지기:     파티클·엔티티·태스크에 수치 상한 (초과 시 연출 강등, 판정 불변)
3. 작성자 문지기:   게임 상태의 단일 작성자는 메인 스레드 (비동기는 계산과 큐 제출만)
```
