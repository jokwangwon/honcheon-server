# 마인크래프트 이식 타당성 검토

> 질문: "텍스트 RPG로 설계·검증한 이 시스템을 마인크래프트로 녹일 수 있는가?"
> 답: **가능하다.** 이 프로젝트의 데이터와 규칙 대부분은 엔진 불문이며,
> 저장소에는 이미 Spigot/Paper 멀티모듈 스캐폴딩(core/server-*)이 있다.
> 단, 3가지 대전환이 필요하고, 그것이 이식 작업의 본체다.

---

## 1. 이식 지도 — 시스템별 난이도

| 시스템 | MC 이식 방식 | 난이도 |
|--------|--------------|--------|
| 세력/경지/무공 카탈로그 (YAML) | 플러그인이 config/를 그대로 로드 (Bukkit YamlConfiguration 호환 포맷) | **낮음** |
| 세력 반응 점수·전이 | 백엔드 로직 그대로 Java 포팅 — 플레이어는 원래 수치를 못 보는 설계라 화면 요소 불필요 | **낮음** |
| 지역 상태 (치안/경제/민심) | 서버 상태 + 체감 변환: 치안↓ → 몹/도적 NPC 스폰율↑, 경제↓ → 상점 물가↑, 민심 → NPC 대사 톤 | 낮음~중 |
| 기연 | 히든 트리거 + **선착순 소모 — 애초에 공유 세계 전제로 설계됨.** 조건(행동 이력 태그)도 서버가 이미 추적 | 낮음~중 |
| 소문 | NPC 대사 풀 + 객잔/장터 브로드캐스트. 정확도 구간(사실적~괴담)별 대사 템플릿 | 중 |
| 판정식 | **비전투 상호작용의 서버 내부 계산으로 재사용** — 잠입 시 NPC 감지, 설득 대화 선택지 성패, 조사. 주사위는 서버가 몰래 굴린다 | 중 |
| NPC 영속성 | Citizens류 커스텀 NPC + DB. 규칙은 그대로, 문제는 콘텐츠 제작량 | 중 |
| 전투 | **패러다임 전환**: 주사위 → 실시간 액션 (README 원안: 4슬롯 스킬 + 회피/카운터/경공). 단, 수치 뼈대(능력치, 무공 위력, 내구=10+체력×2, 내력=내공×3, 협공/부상/살해 훅)는 그대로 밸런스 기반이 된다 | **높음** |
| 시간 (하루 5구간) | MC 낮밤 주기에 매핑 | 낮음 |
| 장 도약 / 유년 시작 | **패러다임 전환**: 공유 세계는 시간을 건너뛸 수 없다 → 3장 참조 | **높음** |
| LLM GM 서사 | 강등: 기본은 템플릿 대사, LLM은 NPC 자유 대화 '옵션'(비용·지연 고려) | 중 |

핵심: **YAML 설정 12종과 그 규칙이 이 프로젝트의 진짜 자산**이고, 그것들은 엔진을 가리지 않는다. 텍스트 RPG는 버려지는 프로토타입이 아니라 밸런스 시뮬레이터 + 콘텐츠 사전 검증 도구로 남는다 (PT 시리즈가 해온 일을 계속한다).

## 2. 세 가지 대전환

### 2.1 전투: 주사위 → 실시간 액션

주사위 대립 판정은 실시간 게임에 못 옮긴다. 옮기는 것은 **수치 뼈대**다:

```text
능력치 7종        → 스탯 (공격력/이속/체력/자원량/감지범위 등으로 매핑)
무기·무공 위력     → 스킬 데미지 테이블 (config/combat.yml 그대로)
내구/부상 3단계    → HP + 부상 디버프 (경상 -1 = 실제 디버프 효과)
내력             → 스킬 자원 (기존 skills.yml의 mana_cost 구조 재사용)
경지 격차 ±2/단계  → 데미지 배율
협공/기습        → 백어택·다중 타격 보정
등급제(아슬아슬)   → 카운터/패링 판정 윈도우로 재해석
살해의 대가       → 그대로 (소문·세력·관군 반응은 백엔드 로직)
```

### 2.2 시간: 장 도약 → 프롤로그 인스턴스

공유 월드에서 플레이어마다 2년을 건너뛸 수는 없다. 해법:

```text
발단의 장(유년~소년) = 1인용 인스턴스 프롤로그
  접속 → 개인 인스턴스에서 집안·발단 사건을 플레이 (PT-002의 내용)
  → 시간 도약 연출 (수련 몽타주) → 소년/약관의 몸으로 본서버(공유 세계) 입장
본서버 시간 = 자동 세계 달력 (권장 배율: 현실 1일 = 게임 15일 — training_and_time.md)
압축 성장 = 수련 상태 선언 + 자리 비움: 캐릭터는 세계의 시간을 살고
           플레이어가 건너뛴다. 오프라인 = "그로부터 삼 년 후" 몽타주.
           성장 정산은 F7 환산표 (config/training.yml) — 텍스트/MC 공용.
```

발단 사건 7종 × 집안 6종이 그대로 **개인화된 튜토리얼 분기**가 된다 — 텍스트 설계가 MC 온보딩 콘텐츠로 직역되는 지점.

### 2.3 서사: LLM GM → 템플릿 우선

MC는 서사 밀도가 낮은 대신 공간 밀도가 높다. 소문은 문장이 아니라 **객잔에서 들리는 NPC 잡담**이 되고, 지역 상태는 설명이 아니라 **거리 풍경**(순찰 병사 수, 문 닫은 상점)이 된다. LLM은 핵심 NPC 자유 대화에만 선택적으로 붙인다.

## 3. 아키텍처 — 기존 스캐폴딩 재활용

```text
core/          ← SharedUtil 자리에 룰 엔진 이식:
                 JudgmentEngine / FactionReactionEngine / RumorEngine /
                 RegionStateEngine / FortuneRegistry  (config/*.yml을 그대로 읽음)
server-main/   ← 청하현 월드 + NPC + 사건 (잘못된 원소 문파 참조 제거·재작성)
server-hub/    ← 프롤로그 인스턴스 + 캐릭터 생성 (성향/집안/발단)
server-faction/← 문파 콘텐츠 (입문 이후)
docker/, scripts/, BungeeCord 구성 → 그대로 사용
저장소: 세계 상태 DB (지역/세력/소문/NPC/기연 소모 — 단일 진실 원천)
```

**1단계 핵심 검증**: core 엔진을 Java로 포팅한 뒤, **같은 입력에 대해 tools/simulate_*.py와 동일한 출력이 나오는지 단위 테스트로 대조**한다 — 파이썬 시뮬레이터가 곧 Java 엔진의 스펙이 된다.

## 4. 단계별 로드맵

```text
0. (현재) 텍스트 룰 마무리 — F7 압축 성장 환산표, F3 세력 우호 축
1. core 룰 엔진 Java 포팅 + 시뮬레이터 대조 테스트          ← 이식의 첫 삽
2. 청하현 맵 + NPC 5종 + 지역 상태 체감 요소 (스폰율/물가/대사)
3. 무공 액션 전투 프로토타입 (4슬롯 스킬, 내구/내력, 문파 무공 2~3종)
4. 프롤로그 인스턴스 (집안×발단 온보딩)
5. 기연·사건·소문 브로드캐스트 → 시즌 운영
```

## 5. 리스크 정직하게

```text
- 콘텐츠 제작량: 텍스트에선 문장 한 줄인 것이 MC에선 맵·모델·대사 풀이다.
  청하현 하나를 제대로 만드는 것이 선결 과제 (범위를 넓히지 말 것).
- 액션 전투의 손맛: 수치 밸런스와 별개로 타격감·이펙트는 순수 추가 작업.
- 판정의 비가시성: 텍스트에선 서사로 설명되던 성패가 MC에선 연출로 보여야 한다
  (설득 실패 = NPC가 등을 돌리는 애니메이션 등).
- 솔로 개발 규모: 2~3단계부터는 리소스팩/빌드 등 비프로그래밍 작업 비중이 커진다.
```

## 6. 결론

**가능하고, 설계 자산의 손실이 거의 없다.** 세계 반응 루프(소문·세력·지역·기연)는 백엔드 로직이라 그대로 옮겨지고 — 오히려 이 부분이 "살아있는 무협 서버"라는 차별점의 본체다. 전투와 시간만 MC 문법(실시간 액션, 프롤로그 인스턴스)으로 번역하면 된다. 권장 순서는 0→1: 텍스트 룰의 남은 빈칸을 채운 뒤, core 엔진 포팅부터 시작하는 것.
