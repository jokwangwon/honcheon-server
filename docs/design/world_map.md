# 세계 지도 (世界地圖)

> 기계 판독본: `config/world_map.yml`
> 판독기: `server-mvt/src/main/java/com/honcheon/mvt/WorldMap.java`
> 월드 생성: `scripts/new_world.sh`

---

## 0. 이 문서가 존재하는 이유

등록제(登錄制)로 세계를 지어 왔다. 세력도, NPC도, 장소도, 물가도 전부 등록부에 있다.
**그런데 좌표만 등록부 밖에 있었다.** 그래서 두 가지가 깨져 있었다.

**① 마을이 이사를 다녔다.**
`/혼천 조성`은 **친 자리에** 마을을 세웠다. 플레이어가 물가·저지대에 서서 치면 마을이 통째로 그리로 갔다.
실제로 사고가 났다 — 물가에 서서 조성했더니 폐사당 후보 12곳이 **전부 물**이었다.

**② 봇과 마인크래프트가 다른 세계를 말했다.**
봇의 `/혼천 출행 화산`은 `time.yml`의 「지역권 이동 3~7일」을 굴려 여정 기간을 정한다.
그런데 그 3~7일은 **지도상 거리와 아무 관계가 없었다.** 화산이 어디 있는지 아무도 몰랐기 때문이다.

이 문서와 `config/world_map.yml`이 그 둘을 하나로 묶는다.

> **좌표가 곧 거리이고, 거리가 곧 시간이다.**

## 1. 축척 — 1블록 = 1미터. 실지리(實地理) 1:1

### 결정

| 항목 | 값 |
|---|---|
| **축척** | **1블록 = 1미터** (1:1) |
| 투영 | 등거리 원통 도법(equirectangular), 표준위도 32°N |
| 원점 | **청하현 광장 중심 = 월드 (0, ?, 0)** |
| 청하현의 지리적 위치 | 북위 34.33° / 동경 108.55° — 섬서 관중 평야, 함양 서쪽 |
| 축 | x = 동(+)/서(-), z = 남(+)/**북(-)** — 마인크래프트 규약 |
| 세계 범위 | x `[-1,940,000 … +1,380,200]` / z `[-1,069,300 … +1,580,100]` |
| 마인크래프트 한계 | ±29,999,984 — **한계의 11%만 쓴다** |

변환식:

```
x = (경도 - 108.55) × 94,406      # 94,406 = 111,320 × cos(32°)
z = (34.33 - 위도) × 110,574
```

### 왜 축소하지 않는가 — 근거 넷

**① 큰 좌표는 공짜다.**
마인크래프트는 **방문한 청크만 생성한다.** 좌표가 ±194만이어도 그 사이의 빈 공간은 **1바이트도 안 든다.**
디스크 비용은 실제로 지은 곳에만 붙는다 (§8 디스크 예산).

**② 축소는 되돌릴 수 없다.**
지도는 되돌리기가 **가장 비싼 층**이다. 좁게 잡으면 나중에 세가·문파·세력이 들어올 자리가 없어 전부 다시 짜야 한다.
지금 실제 크기로 잡으면 영원히 안 고쳐도 된다.

**③ 원거리는 걷지 않는다.**
봇의 `/혼천 출행`은 이미 **오프스크린 여정**이다 (기간·여비를 치르고 도착한다).
마인크래프트에서도 같다 — 원거리는 여정이 건넌다(텔레포트 + 시간·여비). **거리가 커도 게임은 안 죽는다.**

**④ 실지리가 서사를 이미 쓰고 있다.**
등록부가 이미 지리를 말하고 있었다. 좌표를 실지리에 맞추자 **원문이 그대로 성립했다**:

| 등록부 원문 | 지도가 내놓은 답 |
|---|---|
| `map_spec` — "북쪽으로 갈수록 산세, 남서쪽에 강" | 청하현 = 관중 평야. 북쪽에 북산(北山), 남서쪽에 위수(渭水) ✔ |
| `faction_entry_routes` — "청하현에서 닿는 유일한 구파" | 화산까지 **5일** — 봇의 3~7일 범위 한가운데 ✔ |
| `faction_entry_routes` — "청하현 → 화산(섬서 화음)" | 둘 다 섬서. 직선 146 km ✔ |
| `faction_entry_routes` — 당가는 "화산의 **수 배**" | 성도까지 **26일** = 화산(5일)의 5.2배 ✔ |
| `faction_entry_routes` — "거리 자체가 게이트다" | 촉도난(蜀道難). road_factor 1.8 — 진령을 넘어야 한다 ✔ |

**청하현을 관중 평야에 놓자 등록부가 저절로 맞았다.** 지도를 등록부에 맞춘 게 아니라, 등록부가 이미 이 지도를 말하고 있었다.

## 2. 거리 ↔ 시간 환산

### 뿌리 하나

> **하루 도보 = 40 km = 40,000 블록**

전근대 보행 여행의 표준(하루 10시간 × 4 km/h)이다. **여기서 나머지가 전부 파생된다 — 새 수치를 발명하지 않는다.**

### 파생

| 단위 | 블록 | 근거 |
|---|---|---|
| 1 구간 (segment) | **8,000** | `time.yml segments_per_day: 5` → 40,000 ÷ 5 |
| 1 도보일 | **40,000** | 위 |
| 인접 현 (1~2일) | 40,000 ~ 80,000 | `time.yml 인접_현_여행` |
| 지역권 이동 (3~7일) | 120,000 ~ 280,000 | `time.yml 지역권_이동` — **도로거리 기준** |

### 여정일 계산식

```
여정일 = max(1, round( 직선거리(블록) × road_factor / 40,000 ))
```

`road_factor` — **어느 길로 가느냐가 여정을 정한다.** 길은 곧게 나 있지 않다.

| 길 | factor | 뜻 |
|---|---|---|
| 수로 | **0.85** | 배는 빠르다 — 굽어도 걷는 것보다 낫다 |
| 관도(官道) | 1.15 | 관이 닦은 큰길 |
| 상로(商路) | 1.20 | 상단의 길 |
| 평지 | 1.25 | 길 없는 평야 |
| 구릉 | 1.40 | |
| 산길 | 1.60 | 고개를 넘는다 |
| 험산 | **1.80** | 촉도난 — 사천으로 드는 길 |
| 새외 | 2.00 | 사막·설선. 길이랄 것이 없다 |

### 검산 — `time.yml`과의 정합

| `time.yml` 규칙 | 지도의 답 | 판정 |
|---|---|---|
| `현_내_이동: segment` (1구간 = 8,000블록) | 청하현 조성 무대 반경 1,500. 성문↔나루↔산길 전부 1구간 안 | ✔ |
| `인접_현_여행: 1~2일` | 40~80 km — 실제 현(縣) 간격 그대로 | ✔ |
| `지역권_이동: 3~7일` | **청하현→화산 도로 220 km = 5일.** 3~7의 한가운데 | ✔ **봇 무수정** |
| — | 섬서→사천 **26일**, 섬서→새외 **111일** | ✘ **등급이 없다** |

## 3. ★ 봇 정합 — 무엇을 고치고 무엇을 안 고치는가

### 고치지 않아도 되는 것: 화산 (`/혼천 출행 화산`)

봇은 `Rules.regionTravelDays()`로 `time.yml`의 `지역권_이동: "3~7일"`을 읽어 `3 + dice(0..4)`를 굴린다.

- 지도상 청하현 → 화산 = **직선 146 km × 1.5(산길) = 도로 220 km ÷ 40 = 5.0일**
- 봇의 주사위 범위 3~7의 **정확히 한가운데**, 기댓값도 5

> **봇을 한 줄도 안 고쳐도 된다.** 3~7일의 산포는 이제 "지도상 5일 ± 도로 사정"으로 **읽힌다.**
> 우연히 맞은 게 아니다 — 청하현 위치를 **그 범위에 맞도록** 역산해서 잡았다 (§1 근거 ④).

### 고쳐야 하는 것: `time.yml`에 등급이 없다

등록된 여정 중 **`3~7일` 상한을 넘는 것들**이 있는데, `time.yml`에 해당 등급이 없다:

- 섬서 → 사천(당가) = **26일** — 그런데 `faction_entry_routes`는 이미 *"화산의 수 배"*라고 써 놨다. **3~7일 상한으로는 그 문장을 지킬 수 없다.**
- 섬서 → 새외(마교) = **111일**

**제안 (config/time.yml — 다른 에이전트 소유이므로 조각만 제안):**

```yaml
# config/time.yml  action_costs 에 두 줄 추가 (기존 줄은 건드리지 않는다)
action_costs:
  지역권_횡단: "8~40일 (multi_day) — 섬서→사천 26일, 섬서→강남 25일. 정확한 일수는 world_map.yml"
  새외_출경: "40일+ (multi_day) — 중원 밖. world_map.yml travel 계산식이 지배한다"
```

**최종 일수의 원천은 `world_map.yml`의 좌표 + `travel.formula`다.** `time.yml`은 등급 라벨만 준다.
봇이 목적지를 화산 말고도 열게 되는 날, `Rules`는 `world_map.yml`의 `places.<id>.travel.days`를 읽으면 된다.

## 4. 이중 이동 — 축척은 하나, **이동 수단이 둘**

축척을 둘로 쪼개지 않았다 (그러면 세계가 두 개가 된다). 축척은 1:1 하나이고, **이동 수단**이 둘이다.

| | 도보 | 여정 |
|---|---|---|
| 범위 | **≤ 8,000블록** (1구간) | > 8,000블록 |
| 수단 | 실제로 걷는다 — 다리로 | `/혼천 출행` — 텔레포트 + 기간·여비 |
| 무대 | 청하현 성곽·장터·북쪽 산길·흑수나루·폐사당 | 화산·당가·경사… |
| 비용 | 없음 (시간은 구간으로) | 여정일 × 하루치 노자 |

**청하현 무대**는 반경 1,500블록의 1:1 공간이다. 성문에서 폐사당까지 약 110블록 = **도보 30초.** 걸을 만하다.
그 밖은 아무도 걷지 않는다 — 화산까지 145,400블록을 걸으면 2시간 반이지만, **여정이 건넌다.**

> ★ 이것이 **큰 좌표가 게임을 죽이지 않는 이유**다.

**무대 압축**: 청하현의 실제 현역(縣域)은 반경 20 km지만, **조성하는 것은 현성과 그 주변 1.5 km뿐**이다.
나머지는 자연 지형이 그대로 현역을 대신한다 — 들과 산이 곧 현이다.

## 7. 관(官) — 무림과 다른 층위

`factions.yml`에 관군·현령이 등록돼 있는데 **지도엔 관아 하나 없었고, 황실은 아예 없었다.**

### 7.2 관무불가침(官武不可侵) — 세계의 규칙

**규칙**
- **관은 무림에 간섭하지 않는다** — 비무·문파 다툼·강호의 원한을 관이 다루지 않는다.
- **무림은 관을 건드리지 않는다** — 관리를 죽이거나 관아를 치면 **강호 전체가 적이 된다.**

**왜 유지되는가**

> ★ **관은 이길 수 있으나 값이 비싸고, 무림은 이겨도 얻을 게 없다.**

- **관의 계산**: 관은 무림을 *못 이기는 게 아니라 안 이긴다.* 성군·금군을 내면 잡는다 — 그러나 세금이 안 걷히고, 상로가 끊기고, 다른 문파가 결집한다. **강호를 치는 것은 나라를 흔드는 일이다.**
- **무림의 계산**: 현령을 죽이면 지부가 오고, 지부를 죽이면 성군이 오고, 성군을 이기면 금군이 온다. 그 끝은 멸문이다. **이겨도 진다.**
- ★ **그리고 강호가 스스로 단속한다.** 관을 건드린 자를 **정파가 먼저 친다.** 불가침을 지키는 것은 관이 아니라 무림이다. **그것이 이 규칙이 살아 있는 진짜 이유다.**

**`faction_reaction.yml` 접합** (반응 단계 0~6)

| 행위 | 관군 반응 | 비고 |
|---|---|---|
| 관리 살해 | **6 (토벌)** | 협상 없음 |
| 관아 습격 | **6 (토벌)** | |
| 관물 강탈 | 5 (직접 개입) | 표국이 관물을 잃어도 여기 걸린다 |
| 포쾌 폭행 | 4 | |
| 수배자 은닉 | 3 | |
| **정파의 2차 반응** | **+2** | ★ **관을 건드리면 정파가 먼저 온다** |

**예외** (원래부터 불가침 밖)
- 도적·마교·혈교는 보호받지 않는다 (강호의 일원이 아니다) — 토벌 대상
- 관이 무림인을 **개인 자격으로** 고용하는 것은 위반이 아니다 (포두 박호가 그렇다)
- **표국의 관물 호송** — 관과 무림이 합법적으로 만나는 **유일한 접점**

### 7.3 ★ 불가침이 깨지는 순간

> **불가침은 법이 아니라 균형이다. 균형은 한쪽이 이익을 다시 계산하면 깨진다.**

**관이 먼저 깬다**

| 파열 | 무대 | 표층 / 진상 | 플레이어의 자리 |
|---|---|---|---|
| **부패 결탁** | **녹림 중채** | *"북로 도적이 늘었는데 관군이 출동하지 않는다"* / 지부가 통행세 몫을 받는다 | 증거 확보·상급 고발 / 지부 협박·거래 / 정파 보고 / **녹림 합류** / 침묵의 대가 수령 |
| **마교 잠식** | 낙양 잠복지 · 장안 | *"관군이 엉뚱한 문파를 친다. 수배 명단이 이상하다"* / ★ **마교는 관을 이기려 하지 않는다 — 관이 무림을 치게 만든다** | 첩자 색출 / 오인 토벌 가담 / 문파 경고 |
| **역모 혐의** | 경사 · 대상 문파 | 황실이 문파를 역모로 지목 — 봉문(封門) 또는 **멸문(滅門)** 칙령. 성군 + 금군. **문파는 이길 수 없다** | 칙령 집행에 가담(관군 루트) / 문파와 함께 싸운다(멸문) / 피신시킨다(지하 문파) / **증거를 뒤집는다** — 가장 어렵다: 경사에 닿아야 한다 |

> ★ **마교 잠식이 마교 루트의 종착점이다. 마교는 대군을 이끌고 오지 않는다 — 대군을 빌린다.**

**무림이 먼저 깬다**

| 파열 | 결과 |
|---|---|
| **관리 살해** | 현상수배 → ① 현 포쾌 추격(도망칠 수 있다) → ② 부병 + **정파 협객**(강호의 자기단속) → ③ 성군 개입 · 소속 문파에 공문 — **문파가 당신을 버린다** → ④ **봉문 — 당신 때문에.**<br>탈출로: 새외 도주 / 사파 합류 / 하오문 신분 세탁 / **자수 → 유배** / 관에 공을 세워 사면<br>★ **진짜 대가는 관이 아니라 강호다** |
| **관아 습격** | 불가침의 완전 파기. 성군 토벌. **강호는 돕지 않는다.** — 녹림 총채가 이 선을 넘으면 대토벌 |
| **관물 상실** | 표국주 문책 — 신용 붕괴. ★ **진철산(청하 표국)의 파멸 시나리오.** 가장 작은 파열이라 **가장 먼저 쓸 수 있다** |

**깨진 뒤의 세계**

- **강호 연합** — *관이 하나를 치면 다음은 우리다.* ★ **무림맹의 탄생 조건**
- **강호 분열** — *남의 멸문은 나의 공적이다.* ★ **정파가 정파를 친다**
- **정해져 있지 않다.** 지목된 문파의 명성 + 관의 명분(증거) + **플레이어의 개입**이 정한다.

## 8. 조성 · 시드 · 디스크

### 8.1 지금 짓는 것

**청하현 일대뿐이다.** 나머지는 **좌표·성격·조건만 등록** — 그것이 목적이다.

```
/혼천 세계조성     → 청하현이 원점 (0, ?, 0) 에 선다 (친 자리가 아니라 등록된 자리에)
                      폐사당 · 북쪽 산길 사냥터 · 흑수나루는 CheonghaBuilder 가 같이 짓는다
/혼천 조성          → 그대로 남는다 (디버그용 — 친 자리/좌표 지정)
```

### 8.2 지형 적합성 검사

각 장소는 **요구 지형**을 갖는다 (청하현=평지 · 흑수나루=물가 · 화산=험산 · 폐사당=마른 땅).
`WorldMap.fit()`이 그 좌표를 **실측**한다 — 반경 48블록을 6칸 격자로 289열 표본:

- `naturalGroundY` — 물·용암을 만나면 그 열은 '젖었다'
  (★ `getHighestBlockYAt`은 **물도 최상단으로 센다.** 그것만 쓰면 호수를 땅으로 읽는다 — v6.3이 실제로 그 버그로 폐사당을 물에 지었다)
- `water_pct` / `relief` / `mean_y` / `max_depth` / `basin` / 바이옴 적중률
- **점수 0~100.** 이분법이 아니다 — 완벽한 자리는 없으니 *어느 자리가 덜 나쁜가*를 잰다. 70점 이상이면 합격

**부적합이면 결정론 인근 탐색**: 링(64→1024) × 8방위를 **상수 순서**로 돌아 첫 합격지. 전부 실격이면 최고점 자리.
**난수 없음** — `CheonghaBuilder.SHRINE_SITES`/`FERRY_SITES`가 쓰는 바로 그 방식이다.
최대 1,024블록까지만 민다 — **좌표는 흔들려도 시간표는 안 흔들린다** (여정 일수에 0.03일 영향).

### 8.3 시드 탐색

```
/혼천 시드검사 20260710 12345 99999 [원거리]
```

시드마다 임시 월드를 만들어 **등록 좌표의 지형을 실측하고 점수로 보고**한 뒤 지운다.
기본 대상 = **지금 조성하는 것**: 청하현(평지) · 북쪽 산길(산) · 흑수나루(물가) · 폐사당(마른 땅) · 산길 도적(산).

> ★ **이 넷이 과거에 실제로 깨졌던 자리다.** 시드 검사는 그 사고를 **미리** 막는 도구다.

`원거리`를 붙이면 엿새 안 지역(화산·녹림 소채·진령 심산…)까지 재지만 수십 초 걸린다.

완벽히 맞는 시드는 없다. **점수로 고른다** — 어느 시드가 덜 나쁜가.

```
scripts/new_world.sh <최고점 시드>       # 전용 월드 honcheon 생성
```

### 8.4 디스크 예산 — **큰 좌표는 공짜다**

| | 생성 청크 | 디스크 |
|---|---|---|
| **지금** (청하현 일대, 반경 ~170블록) | 약 **484** 청크 | **10~25 MB** |
| **전부 다 지었을 때** (30여 곳 × 반경 500) | 약 **119,000** 청크 | **2~5 GB** |

> ★ 좌표가 ±194만이어도 **그 사이의 빈 공간은 1바이트도 안 든다.** 방문한 청크만 생성된다.
> 월드 보더는 설정하지 않는다 — 여정이 텔레포트이므로 플레이어가 빈 공간을 걸어 건널 일이 없다.

### 시드검사가 서버를 죽이던 문제 (수복)
검사는 후보 좌표를 훑으며 지형을 표본하는데, 그때 **청크가 동기 생성**된다. 구판은 그걸 한 틱 안에서
다 했다 — 시드 5개에 4,380청크였고, 워치독이 "메인 스레드 60초 무응답"으로 서버를 죽였다.
지형을 보려면 지형을 만들어야 한다(그 값은 못 깎는다). 깎을 수 있는 건 **한 틱에 얼마나 하냐**다:
후보를 하나씩 꺼내 쓰고 틱 예산(20ms)이 다하면 손을 뗀다. 서버는 검사 내내 계속 돈다.
결과는 로그에도 남긴다 — 콘솔(RCON)로 부르면 명령이 끝난 뒤의 말은 사라지므로.

## 원거리 조성기 (2026-07-12) — 등록만 된 곳을 집으로

지도에 33곳이 좌표를 갖고 있는데 **선 것은 청하현과 산길 도적뿐**이었다(나머지는 `build: later`).
등록만 되고 서지 않은 곳은 여행의 목적지가 아니라 문서의 줄이다.

### 원형(archetype) 방식
실지리 1:1(1블록 = 1m)이라 33곳을 손으로 지을 수 없다. 등록부가 세력·등급·건축을 적어 두었으니
조성기가 그것을 읽어 원형을 고른다. 첫 원형은 **산채(寨)** — 녹림.

* `/혼천 지역조성 <id>` (콘솔 가능) · `/혼천 조감 <id>` (그 지역 조감도 PNG)
* 부지는 지도가 고른다 — 등록 좌표에서 지형 적합성을 재고, 안 맞으면 링(64~1024칸)을 돌아 첫 합격지.
  녹림 소채는 등록 좌표에서 64칸 이동, 지형 점수 **100**.

### 산채의 문법 — 청하현과 다른 점이 곧 도적의 성격이다
* **담이 아니라 목책** — 돌을 쌓지 않는다. 통나무 5단 + 뾰족한 끝 + 안쪽 순찰 마루.
  버리고 떠날 집에 석공을 부르지 않는다.
* **완전한 원이 아니다** — 반듯한 원은 도면이다. 도적에겐 도면이 없다 (12방위 좌표 해시로 반경 ±2 흔듦).
* **마당이 중심** — 관아는 정청이 중심이고 산채는 **모닥불**이 중심이다. 나눠 먹는 자리가 그 집의 정체다.
  채문에서 모닥불까지 동선을 비운다: 아무도 그 앞을 막지 않는다.
* **초가는 청하현의 어휘 그대로** — 짚으로 통째 덮으면 노란 덩어리가 되어 수묵이 깨진다.
  초가는 "짚으로 덮은 지붕"이 아니라 **너와 지붕에 짚을 얹은 것**이다(경사면 계단의 점치환).
  도적의 초가는 더 성글다: 청하현 25% 에 비해 40%.
* **두목 막사의 시렁** — 벽에 걸린 것이 그 집의 정체다. 훔친 병기, 그중엔 표국의 정련 검도 있다(1.21.11 선반).

### 조감이 잡은 것 (루프 3사이클)
1. 막사 넷이 마당을 다 먹어 모닥불이 묻혔고, 두목 막사가 채문 앞을 막았다 → 집을 벽으로 물리고 가운데를 비웠다.
2. 재조성이 옛 집을 안 걷어 유령 지붕이 새 마당 위에 떠 있었다 → 담장 안은 지면 위를 전부 걷는다.
3. 목책이 낮아 '흙 테두리'로 읽혔다 → 5단으로 세우고 반경을 흔들었다. 마당이 휑했다 → 훈련 말뚝·장작더미·짐수레.

### 서버를 멈추던 병 (수복)
원거리 조성은 **20km 밖의 땅을 처음 만드는 일**이다. 부지 탐색이 후보마다 96×96 창을 표본하는데,
그 표본이 곧 청크 생성이다 — 메인 스레드에서 하면 서버가 15~20초 멈춘다(워치독이 스레드 덤프를 뜬다).
처방은 시드검사와 같다:
* 부지 탐색은 **틱을 나눠 먹는다**(SiteProbe, 예산 20ms/틱).
* 후보의 땅은 **비동기로 싣는다**(`getChunkAtAsync`) — 예산은 후보 *사이*에서만 물리므로,
  후보 하나가 통째로 10초를 먹으면 소용이 없다. 생성은 워커 스레드가 하고 메인은 읽기만 한다.
* 같은 처방을 `/혼천 세계조성`(청하현)에도 적용했다.
결과: 지역조성 중 워치독 경고 0회 (조성 자체의 블록 쓰기 한 틱은 여전히 부채 — CheonghaBuilder 90만 회).
