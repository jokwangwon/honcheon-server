# 화산파 리소스팩 트랙 — 설계 (2026-08-04)

> 사용자 확정: 「레퍼런스엔 바닐라에 없는 블록·디자인이 있다 — 리소스팩을 별도 생성해
> 정확성을 올린다」. 기존 팩 문법·파이프라인 조사 결과를 바탕으로 한 절차서.

## ★★ 전제 교정 (사용자 확정 2026-08-04) — 팩 트랙은 보류

> 「**곡선 처마는 불허.** 레퍼런스 사진을 자세히 봐도 그렇고, 그냥 마인크래프트 블록으로
> **반블록·계단블록·블록을 혼합해 기와처럼 보이게** 했지, 리소스팩을 써서 기와를 표현하진
> 않았다.」

이 관찰이 트랙의 전제를 뒤집는다:

- **레퍼런스 렌더 자체가 바닐라다.** 그렇다면 우리가 도달 못 할 이유가 없고, 남은 격차는
  팩의 문제가 아니라 **블록 조합 기술의 문제**다.
- 따라서 **팩 트랙은 보류**한다. 아래 §0~§6 은 나중에 정말 필요해질 때를 위한 조사 결과로
  남긴다 (등록부·절차·B-195 회피는 그때도 유효하다).
- **BetterModel(진짜 곡선 처마)은 불허** — 결정 종료. 라이브 JDK 승격 안건도 함께 닫는다.

### 대신 할 일 — 「블록으로 기와처럼」

레퍼런스가 쓴 것은 반블록·계단·풀블록의 **혼합 리듬**이다. 우리가 지금 쓰는 「계단 한 줄 +
반블록 처마 끝」보다 켜가 얕다. 다음 개선의 표적:
- 지붕면을 계단 일색으로 깔지 말고 **계단/반블록/풀블록을 번갈아** 놓아 기와골의 요철을 만든다
- 처마 끝은 반블록 한 겹이 아니라 **계단 뒤집기 + 반블록**으로 두 켜
- 용마루·내림마루는 풀블록 위 계단 마감으로 두께를 준다
- 이 문법을 실측으로 잡는다 — 레퍼런스 지붕을 확대해 **한 칸씩 무슨 블록인지 판독**

---

## 0. 팩이 할 수 있는 것과 없는 것 (먼저 못 박는다)

- **할 수 있다**: 바닐라 블록의 **겉모습**(텍스처·모델 형태)을 갈아입히기.
- **못 한다**: 새 블록 종류 추가 (노트블록 blockstate 트릭은 `texture_layer_design.md §3.3`
  에서 **불채택** 확정 · `resourcepack_design.yml:178` `adopted: false`).
- **못 한다**: 현판 글자·궤 등 **블록엔티티의 형태 교체** — entity 텍스처까지가 끝.
- **한계**: MC 모델 원소는 직육면체뿐 → **진짜 곡선 처마는 불가**, 45° 평면 근사가 현행 상한
  (`resourcepack_design.yml:983` 「직육면체_한계」).

## 1. 택할 방식 — 두 계열만

| 계열 | 무엇 | 모듈 | 왜 |
|---|---|---|---|
| **C. 모델 경로 재정의** | `assets/minecraft/models/block/*.json` 만 갈고 blockstate 무접촉 | `tools/respack/hanok.py` | 바닐라 회전표를 그대로 타 **빠질 variant 가 구조적으로 없다** · 컬링 안전 |
| **D. 텍스처 징발** | `assets/minecraft/textures/block/` 치환 | `tools/respack/blocks.py` | 단청·기와 결·회백 석재의 본체 |

★ **B 계열(blockstate 재정의 — furniture.py)은 새 자산에 쓰지 않는다** — B-195(유령 벽)가
미결이기 때문이다. 불투명 큐브를 속 빈 형태로 갈아치우면 이웃 벽이 뚫린다.

**컬링 계약** (`resourcepack_design.yml:975`): 바닐라가 cullface 를 붙이던 「가득 찬 면」
(계단 밑판·뒷판, 반블록 밑판, 풀블록 여섯 면)은 재정의 후에도 **같은 자리를 가득 채운다**.
장식은 표면 위 **≤2px 돋움**까지 (`침범_한계`).

## 2. ★가장 큰 제약 — 팩은 전역이다

화산 단청을 어떤 바닐라 블록에 얹으면 **세계 모든 그 블록**이 단청이 된다.
→ 화산 전용 자산은 **화산에서만 쓰이는 블록 종**을 골라야 한다.
→ 그러므로 **자산 목록보다 「어떤 블록을 징발할 것인가」가 먼저 정해져야 한다.**
현재 캠퍼스가 쓰는 블록 중 다른 지역에서 안 쓰는 것을 골라 배정하는 작업이 1단계다.

## 3. 후보 자산 (격차 재점검 3 항목에 대응)

| 자산 | 격차 | 방식 | 비고 |
|---|---|---|---|
| 기와 결 (흑와) | ③ 재료 대비 | D 텍스처 | 이미 「흑와」 채널 있음 — 화산용 변주 검토 |
| **단청** (기둥·보 문양) | ③ | D 텍스처 | 적목 계열 징발 — 전역 영향 최소인 종을 골라야 |
| 격자 창호 | ① 디테일 밀도 | C 모델 + D 텍스처 | 판유리·뚜껑문 계열 |
| 공포 부재 | ① | C 모델 | 계단·반블록 위 ≤2px 돋움 |
| 회백 석재 (따뜻한) | ③ | D 텍스처 | 축대·기단 계열 |
| 처마 곡선 근사 | ② 실루엣 | C 모델 | 45° 평면까지가 상한 |
| **진짜 곡선 처마** | ② | **BetterModel** | ★별건 결정 — §4 |

## 4. 【사용자 결정 필요】 BetterModel (진짜 곡선 처마)

디스플레이 엔티티는 임의 회전이 되어 곡선 처마가 가능하다. 그러나 전제가 셋:
1. **라이브 JDK 21 → 25 승격** (BetterModel 3.x 가 class 69)
2. 라이브 플러그인에 BetterModel 도입 (지금은 **테스트 서버에만** 있다)
3. **성능 계약 재협상** — 패킷 발행이라 기존 엔티티 예산에 안 잡히지만, 건물마다 상시
   디스플레이는 별개 문제다

→ 팩 트랙과 분리해 별도 결정으로 올린다. **당분간은 45° 평면 근사가 상한.**

## 5. 절차 6단계 (자산 하나를 넣을 때마다)

1. **등록부에 먼저 적는다** — `config/resourcepack_design.yml`
   · 텍스처 → `block_channels.징발` (629~): `무협_자산`/`징발_판정`/`팩없음_폴백` 3칸 필수
   · 모델 → **`건축_형태층.재정의`** (968~) 등재. **미등록 = 즉흥 재형태 = 삭제 대상**
2. **빌더 모듈에 반영** — 형태는 `tools/respack/hanok.py` (화산 어휘가 크면
   `tools/respack/hwasan.py` 신설 + `__init__.py` 에 import·호출 추가) · 텍스처는 `blocks.py`
3. **B-195 회피** — 베이스는 비폐색 블록 우선 · 풀 큐브면 여섯 면 가득 · 장식 ≤2px
4. **굽는다** — `python3 tools/build_resourcepack.py` (결정론: 두 번 구워 같은 바이트)
5. **잰다** — `tools/texture_audit.py` · `tools/model_key_audit.py`
6. **배포** — `bash scripts/publish_pack.sh` (굽기+비밀 검사+릴리스 덮어쓰기) → 서버 재기동 시
   `PackPusher` 가 sha1 을 실물에서 재측정. `config/resource_pack.yml` 은 손댈 것 없다.

## 6. 첫 회차 제안

**블록 징발 배정표**부터 만든다 (§2 — 이게 안 되면 나머지가 세계를 오염시킨다):
캠퍼스가 쓰는 블록을 세고, 각 블록이 다른 지역에서도 쓰이는지 조사해, 화산 전용으로
징발 가능한 종을 가려낸다. 그 표가 서면 자산 제작은 기계적이다.
