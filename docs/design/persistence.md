# 영속화 — 저장이 곧 세계다 (G5 해소)

> 결정: **SQLite 단일 파일 + 단일 작성자(봇 프로세스) + WAL**.
> 동접 60·자정 배치 규모에 충분하고 운영 비용 0. 스케일 문제는 스케일이 생긴 뒤에.
> 스키마 실체: `db/schema.sql` (이 문서는 원칙과 지도)

---

## 1. 원칙

```text
단일 작성자   봇 프로세스만 쓴다 (MC 서버는 봇의 API 경유 — performance.yml 단일 작성자 원칙 승계)
이벤트 소싱 겸용  상태 테이블(빠른 조회) + 이벤트 로그(append-only 진실) 이중 기록
              — 개입 기록·회수 루프·감사·사망률 집계(G10)가 전부 로그에서 나온다
캐릭터 귀속    화후·마크·favor는 캐릭터의 것 (계정의 것이 아니다 — 죽음 규칙 정합)
JSON 컬럼 허용  v1 단순화 — 시트·원장은 JSON, 조회 축(위치·상태·소유)만 컬럼으로
백업        일 1회 파일 스냅샷 (자정 배치 직후) + WAL 체크포인트
```

## 2. 테이블 지도 — 3군 11테이블

```text
[캐릭터군]
characters      시트·화후 원장·전낭·마크·위치 — 플레이어의 전부 (사망 시 status 전이)
character_bank  전장 예치 (지점·전표 — 상속 규칙의 대상)

[세계군]
world_meta      세계 달력 현재일, 시즌 — 단일 행 키밸류
regions         치안/경제/민심 상태 (region_state 수치의 저장소)
npcs            등급·스케줄 상태·lifepath 궤적·favor — 생애 시뮬의 대상
rumors          내용·강도·정확도·망·감쇠 상태 (소문 엔진의 저장소)
faction_standing 세력 × 캐릭터: 주목·favor 2축
price_events    품목 시세 이벤트 (델타·감쇠)
registry        ★세계 유일 등록제의 실체 — 기연·신병·명명(오의/명병/별호)·세계급 사건
                UNIQUE 제약이 곧 '세계에 하나' 규칙의 집행자

[기록군]
events          append-only 이벤트 로그 — 판정·거래·마크·개입·사망 (진실의 원장)
scenes          장면(스레드) 상태·참가자 — 동시성 잠금 단위 (G8의 저장소)
```

## 3. 쓰기 규율

```text
턴 커밋      판정 1턴 = 트랜잭션 1개 (원장 갱신 + 이벤트 로그 — 원자적)
자정 배치    소문 감쇠·지역 회복·시세 감쇠 = 단일 트랜잭션 / 계절 배치(NPC 생애) 동일
등록 경합    registry 등록은 UNIQUE 충돌로 선착순 판정 — 기연 race의 DB 수준 해결
MC 연동     MC 서버는 봇의 로컬 API로 읽고 쓴다 (원장 이중화 금지 — 공용 원장 하나)
```

## 4. 이 스키마가 이미 지탱하는 기존 규칙

개입 기록·시효(F21) → events / 세계 유일 명명 → registry UNIQUE / 사망률 관측(죽음 설계)
→ events 집계 / 피의 장부·상속 → events + character_bank / 장면 잠금(G8) → scenes.
**새 규칙 없이 기존 규칙의 저장처를 정한 것** — 설계와 저장이 1:1이다.
