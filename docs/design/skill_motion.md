# 무공의 모션 — 조작에서 시전까지 (MVT 배선)

> 정본: `docs/design/mc_action_mapping.md` (조작 ↔ 행동 매핑) · `skill_mechanics.md` · `qi_manifestation.md`
> 구현: `server-mvt/.../SkillEngine.java` (규칙) · `SkillListener.java` (모션) · `SkillHud.java` (HUD·파티클 예산)
> 원칙: **config 가 단일 진실 원천**. 이 세 파일에 있는 수치는 파티클 개수와 사운드 이름뿐이다.

MVT에는 마을만 있었다. 무공을 쓸 수단이 없었다 — 이 문서는 그 손을 붙인다.

## 1. 조작 매핑

| 입력 | 나가는 것 | 코스트 | 근거 |
|---|---|---|---|
| **좌클릭** (검·도 소지, 대상 타격) | 육합검 콤보 1타 → 2타 → 3타 | 초식은 **0** — 내력을 먹는 것은 격이다 | skill_mechanics `yukhap_geom.combo` (cost 0) · combat.yml `internal_energy.skill_cost_rule` |
| **좌클릭** (맨손) | 태조장권 3타 — **3타에 발경이 실려 태어난다** | 0 · 0 · **내력 1** | skill_mechanics `taejo_jangkwon.qi_rider {step: 3, 격: 발경, cost: 1}` |
| **좌클릭** (허공) | 헛손질 — 콤보는 진행된다 | 동일 | 콤보 체인의 입력 유예(10틱)는 명중 여부와 무관해야 손에 붙는다 |
| **Shift + 우클릭** | **태세 순환** — 외공 → 발경 → 검기 → 검강 → **호신강기** → 외공 | 발경 **타격마다 1** / 검기·검강 유지 1·2 / 호신강기 **전개 4 + 유지 2** | qi_manifestation `forms.두름`·`forms.두름_몸` · 경지 게이트가 못 여는 것은 목록에서 빠진다 |
| **Shift + 좌클릭** (검기 이상 태세) | **기 발출(쏨)** — 검기 참격 / 강기 포 | **3 / 6** (위력 3 / 5) | qi_manifestation `forms.쏨` |
| **F** (스왑) | **오의** — 발동권(흐름)을 얻었을 때만 | **내력 총량의 50~60%** | mc_action_mapping 1장 "F = 오의 (발동권 획득 시에만 활성)" · ultimate_arts `casting` |
| **Shift + F** | 전승 오의 선택 (4종 순환) | — | MVT엔 전승(사문·비급)이 없다 — 손으로 고른다 (검증 수단) |
| 우클릭 (웅크림 없이) | (건드리지 않음 — 세계 상호작용) | — | 가드·패링은 후속. 지금 잡으면 마을의 문·상인이 죽는다 |
| 좌클릭 (블록) | (건드리지 않음) | — | 채굴을 무공이 잡아먹으면 안 된다 |

**발경은 두름이 아니다.** 검기·검강은 라운드에 과금하지만(두름), 발경은 **타격마다** 밴드 코스트(1)를 낸다
(`cost_bands.발경 {cost: 1}` — "타격에 내력을 싣는다"). 그래서 발경을 두른 일류는 내력이 빨리 마르고,
마르면 그 자리에서 맨 기술로 떨어진다(다운캐스트). 이것이 개화한 몸의 첫 자원 관리다.

**호신강기는 격이 아니라 형태다** (`forms.두름_몸`). 같은 강기를 검에 두르면 검강(공격),
몸에 두르면 호신강기(방어) — 태세 슬롯 하나를 두 형태가 나눠 쓴다. 호신강기 중에는 검에 기가 없다.

콤보는 **명중 확인식**이 아니라 **스윙식**이다. 좌클릭 한 번 = 한 수. 맞았든 헛쳤든 다음 수로 넘어간다.
바닐라 피해는 취소되고 판정층이 대신 굴린다 — 그래야 프레임·경직·호(arc) 히트박스가 의미를 갖는다.

### 정본과 어긋나는 결정 3개 (근거)

1. **우클릭 = 가드/패링 (정본 1장) 을 아직 구현하지 않았다.**
   MVT의 우클릭은 이미 상인·게시판·문의 것이다 (TradeListener·ZoneListener). 가드를 여기에 얹으면
   마을이 먼저 망가진다. 대신 **Shift+우클릭**을 격 태세에 배정했다 — 정본이 비워 둔 칸이다.
   가드/패링은 무기 전용 슬롯(핫바 1~2)에서 문맥 분기로 붙이는 것이 옳다 (후속).

2. **Shift + 좌클릭 = 발출** — 정본에 없는 조작이다.
   정본의 Shift 예산은 은신(유지)·회피(탭)·운기(정지 3초)로 이미 과부하 상태이고(5장 리스크 노트),
   그 셋은 전부 **클릭을 동반하지 않는다**. Shift+클릭 두 칸은 비어 있다 — 그 자리를 쓴다.
   대안이던 "핫바 6~9 스킬 슬롯 우클릭"(정본 1장)은 스킬 슬롯 GUI·아이템 배정이 선행돼야 한다.
   격은 슬롯에 담기는 물건이 아니라 **몸의 태세**라는 점에서도 태세 순환이 정합적이다.

3. **발출에는 다운캐스트가 없다.**
   `internal_energy.yml downcast` 는 "시전 불가가 아니라 맨 기술로 나간다 — 프레임 유지"라고 정한다.
   그러나 발출은 프레임이 아니라 **기 그 자체가 본체**다. 맨 기술로 나갈 몸이 없다.
   → 내력 부족 시 **불발**(기 흩어짐 + 10틱 짧은 쿨다운). 콤보·근접의 다운캐스트는 정본대로 작동한다.

## 2. 격(格)이 눈에 보이는 방식

"응집은 빛으로 보인다" (`qi_manifestation.yml integration.npc` — npc_combat 대칭 원칙).
플레이어가 두른 격은 **상대가 읽을 수 있어야 한다**. 격이 높을수록 밝고 차갑다.

| 격 | 색 (액션바·파티클) | 태세 진입 SFX | 타격 순간 VFX | 타격 SFX |
|---|---|---|---|---|
| 외공기 | 회색 · `SMOKE` | — | `CRIT` ×4 (대성공 ×8) | `ENTITY_PLAYER_ATTACK_STRONG` |
| **발경** | 금색 · `CRIT` | `ITEM_TRIDENT_RIPTIDE_1` | `SWEEP_ATTACK` ×1 + `CRIT` ×10 — **짧은 충격파** | `..._ATTACK_KNOCKBACK` + `BLOCK_ANVIL_LAND`(1.8) |
| **검기** | 청록 · `ELECTRIC_SPARK` | `ITEM_TRIDENT_RIPTIDE_1` | `ELECTRIC_SPARK` ×12 + `END_ROD` ×5 — **날에 서린 기운** | `ITEM_TRIDENT_THROW`(1.5) |
| **강기** | 자주 · `END_ROD` | `BLOCK_CONDUIT_ACTIVATE` | `END_ROD` ×16 + `EXPLOSION` ×1 — **응집** | `BLOCK_CONDUIT_ACTIVATE` |
| 어검·심검 | 진자주/백 · `END_ROD` | (미배선 — 격 사다리만 열려 있다) | `END_ROD` ×20 | `BLOCK_BEACON_ACTIVATE` |

**텔레그래프**: 선딜(startup) 2틱마다 손끝에 `2 + 격 rank` 개의 기가 모인다 (최대 7).
검기 이상은 태세 진입·시전 개시에 **소리로도** 예고한다 — 상대가 회피를 준비할 시간을 준다.
두름 유지 중에는 라운드마다 손끝 잔광 2~4개 — 켜져 있다는 사실 자체가 정보다.

**다운캐스트의 연출은 빈약함이다** (`downcast.vfx`): 격이 외공기로 떨어지면 파티클도 회색 4개로 떨어진다.
상대는 그것을 보고 "저 자의 내력이 다했다"를 읽는다. 심리전은 여기서 시작한다.

## 3. VFX 예산 준수 (`performance.yml` F-P1)

| 예산 | 값 | 구현 |
|---|---|---|
| 전역 파티클 | 4000/틱 | `SkillHud` 가 틱마다 카운터를 0으로 되돌리고, 초과분은 발행하지 않는다 |
| 시야당 파티클 | 600/틱 | **관람자별 발행** (`viewer.spawnParticle`) — 브로드캐스트로는 시야 예산을 지킬 수 없다 |
| LOD | 16m 전량 / 32m 절반 / 그 밖 컬링 | 관람자 거리별 개수 조정 |
| 초과 시 | 연출 강등 | 그 관람자에게만 생략. **판정은 불변** — `SkillHud` 는 판정을 모른다 (한 방향 의존) |
| VFX 엔티티 | 풀 120 / 수명 60틱 | **쓰지 않는다** (0개) — 디스플레이 엔티티는 이기어검의 몫 (후속) |
| 중앙 티커 | 효과별 태스크 금지 (F-P2) | 태스크 **1개** (`SkillListener.start()`). 예약 타격·텔레그래프·유지비·HUD 가 이 하나를 공유 |

**단발 상한**: 가장 비싼 한 수(강기 타격, 대성공)가 `16 + 1 + 6 = 23`개.
텔레그래프는 2틱마다 최대 7개. 발출 궤적은 길이 8m × 2개 = 16개.
→ 한 플레이어가 한 틱에 만드는 최악치 ≈ **23개 = 시야 예산 600의 3.8%**.
60인 동시 전투(load_test)에서도 한 관람자의 시야에 들어오는 시전자는 LOD 32m 안쪽뿐이다.

**F-R1 중복 시전 폐기**: `duplicate_request_window_ticks` (=1) 안의 재입력은 버린다.
**F-P3 대상 상한**: 호·선 히트박스 모두 `max_targets_default` (=8) 에서 끊는다.

## 4. 규칙 층 (`SkillEngine`) — 무엇을 어디서 읽는가

Bukkit 의존 0. 순수 함수. `core` 룰 엔진 4종에 위임한다.

| 판단 | 위임처 | config |
|---|---|---|
| 내력 풀 = round(내공×3) | `InternalEnergyEngine.pool` | internal_energy.yml |
| 경지 게이트 (발경=일류, 검기=절정, 강기=화경) | `InternalEnergyEngine.canUse` | internal_energy.yml `realm_gates` |
| 다운캐스트 | `InternalEnergyEngine.payOrDowncast` | internal_energy.yml `downcast` |
| 격 rank·상성·무기 감당·자기손상 | `QiManifestationEngine` | qi_manifestation.yml |
| 명중·마진·등급 (2d6) | `JudgmentEngine.tierOf` | judgment.yml |
| 무기 등급 판정 보정 | `EquipmentEngine.weaponJudgmentBonus` | equipment.yml |
| 프레임·히트박스·경직·콤보 창 | (직접 판독) | skill_mechanics.yml |
| 피해 = 무기 위력 + 무공 위력 + ⌊마진/2⌋ | (직접 판독) | combat.yml `damage` |
| 경지 격차 보정 (단계당 ±2) | (직접 판독) | gm_modifiers.yml `realm_gap` |

### 격의 결정 순서 (한 수마다)

```
1. 요청 격  = max(초식의 격 라이더(qi_rider),  두른 격)
2. 코스트   = 라이더 cost │ 두름이 이겼으면: 유지비형(검기·검강) 0 · 발경 1/타격
3. 경지 게이트 → 못 여는 격은 한 칸씩 강등 (gated)   ← "그 격은 아직 이 몸의 것이 아니다"
4. 내력 지불 → 모자라면 외공기로 추락 (downcast)     ← 프레임은 남는다
5. 위력 = 무기 위력 + 무공 위력 + ⌊마진/2⌋ + 격 위력  ← combat.yml damage.qi_power (엔진 정본)
```

**【고침】 격 위력의 출처는 `combat.yml damage.qi_power` 다** (이전엔 격 rank 를 그대로 썼다).
숫자가 같아 증상이 없었을 뿐, 정본이 아닌 곳에서 위력을 읽고 있었다. 그리고 **발출은 형태 위력이 우선한다** —
`forms.쏨.검기_참격.power = 3` (두름 검기 2 보다 아프다. 1회에 몰아 쓰는 값이다). 강기 포는 5.

**【고침】 초식 코스트 0 = 발경 무료 버그.** 2026-07 정합 패스가 콤보 `cost` 를 전부 0으로 내리고
격 코스트를 `qi_rider` 로 옮겼는데, 엔진은 여전히 `cost > 0 ? 발경 : 외공기` 로 격을 판정하고 있었다.
결과: **발경을 두르면 내력이 한 방울도 들지 않았다** (위력 +1은 그대로 받으면서). 이제
① 초식의 `qi_rider` 를 읽고, ② 두름 발경은 타격마다 밴드 코스트(1)를 낸다.

### 무기 손상 (`weapon_break`) — 이제 **정말로 부러진다**

| 상황 | 규칙 | 구현 |
|---|---|---|
| **자기 격** (범철에 검기 두름) | 시전 3회마다 내구 1 (`self_damage_every`) | "검이 운다" → 내구를 넘기면 **그 자리에서 부러진다** |
| **남의 격** (범철이 검기를 받음) | 1격 초과 = 격돌 3회째 파괴 (`breaks_at`) | "날에 금이 간다 (n/3합)" → 3합째 **파괴** |
| **2격 초과** (범철이 검강을 받음) | 즉시 절단 | 한 합에 **절단** |
| 감당 이상 (정련이 검기를 받음) | 손상 없음 | — |

**【고침】** 이전 구현은 `Damageable.setDamage(+1)` 만 했다. 바닐라는 아이템을 **'사용'해야** 부러지므로
내구를 넘겨도 검은 멀쩡히 남아 있었다 — 무기 파괴가 장부에만 있었다. 이제 내구 상한을 넘기면 손에서 지운다
(`after_break`: 맨손). NPC 의 병기도 같은 규칙으로 부러지고, 부러지면 그 몸의 공격력이 맨손 값으로 내려간다.

### MVT 근사 4개 (한계이자 청구서)

| 근사 | 왜 | 옳은 자리 |
|---|---|---|
| **능력치 시트가 없다** — 실행력에 근력·민첩이 안 들어간다. 경지 격차(gm_modifiers `realm_gap`)가 그 자리를 대신한다 | MVT PlayerLedger 에 능력치가 없다 | 캐릭터 생성(player_creation) 배선 후 `능력치 + 무공 숙련` 정식 합산 |
| **몹의 저항 = 고정 난이도** — 적대 몹 12(보통) / 그 외 10(쉬움) | 몹에 능력치 시트가 없다 | npc_combat.yml 의 NPC 시트 (+7 고정) 배선 |
| ~~경지는 삼류/범인 취급~~ → **등록부의 몸이면 그 경지로 격차를 잰다** (백영묘 = 절정) | (이번 사이클에 고쳤다) | — |
| **무기 등급 = PDC 태그** (혼천 병기), 바닐라는 재질 근사 (다이아 = 정련 / 네더라이트 = 보병) | 바닐라 무기 하위호환 | `Weapons.KEY_GRADE` 가 이미 정본 — 근사는 폴백일 뿐 |
| **경지·내공은 손으로 세운다** (`/혼천 경지`) | MVT 에 개화·심법 배선이 없다 (봇에는 있다) | 개화 이벤트 → 서버 이관 |

### config 에 없어서 코드가 정한 값 (제안 키를 함께 적는다 — 등록되면 코드가 자동으로 그쪽을 읽는다)

| 값 | 폴백 | 제안 config 키 |

| 실시간 '라운드' 길이 (두름 유지비 과금 주기) | 60틱 = 3초 | `combat.yml → realtime.round_ticks: 60` ← **코드가 이미 이 키를 읽는다** (있으면 config 우선) |
| **'한 전투'의 길이** (오의 횟수·흐름의 수명) | 200틱 = 10초 무공방 | `combat.yml → realtime.combat_window_ticks: 200` ← **코드가 이미 이 키를 읽는다** |
| 발출(쏨)의 프레임·쿨다운 | [8,2,12] · 40틱 | `qi_manifestation.yml → forms.쏨.검기_참격.frames / cooldown_ticks` |
| 발출의 사거리·폭 | 8m × 1.5m | 위와 동일 (제왕검형 `선` 8×1.5 를 기준선으로 빌렸다) |
| **일류의 내공 하한** (NPC 내력 풀의 근거) | 1.0 | `cultivation.yml → 일류.promotion.requirements 에 "내공 1"` (절정 3·초절정 5·화경 7·현경 9 는 이미 있다) |
| **NPC 근접 사거리 / 격이 실린 창** | 3.5m / 20틱 | `npc_combat.yml → reach / qi_window_ticks` |
| **NPC 전투 밖 내력 회복** | 1/라운드 | `internal_energy.yml` 의 자연 회복은 '구간'(일) 단위다 — 실시간 회복률이 없다 |

**태조장권(맨손)은 점등됐다.** 지난 사이클엔 `skill_mechanics.yml` 에 combo 가 없어 맨손이 바닐라 주먹이었다.
이제 combo(2/2/3 · 2/2/3 · 5/3/8) 와 `qi_rider` 가 config 에 있고, 코드가 이미 `맨손 → taejo_jangkwon` 을
찾고 있었으므로 **코드 수정 없이 켜졌다** — 예고한 대로다. 권법가는 개화하면 3타에 발경이 실린다.

그리고 **육합검에는 `qi_rider` 가 없다** — `qi_note`(산문)만 있다: "개화한 자는 3타에 발경(내력 1)을 얹는다".
지금은 그 말이 **두름(Shift+우클릭 발경)** 으로만 실현된다. 산문을 코드가 읽을 수는 없다.
→ **config 등록 제안**: `yukhap_geom.qi_rider: { step: 3, 격: 발경, cost: 1, gate: 일류, power: 1 }`
(태조장권과 같은 문법. 등록되면 검객도 코드 수정 없이 3타 발경이 켜진다.)

## 7. NPC 도 격을 쓴다 (`npc_combat.yml symmetry`)

> "NPC 자원 = 내력 풀·소모 밴드·다운캐스트 동일 (고갈 이펙트 빈약화 — 읽기 가능)"

`SkillEngine` 은 더 이상 플레이어 전용이 아니다. 등록부(`npcs/cheongha_npcs.yml`)를 읽어
**어느 몸이 어느 격을 두르는지**를 엔진이 결정하고, `SkillListener` 의 같은 티커가 그것을 돌린다.
NPC 는 플레이어와 **같은 State** 를 쓴다 — 그것이 규칙이 대칭이라는 말의 실제 의미다.

### 격의 결정 (전부 config 판독)

```
내력 풀 = 개체의 internal_energy  │  없으면: 짐승은 0 (영물 제외 — "들짐승·맹수는 내력이 없다")
                                 │        사람은 pool(경지의 내공 하한)  ← cultivation.yml "내공 N"
격     = 개체의 qi_grade         │  없으면: 그 경지가 여는 가장 높은 격 (realm_gates)
```

### NPC 격 시전표 (지금 인게임에 서는 몸)

| 몸 | 경지 | 내력 | 격 | 코스트 | 텔레그래프 |
|---|---|---|---|---|---|
| 산길 도적 (졸개) | 삼류 | 0 | **외공기** | — | 없음 (격이 없으니 예고할 것도 없다) |
| **갈호** (두목) | 이류 | 0 | **외공기** | — | 없음 — 두목이라고 기를 쓰지는 않는다 |
| 곽진 (비무 상대) | 미등록 → 삼류 | 0 | **외공기** | — | 없음 |
| 산늑대·멧돼지 | 삼류 (들짐승) | 0 | **외공기** | — | 이빨과 발톱뿐 |
| 호랑이·반달곰 | 일류 (맹수) | 0 | **외공기** | — | 맹수도 내력은 없다 (config 규칙) |
| **백영묘** (영물) | 절정 | **9** | **검기 두름** | 유지 **1/라운드** | 상시 잔광 (`ELECTRIC_SPARK` ×3) + 발광 |
| **일류 무인** (진철산·혜각) | 일류 | 3 | **발경** | **1/타격** | 사거리 진입 시 **응집 6틱** (`CRIT`, 손끝) + 소리 |
| **절정 고수** (취걸개) | 절정 | 9 | **검기 두름** | 유지 1/라운드 | 상시 잔광 |

**텔레그래프 = 플레이어와 같은 연출이다.** 두름은 라운드마다 잔광을 흘리고(켜져 있다는 사실이 정보다),
발경은 **응집 → 격이 실린 창(20틱) → 소멸**의 주기를 돈다. 응집을 보고 물러서면 맨 주먹이 온다.
바닐라 근접 AI 의 스윙 타이밍은 우리가 정할 수 없으므로, "격이 실린 창"으로 근사했다 (아래 근사표).

**내력 관리도 대칭이다.** 백영묘의 내력 9는 검기 두름을 **9라운드(27초)** 버틴다. 그 뒤엔 기가 흩어지고
(`SMOKE` + 소멸음) **발톱만 남는다** — 플레이어가 그것을 보고 "버텼다"를 안다. 표적을 잃으면 다시 채운다.

## 8. 오의(奧義) — `ultimate_arts.yml`

> "오의는 배우는 것이 아니라 얻는 것이다. 최상위 자원을 태우는, 전투의 문장부호."

**격과는 다른 사다리다.** 격은 경지가 열지만, 오의는 **발동권(흐름)** 이 연다.

| 층 | 규칙 | 구현 |
|---|---|---|
| **경지** | 초절정 **개안** / 화경 **완성** / 현경 **자재** / 생사경 창작 | 초절정 미만은 F 가 그냥 손 바꾸기다 |
| **발동권(흐름)** | 아슬아슬한 성공 이상 **공방 3회 누적** | 공방마다 액션바 `●●○` — 차는 순간 연출로 고지 |
| **코스트** | 내력 총량의 **50%** (제왕검형 60%) | 모자라면 **불발** — 오의엔 다운캐스트가 없다 |
| **횟수** | 화경 이하 **전투당 1회** / 현경부터 해제 | 전투 창(200틱 무공방)이 끝나면 흐름·횟수 초기화 |
| **개안(초절정)** | 위력 **절반** + 직후 **내력 전소 + 내상** | 벽 너머를 훔쳐본 대가 (30초 쇠약·둔화) |
| **무적/슈퍼아머** | 오의별 명시, **20틱 절대 상한** | 매화만개 무적 12틱 · 제왕검형 슈퍼아머 |
| **세계가 안다** | 시전 목격 = 강도 3 소문 (억제 불가) | 32m 안의 모든 눈에 **오의명 타이틀** — 이름이 노출된다 |

### 전승 오의 4종 (전부 config 판독 — 코드에 수치가 없다)

| 오의 | 형태 | 프레임 | 코스트 | 효과 |
|---|---|---|---|---|
| **매화만개** | 원 6m · **5연타** | 16/6/18 · 무적 12틱 | 50% | 사방을 벤다 |
| **태극혜검** | **반격 오의** (창 10틱) | 8/10/12 | 50% | 받은 공격 1회 무효 + **위력 그대로 반사** |

(일반 연출은 생략된다). 전역 4000/시야 600 상한은 그대로 지킨다.

## 9. 격 상성이 실전에서 작동하는가 (`counters` 4원칙)

| 원칙 | 배선 | 확인 방법 |
|---|---|---|
| **1 관통** — 한 격 위는 아래 기 방어를 관통 (피해 = 격 위력 차) | ✅ `SkillEngine.guard()` | 화경 호신강기(강기 3)에 어검(4)이 들어오면 피해 **1** |
| **2 회피** — 격은 회피를 부수지 못한다 | ⛔ 회피가 아직 없다 (P2) | — |
| **3 무기** — 무기가 격을 견뎌야 한다 | ✅ `clashWeapon()` | 범철 + 검기 = **3합에 파괴** · 범철 + 검강 = **1합에 절단** |
| **4 상쇄** — 기 방어는 소모품이다 | ✅ 하위 격 **−1** / 동격 **−2** / 상위 격 **−2** | 도적이 외공으로 두들겨도 호신강기의 내력이 깎인다. 못 내면 **붕괴** |

호신강기의 값은 config 그대로다: 화경 내력 21 → 전개 4 + 유지 2/라운드 = 무피격 8라운드.
절정 3인 협공이면 3라운드 만에 마른다("하위 격도 머릿수로 강기를 말릴 수 있다").

| 근사 | 왜 | 옳은 자리 |
