# 무공의 모션 — 조작에서 시전까지 (MVT 배선)

> 정본: `docs/design/mc_action_mapping.md` (조작 ↔ 행동 매핑) · `skill_mechanics.md` · `qi_manifestation.md`
> 구현: `server-mvt/.../SkillEngine.java` (규칙) · `SkillListener.java` (모션) · `SkillHud.java` (HUD·파티클 예산)
> · `SkillDisplay.java` (3D 모션 계층 — §3-D)
> 원칙: **config 가 단일 진실 원천**. 이 네 파일에는 파티클 이름도 사운드 키도 아이템 이름도 없다 —
> 전부 등록부(`config/skill_motion.yml`)를 이름으로 부른다 (`motion_audit ⑦` 이 하드코딩 0건을 지킨다).

MVT에는 마을만 있었다. 무공을 쓸 수단이 없었다 — 이 문서는 그 손을 붙인다.

## 1. 조작 매핑

| 입력 | 나가는 것 | 코스트 | 근거 |
|---|---|---|---|
| **좌클릭** (검·도 소지, 대상 타격) | 육합검 콤보 1타 → 2타 → 3타 | 초식은 **0** — 내력을 먹는 것은 격이다 | skill_mechanics `yukhap_geom.combo` (cost 0) · combat.yml `internal_energy.skill_cost_rule` |
| **좌클릭** (맨손) | 태조장권 3타 — **3타에 발경이 실려 태어난다** | 0 · 0 · **내력 1** | skill_mechanics `taejo_jangkwon.qi_rider {step: 3, 격: 발경, cost: 1}` |
| **좌클릭** (허공) | 헛손질 — 콤보는 진행된다 | 동일 | 콤보 체인의 입력 유예(10틱)는 명중 여부와 무관해야 손에 붙는다 |
| **Shift + 우클릭** | **태세 순환** — 외공 → 발경 → 검기 → 검강 → **호신강기** → 외공 | 발경 **타격마다 1** / 검기·검강 유지 1·2 / 호신강기 **전개 4 + 유지 2** | qi_manifestation `forms.두름`·`forms.두름_몸` · 경지 게이트가 못 여는 것은 목록에서 빠진다 |
| **Shift + 좌클릭** (검기 이상 태세) | **기 발출(쏨)** — 검기 참격 / 강기 포 | **3 / 6** (위력 3 / 5) | qi_manifestation `forms.쏨` |
| **F** (스왑) | **오의** — 발동권(흐름)을 얻었을 때만 | **내력 총량의 50~60%** | mc_action_mapping 1장 "F = 오의 (발동권 획득 시에만 활성)" · ultimate_arts `casting` |
| **Shift + F** | 전승 오의 선택 (4종 순환) | — | MVT엔 전승(사문·비급)이 없다 — 손으로 고른다 (검증 수단) |
| 우클릭 (웅크림 없이) | (건드리지 않음 — 세계 상호작용) | — | 가드·패링은 후속. 지금 잡으면 마을의 문·상인이 죽는다 |
| 좌클릭 (블록) | (건드리지 않음) | — | 채굴을 무공이 잡아먹으면 안 된다 |

**발경은 두름이 아니다.** 검기·검강은 라운드에 과금하지만(두름), 발경은 **타격마다** 밴드 코스트(1)를 낸다
(`cost_bands.발경 {cost: 1}` — "타격에 내력을 싣는다"). 그래서 발경을 두른 일류는 내력이 빨리 마르고,
마르면 그 자리에서 맨 기술로 떨어진다(다운캐스트). 이것이 개화한 몸의 첫 자원 관리다.

**호신강기는 격이 아니라 형태다** (`forms.두름_몸`). 같은 강기를 검에 두르면 검강(공격),
몸에 두르면 호신강기(방어) — 태세 슬롯 하나를 두 형태가 나눠 쓴다. 호신강기 중에는 검에 기가 없다.

콤보는 **명중 확인식**이 아니라 **스윙식**이다. 좌클릭 한 번 = 한 수. 맞았든 헛쳤든 다음 수로 넘어간다.
바닐라 피해는 취소되고 판정층이 대신 굴린다 — 그래야 프레임·경직·호(arc) 히트박스가 의미를 갖는다.

### 정본과 어긋나는 결정 3개 (근거)

1. **우클릭 = 가드/패링 (정본 1장) 을 아직 구현하지 않았다.**
   MVT의 우클릭은 이미 상인·게시판·문의 것이다 (TradeListener·ZoneListener). 가드를 여기에 얹으면
   마을이 먼저 망가진다. 대신 **Shift+우클릭**을 격 태세에 배정했다 — 정본이 비워 둔 칸이다.
   가드/패링은 무기 전용 슬롯(핫바 1~2)에서 문맥 분기로 붙이는 것이 옳다 (후속).

2. **Shift + 좌클릭 = 발출** — 정본에 없는 조작이다.
   정본의 Shift 예산은 은신(유지)·회피(탭)·운기(정지 3초)로 이미 과부하 상태이고(5장 리스크 노트),
   그 셋은 전부 **클릭을 동반하지 않는다**. Shift+클릭 두 칸은 비어 있다 — 그 자리를 쓴다.
   대안이던 "핫바 6~9 스킬 슬롯 우클릭"(정본 1장)은 스킬 슬롯 GUI·아이템 배정이 선행돼야 한다.
   격은 슬롯에 담기는 물건이 아니라 **몸의 태세**라는 점에서도 태세 순환이 정합적이다.

3. **발출에는 다운캐스트가 없다.**
   `internal_energy.yml downcast` 는 "시전 불가가 아니라 맨 기술로 나간다 — 프레임 유지"라고 정한다.
   그러나 발출은 프레임이 아니라 **기 그 자체가 본체**다. 맨 기술로 나갈 몸이 없다.
   → 내력 부족 시 **불발**(기 흩어짐 + 10틱 짧은 쿨다운). 콤보·근접의 다운캐스트는 정본대로 작동한다.

## 2. 모션 등록부 (`config/skill_motion.yml`) — 【2026-07 신설】

> 사용자 요구: *"스킬 모션까지도 리소스팩을 통해 적용이 되어야 하고, 만약 리소스팩이 없더라도
> 마인크래프트 파티클 시스템을 통해서 어느정도는 확인이 되어야 합니다"*

모션이 **두 층**이다.

| 층 | 무엇 | 누가 |
|---|---|---|
| ① 팩이 있으면 | 여기 적힌 바닐라 파티클의 **텍스처**가 수묵 획으로 다시 그려진다 | 팩 담당 (`resourcepack/`) |
| ② **팩이 없어도** | 여기 적힌 **개수·퍼짐·소리·궤적**만으로 무엇이 일어났는지 읽힌다 | **이 등록부** |

`require-resource-pack=false` 가 불가침이므로 ②가 본체다. 팩은 ②를 아름답게 할 뿐, ②를 대신하지 않는다.

### 이전의 병 — 모션이 격(格)별로만 갈렸다

육합검 3타든 태조장권 붕권이든 오호단문창 찌르기든, 발경이 실리면 **똑같은 파티클**이 떴다.
무공을 배워도 눈으로는 구별되지 않았다. 파티클·소리는 Java 의 `switch` 안에 하드코딩돼 있었고,
오의·보법·발출·호신강기의 연출이 코드 여기저기에 흩어져 등록부가 없었다.

### 키 구조

```

                · rank · brightness · color

```

### 초식이 서로 달라 보이는 수단 3개

팔레트가 13장뿐이므로 **파티클 종류를 바꾸는 것은 마지막 수단**이다. 앞의 둘로 먼저 가른다.

1. **궤적의 모양** — 히트박스가 이미 다르다. 그것을 **그대로** 그린다 (호는 부채꼴, 선은 직선, 원은 사방).
2. **소리의 음높이** — 같은 검이라도 쾌검(음풍검 pitch 1.8)과 중검(제왕검형 0.5)은 **귀로** 갈린다.
   콤보 안에서도 1타 → 2타 → 마무리로 음이 내려간다. 눈을 감아도 몇 타째인지 안다.
3. **강조(accent·finisher)** — 마무리 타에만 붙는 한 개의 획. "이번 것이 무겁다"는 신호.

## 3. 팩이 없어도 읽히는가 — 여섯 가지가 서로 다르다

| 읽어야 하는 것 | 무엇으로 구별되는가 | 등록 키 |
|---|---|---|
| **격의 사다리** | **밝기와 밀도** (색이 아니다 — 수묵 규약). 타격 파티클이 외공 4 → 발경 10 → 검기 14 → 강기 18 → 어검 22 → 심검 24 로 **단조 증가**한다. 잔광도 0→1→3→5→7→9. 숫자를 못 세어도 먹점 넷과 흰 획 스물넷은 착각할 수 없다 | `grades[].impact/aura/brightness` |
| **응집(선딜)** | **제자리에서 모인다** — 2틱마다 손끝, 그리고 **소리로 예고**한다 (외공기만 무음). 보고 물러서면 맨 주먹이 온다 | `grades[].charge` + `sounds.charge` |
| **두름(근접타 태세)** | **머문다** — 라운드마다 손끝 잔광, **소리 없음**. 켜져 있다는 사실 자체가 정보다 | `grades[].aura` · `forms.두름` |
| **발출(쏨)** | **날아간다** — 8m 직선 광선(beam) + 큰 발사음. 몸을 빼는 것 말고는 답이 없다 | `forms.검기_참격 / 강기_포` |
| **호신강기** | **몸을 두르는 고리** — 손끝이 아니라 몸 둘레를 6점이 천천히 돈다. 실루엣이 두름과 다르다 → "저 자는 검이 아니라 몸에 둘렀다. 하위 격은 닿지 않는다" | `forms.호신강기.ring` |
| **오의** | ① 사방에서 몸으로 **빨려드는 고리** (다른 어떤 모션도 고리를 쓰지 않는다) ② **개시 섬광**(`flash` — 오의와 심검만 쓴다) + 뇌격음 ③ 32m 안 모든 눈에 **오의명 타이틀** | `ultimates[]` |
| **무기 파괴·격돌** | 균열(먹점 8 + 높은 모루음) → 파괴(파편 20) → **절단**(파편 24 + 낮은 모루음, 한 합에) — 셋이 소리로 갈린다 | `events.무기_균열/파괴/절단` |
| **패링** | 방패 접촉 순간 획 1개 + 방패음 + 맑은 종 (판정은 바닐라 그대로 — 모션만 얹는다) | `events.패링_성공` |
| **다운캐스트·고갈** | **빈약함이 곧 정보다** — 회색 연기 4개로 떨어진다. 상대는 그것을 보고 "저 자의 내력이 다했다"를 읽는다. 심리전은 여기서 시작한다 | `events.다운캐스트 / 격_소산` |

**색을 쓰지 않는 이유.** 이전 판은 발경=금색·검기=청록·강기=자주로 격을 갈랐다. 그것은 (ㄱ) 수묵 규약
(`resourcepack_design.yml`: 채색 금지)에 어긋나고 (ㄴ) 색맹 규약에 걸리며 (ㄷ) **팩 없는 클라이언트에서
파티클 색이 바닐라 텍스처를 따르므로 어차피 재현되지 않는다**. 격을 가르는 것은 **밝기(개수)** 다.
유일한 채색 예외는 마공의 혈점(`crimson_spore`) — 예외 자체가 정보다: "저것은 사람의 기가 아니다."

## 3-B. VFX 예산 준수 (`performance.yml` F-P1 · `skill_motion.yml budget`)

| 예산 | 값 | 구현 |
|---|---|---|
| 전역 파티클 | 4000/틱 | `SkillHud` 가 틱마다 카운터를 0으로 되돌리고, 초과분은 발행하지 않는다 |
| 시야당 파티클 | 600/틱 | **관람자별 발행** (`viewer.spawnParticle`) — 브로드캐스트로는 시야 예산을 지킬 수 없다 |
| LOD | 16m 전량 / 32m 절반 / 그 밖 컬링 | 관람자 거리별 개수 조정 |
| 초과 시 | 연출 강등 | 그 관람자에게만 생략. **판정은 불변** — `SkillHud` 는 판정을 모른다 (한 방향 의존) |
| VFX 엔티티 | 풀 120 / 수명 60틱 | **3D 모션 계층** (§3-D · `SkillDisplay`) — 강등선 90 · 오의 예약 16 |
| 중앙 티커 | 효과별 태스크 금지 (F-P2) | 태스크 **1개** (`SkillListener.start()`) — 3D 층도 같은 티커를 탄다 |

### 【한 지점·한 틱 30개】가 이 설계의 못이다

```
시야 예산 600/틱 ÷ load_test.combat_cluster_size 20인 = 30
  → 가장 비싼 한 지점 = 심검 타격 24 + 강조 1 + 대성공 4 = 29 ≤ 30
  → 스무 명이 같은 틱에 때려도 한 관람자의 시야 예산에 **정확히** 들어온다
```

그 위의 셋은 **풀(pool)** 이다 — 프레임이 길다고 파티클이 비례해 늘면 안 된다:

| 풀 | 값 | 뜻 |
|---|---|---|
| 응집 풀 | 32 | 선딜 20틱짜리 오의급 초식도 응집에 32개까지만. 풀이 마르면 발행을 멈춘다 |
| 궤적 풀 | 24 | 사거리 12m 선을 그려도 24개 — 점당 개수로 **표본점을 솎는다** |
| 타격 풀 | 48 | 다중 대상은 **나눠 쓴다** (광역 8인 = 6개씩). 아무리 나눠도 대상당 3개는 남긴다 — *맞았다는 사실*은 언제나 보여야 한다 |

**한 시전 총량 최악치** = 32 + 24 + 1 + 29 = **86** ≤ `per_cast_max` 160.
**오의**는 우선권(`world_weight.particle_priority`): 예산이 모자라면 생략되지 않고 **깎인다**.
한 틱 48 × 동시 12인 = 576 < 600 — 전투당 1회(화경 이하)라 동시성이 낮다.

**F-R1 중복 시전 폐기**: `duplicate_request_window_ticks` (=1) 안의 재입력은 버린다.
**F-P3 대상 상한**: 호·선·원 히트박스 모두 `max_targets_default` (=8) 에서 끊는다.

## 3-D. 3D 모션 계층 — 검기는 점 무리가 아니라 **한 자루의 획**이다

`SkillDisplay` (신규) · `config/skill_motion.yml` **`display:`** 절 · `ItemDisplay` 엔티티.

### 불변식 ㅁ — 디스플레이는 **덧칠**이다

이 층이 통째로 실패해도(팩 없음 · 예산 초과 · 미등록 · 볼 눈 없음) **파티클 층은 그대로 돈다.**
그러므로 `require-resource-pack=false` 는 이 층에서도 불가침이다 — **3D 는 특권이 아니라 사치다.**
모든 진입점은 *조용히 아무것도 하지 않는 것*으로 실패한다.

### 무엇이 어떻게 움직이는가

| 층 | 형체 | 움직임 (보간이 부드러움의 전부다) |
|---|---|---|
| **병기 휘두름** (握) | **손에 든 병기 그 자체** | 좌클릭 한 타마다 `ItemDisplay` 1개가 히트박스를 훑는다. 호 = 부채꼴을 한쪽 끝에서 다른 끝으로 (살짝 솟았다 내려온다) · 선 = 곧게 뻗었다 조금 거둔다 · 원 = 몸을 한 바퀴 · 돌 = 뒤로 흐른다. `setTeleportDuration(1)` 이 그 사이를 잇고, `roll` 이 병기를 돌린다 (겸은 **거꾸로** 돈다 — 걸어 채는 것이므로) |
| **기의 획** (격) | 초승달 획 | 격이 실렸을 때만 병기의 궤적 **위에 겹친다**. 씨앗에서 제 크기로 자랐다(`birth`) 스러진다(`fade`). 검기 → 심검으로 **크기가 단조 증가** (불변식 ㄷ가 3D 에도 걸린다) |
| **발출** (쏨) | 날아가는 획 | 검기 1.6m/틱(8m 를 5틱) · 강기 1.0m/틱(무겁다). 자전하며 날다가 벽·사거리 끝에서 **확장하며 터진다**(`impact_scale` 검기 1.8 · 강기 2.2) |
| **호신강기** | 몸을 두르는 판 4장 | 궤도 위를 63틱에 한 바퀴 (급하면 방어가 아니라 공격으로 읽힌다). **심장박동으로 산다** — `sustain()` 이 4틱마다 갱신하고, 12틱간 갱신이 끊기면 스스로 사라진다 |
| **오의** | 잊지 못할 형체 | 응집 내내 **오므린 채 자라고**(선딜 전체를 보간으로 씀) 개시의 순간 사거리만큼 **활짝 편다**. 매화가 피고 · 태극 원반이 서고 · 거대한 칼이 떨어지고 · 붉은 파문이 바닥을 훑는다 |

### 【정직의 못】 획은 히트박스보다 길 수 없다

`range`·`angle` 은 **판정이 쓴 값**(`skill_mechanics` 히트박스)이 코드로 그대로 들어온다.
등록부(`swings`)가 할 수 있는 일은 `reach ≤ 1.0` 으로 **줄이는 것뿐**이다 —
히트박스 3.5m 에 획 6m 를 그릴 방법이 이 구조에는 **없다**. 거짓말을 구조가 막는다 (감사 ⑧이 재확인).
**공속이 곧 리듬**: `span_ratio` 는 자세가 돌아오는 시간에 곱해진다 — 단검(2.2/s)의 획은 3틱에 끝나고
부(0.9/s)의 획은 18틱을 끈다. 무게가 눈에 보인다.

### 팩 유무의 분기 — 두 갈래뿐이고, 하나는 분기조차 없다

| 형체 | 팩 있음 | 팩 없음 |
|---|---|---|
| **`use_held`** (병기 휘두름 · 이기어검) | 팩이 구운 병기 3D 모델 | **바닐라 병기 모델** |
| 그 밖 (기의 획 · 투사 · 고리 · 오의) | `item_model` 키를 얹은 형체 | 키를 **아예 얹지 않는다** → 폴백 바닐라 아이템 (철검이 날아가고 · 흰 막대가 몸을 돈다) |

`use_held` 는 실은 것이 *그 사람의 병기 그 자체*이므로 **팩 게이트가 저절로 충족된다** — 분기가 없고,
관람석을 가를 필요가 없어 엔티티도 하나뿐이다 (값이 절반이다). 그래서 이 두 형체는 팩 담당에게
**아무것도 요구하지 않는다** — 병기 45자루가 이미 그 목록이기 때문이다.
그 밖의 형체는 팩을 받은 눈과 못 받은 눈이 섞여 있으면 **변주 2벌**을 띄우고 서로에게 숨긴다
(`setVisibleByDefault(false)` + `showEntity`). 지금 서버는 팩을 배포하지 않으므로(`resource-pack=` 빈 값)
**전원이 폴백 관람석**이다 — 그래도 무공은 3D 로 보인다. 그것이 이 설계의 요점이다.

> **왜 키만 얹고 말면 안 되는가**: `item_model` 키가 팩에 없으면 클라이언트는 '없는 모델'(보라·검정 큐브)을
> 그린다. 팩을 안 받은 눈에 키를 얹는 것은 연출이 아니라 **고장**이다. 그래서 분기가 존재한다.

### 두 층의 조율 (`display.blend`)

3D 획이 **실제로 떴을 때만** 궤적 파티클을 35% 로 깎는다 (둘 다 온전히 뿌리면 지저분하고 비싸다).
그러나 **0 으로 만들지는 않는다**(하한 1): 3D 가 강등된 순간 그 타가 아무 자국도 남기지 않으면 그건
강등이 아니라 **실종**이다. **타격 파티클은 건드리지 않는다** — 격의 사다리는 타격에서 읽힌다.

### 예산 (`performance.yml vfx_entities` 120 / 60틱)

### 격의 결정 순서 (한 수마다)

```
1. 요청 격  = max(초식의 격 라이더(qi_rider),  두른 격)
2. 코스트   = 라이더 cost │ 두름이 이겼으면: 유지비형(검기·검강) 0 · 발경 1/타격
3. 경지 게이트 → 못 여는 격은 한 칸씩 강등 (gated)   ← "그 격은 아직 이 몸의 것이 아니다"
4. 내력 지불 → 모자라면 외공기로 추락 (downcast)     ← 프레임은 남는다
5. 위력 = 무기 위력 + 무공 위력 + ⌊마진/2⌋ + 격 위력  ← combat.yml damage.qi_power (엔진 정본)
```

**【고침】 격 위력의 출처는 `combat.yml damage.qi_power` 다** (이전엔 격 rank 를 그대로 썼다).
숫자가 같아 증상이 없었을 뿐, 정본이 아닌 곳에서 위력을 읽고 있었다. 그리고 **발출은 형태 위력이 우선한다** —
`forms.쏨.검기_참격.power = 3` (두름 검기 2 보다 아프다. 1회에 몰아 쓰는 값이다). 강기 포는 5.

**【고침】 초식 코스트 0 = 발경 무료 버그.** 2026-07 정합 패스가 콤보 `cost` 를 전부 0으로 내리고
격 코스트를 `qi_rider` 로 옮겼는데, 엔진은 여전히 `cost > 0 ? 발경 : 외공기` 로 격을 판정하고 있었다.
결과: **발경을 두르면 내력이 한 방울도 들지 않았다** (위력 +1은 그대로 받으면서). 이제
① 초식의 `qi_rider` 를 읽고, ② 두름 발경은 타격마다 밴드 코스트(1)를 낸다.

### 무기 손상 (`weapon_break`) — 이제 **정말로 부러진다**

| 상황 | 규칙 | 구현 |
|---|---|---|
| **자기 격** (범철에 검기 두름) | 시전 3회마다 내구 1 (`self_damage_every`) | "검이 운다" → 내구를 넘기면 **그 자리에서 부러진다** |
| **남의 격** (범철이 검기를 받음) | 1격 초과 = 격돌 3회째 파괴 (`breaks_at`) | "날에 금이 간다 (n/3합)" → 3합째 **파괴** |
| **2격 초과** (범철이 검강을 받음) | 즉시 절단 | 한 합에 **절단** |
| 감당 이상 (정련이 검기를 받음) | 손상 없음 | — |

**【고침】** 이전 구현은 `Damageable.setDamage(+1)` 만 했다. 바닐라는 아이템을 **'사용'해야** 부러지므로
내구를 넘겨도 검은 멀쩡히 남아 있었다 — 무기 파괴가 장부에만 있었다. 이제 내구 상한을 넘기면 손에서 지운다
(`after_break`: 맨손). NPC 의 병기도 같은 규칙으로 부러지고, 부러지면 그 몸의 공격력이 맨손 값으로 내려간다.

### MVT 근사 4개 (한계이자 청구서)

| 근사 | 왜 | 옳은 자리 |
|---|---|---|
| **능력치 시트가 없다** — 실행력에 근력·민첩이 안 들어간다. 경지 격차(gm_modifiers `realm_gap`)가 그 자리를 대신한다 | MVT PlayerLedger 에 능력치가 없다 | 캐릭터 생성(player_creation) 배선 후 `능력치 + 무공 숙련` 정식 합산 |

## 7. NPC 도 격을 쓴다 (`npc_combat.yml symmetry`)

> "NPC 자원 = 내력 풀·소모 밴드·다운캐스트 동일 (고갈 이펙트 빈약화 — 읽기 가능)"

`SkillEngine` 은 더 이상 플레이어 전용이 아니다. 등록부(`npcs/cheongha_npcs.yml`)를 읽어
**어느 몸이 어느 격을 두르는지**를 엔진이 결정하고, `SkillListener` 의 같은 티커가 그것을 돌린다.
NPC 는 플레이어와 **같은 State** 를 쓴다 — 그것이 규칙이 대칭이라는 말의 실제 의미다.

### 격의 결정 (전부 config 판독)

```
내력 풀 = 개체의 internal_energy  │  없으면: 짐승은 0 (영물 제외 — "들짐승·맹수는 내력이 없다")
                                 │        사람은 pool(경지의 내공 하한)  ← cultivation.yml "내공 N"
격     = 개체의 qi_grade         │  없으면: 그 경지가 여는 가장 높은 격 (realm_gates)
```

### NPC 격 시전표 (지금 인게임에 서는 몸)

| 몸 | 경지 | 내력 | 격 | 코스트 | 텔레그래프 |
|---|---|---|---|---|---|
| 산길 도적 (졸개) | 삼류 | 0 | **외공기** | — | 없음 (격이 없으니 예고할 것도 없다) |
| **갈호** (두목) | 이류 | 0 | **외공기** | — | 없음 — 두목이라고 기를 쓰지는 않는다 |
| 곽진 (비무 상대) | 미등록 → 삼류 | 0 | **외공기** | — | 없음 |
| 산늑대·멧돼지 | 삼류 (들짐승) | 0 | **외공기** | — | 이빨과 발톱뿐 |
| 호랑이·반달곰 | 일류 (맹수) | 0 | **외공기** | — | 맹수도 내력은 없다 (config 규칙) |
| **백영묘** (영물) | 절정 | **9** | **검기 두름** | 유지 **1/라운드** | 상시 잔광 (`ELECTRIC_SPARK` ×3) + 발광 |
| **일류 무인** (진철산·혜각) | 일류 | 3 | **발경** | **1/타격** | 사거리 진입 시 **응집 6틱** (`CRIT`, 손끝) + 소리 |
| **절정 고수** (취걸개) | 절정 | 9 | **검기 두름** | 유지 1/라운드 | 상시 잔광 |

**텔레그래프 = 플레이어와 같은 연출이다.** 두름은 라운드마다 잔광을 흘리고(켜져 있다는 사실이 정보다),
발경은 **응집 → 격이 실린 창(20틱) → 소멸**의 주기를 돈다. 응집을 보고 물러서면 맨 주먹이 온다.
바닐라 근접 AI 의 스윙 타이밍은 우리가 정할 수 없으므로, "격이 실린 창"으로 근사했다 (아래 근사표).

**내력 관리도 대칭이다.** 백영묘의 내력 9는 검기 두름을 **9라운드(27초)** 버틴다. 그 뒤엔 기가 흩어지고
(`SMOKE` + 소멸음) **발톱만 남는다** — 플레이어가 그것을 보고 "버텼다"를 안다. 표적을 잃으면 다시 채운다.

| **세계가 안다** | 시전 목격 = 강도 3 소문 (억제 불가) | 32m 안의 모든 눈에 **오의명 타이틀** — 이름이 노출된다 |

## 9. 격 상성이 실전에서 작동하는가 (`counters` 4원칙)

| 원칙 | 배선 | 확인 방법 |
|---|---|---|
| **1 관통** — 한 격 위는 아래 기 방어를 관통 (피해 = 격 위력 차) | ✅ `SkillEngine.guard()` | 화경 호신강기(강기 3)에 어검(4)이 들어오면 피해 **1** |
| **2 회피** — 격은 회피를 부수지 못한다 | ⛔ 회피가 아직 없다 (P2) | — |
| **3 무기** — 무기가 격을 견뎌야 한다 | ✅ `clashWeapon()` | 범철 + 검기 = **3합에 파괴** · 범철 + 검강 = **1합에 절단** |
| **4 상쇄** — 기 방어는 소모품이다 | ✅ 하위 격 **−1** / 동격 **−2** / 상위 격 **−2** | 도적이 외공으로 두들겨도 호신강기의 내력이 깎인다. 못 내면 **붕괴** |

호신강기의 값은 config 그대로다: 화경 내력 21 → 전개 4 + 유지 2/라운드 = 무피격 8라운드.
절정 3인 협공이면 3라운드 만에 마른다("하위 격도 머릿수로 강기를 말릴 수 있다").
