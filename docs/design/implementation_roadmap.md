# 구현 로드맵 — 막(幕) 단위 단계 구성

> 방침: 전체를 한 번에 만들지 않는다. 막마다 **엔진화 → 패리티 테스트 → 실주사위
> 플레이 테스트(PT) → 발견 과제(F) 수정** 루프를 완주하고 다음 막으로 간다.
> 설계 층은 완결 상태 (기준 문서 29편 + config 27종) — 이제 구현이 설계를 검증한다.

## 막 구성

```text
1막 「생존과 첫 실전」 (진행 중)
    범위: 성장 v2 (화후 원장·실전 적립·기세 격차) + 경제 (물가·매매·생계 루프)
    산출: ProgressionEngine · EconomyEngine + 패리티 테스트, PT-006
    검증 질문: "무공 백지 소년이 사냥과 품팔이로 살아남으며 자라는가?"

2막 「강호의 관계」
    범위: NPC 일과·생애 정산 + 동행(협력 판정·협공) — 1막 수정 반영 후 착수
    산출: NpcLifecycleEngine · PartyEngine + 테스트, PT-007
    검증 질문: "세계가 나 없이도 자라고, 은혜가 회수되는가?"

3막 「격과 재산」
    범위: 기 발현(격 상성·무기 파괴) + 장비(애병·마병) 엔진화
    산출: QiManifestationEngine · EquipmentEngine + 테스트, PT-008
    검증 질문: "고경지 전투에서 격·무기·오의가 설계대로 맞물리는가?"

이후: 2단 파이프라인 프로토타입 (엔진→LLM 렌더 실동) → M2b (지형+MC 월드 어댑터, 로컬)
```

## 막 공통 프로토콜

```text
① 엔진화     config/*.yml이 단일 진실 원천 — 엔진은 수치를 하드코딩하지 않는다
             (엔진 판독용 수치 키를 config에 보강하되 서사 문구는 유지)
② 패리티     gradle :core:test — 손계산·시뮬레이터·PT 실측값이 스펙
③ 실전 검증   실주사위 PT (tools/roll.py) — 규칙을 실제로 굴려 마찰 지점 수집
④ 수정       발견 과제 F번호 채번 → config·문서 패치 → 재검증 → 커밋
```

## 발견 과제 채번 현황

PT-001~005에서 F1~F16 처리 완료. 1막 PT-006부터 F17~ 채번.
