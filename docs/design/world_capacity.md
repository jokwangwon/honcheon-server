# 세계 정원(定員) — 한 세상에 몇 명의 강호인이 살 수 있는가

> 질문: 한 세션(같은 세상에서 활동하는 플레이어 수)에 제한이 필요한가?
> 답: **필요하다. 단, 기술 동접 제한과 디자인 정원을 분리해서.**

---

## 1. 왜 제한이 필요한가 — 이 세계는 인구에 민감하다

일반 MMO보다 인구 압력에 약한 설계를 우리가 일부러 골랐다:

```text
기연은 선착순 1회성      청하현 중기연 2~3개 — 100명이 뒤지면 첫 주에 소진된다
NPC는 한 명뿐           묵삼 사건은 세계에 하나. 동시에 열 명이 굴릴 수 없다
지역 상태는 공유 수치     치안 50에 100명이 사건을 치면 하루에 바닥나거나 천장을 친다
소문망의 서사 밀도       "낯선 낭인" 소문이 동시에 40개면 소문이 아니라 소음이다
```

즉 제한의 근거는 서버 성능보다 **콘텐츠 생태계의 수용력**이다.

## 2. 두 층위의 제한

```text
① 동접 상한 (기술) — 지역 서버당 동시 접속자
   근거: performance.yml 부하 합격 기준 (60명, MSPT<40)
   초기값: 60 / BungeeCord 수평 분산으로 지역 서버가 늘면 총 동접도 는다

② 세계 정원 (디자인) — 한 세계에 '등록된' 총 인구
   근거: 지역 수 × 콘텐츠 밀도 (사건 스레드, NPC, 기연 재고)
   초기값: 청하현 1개 체제 = 정원 120
   확장식: 완전 구현 지역 1개 추가마다 +80~100
```

동접과 정원은 다르다 — 정원 120에 동접 60이면, 절반은 수련 상태(오프라인 몽타주)다. **수련 시스템이 자연스러운 인구 완충재 역할을 한다** (모두가 동시에 강호를 뛰지 않는다).

## 3. 정원 초과 시 — 대기열이 아니라 평행 강호

```text
새 세계(월드) 증설 = 각자 독립된 세계 상태로 시작하는 또 하나의 강호.
세계 간 상태 공유 없음 — "하나의 공유 세계" 원칙은 세계 안에서만 성립한다.
부산물: 서버마다 역사가 다르게 진화한다 (A서버는 혈교가 창궐했고 B서버는 정파가 눌렀다)
        — 결함이 아니라 관전 포인트. 시즌 종료 후 세계별 연대기 공개는 그 자체로 콘텐츠.
```

## 4. 인구-사건 스케일링 — 제한의 반대편 레버

정원 안에서도 인구가 늘면 콘텐츠가 마른다. 세계 배치 루프에 스케일링 규칙을 추가한다:

```text
사건 생성률 = 기본률 × f(지역 활동 인구)
  — 활동 인구가 많은 지역일수록 세계가 사건 씨앗(도적, 분쟁, 의뢰)을 더 뿌린다
  — 이미 있는 임계 효과(치안<30 → 도적 자동 발생)와 같은 채널 사용
기연 재고 보충: 소모된 기연 자리에 시즌 단위로 새 기연이 심긴다 (등록제 원칙 유지 —
  GM 즉석 발명은 여전히 금지, 운영이 config에 추가하는 것)
NPC 경합 완화: 핵심 NPC 사건은 '단계'가 세계 공유이므로, 후발 주자는 진행된 단계에서
  참여한다 (묵삼이 이미 노출됐다면 후발 주자의 강호는 '수배 이후'의 청하현이다)
```

## 5. 권고 요약

```text
초기 운영: 세계 정원 120 / 지역 서버 동접 60 / 초과 시 평행 세계 증설
성장 경로: 지역 추가 → 정원 확대 (제한을 푸는 방법은 서버 증설이 아니라 세계를 넓히는 것)
철학:     정원은 페널티가 아니라 약속이다 — "이 세계에서 당신의 행동은 희석되지 않는다"
```
