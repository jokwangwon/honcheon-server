# 플레이 인터페이스 결정 — 디스코드 봇 (G4 해소)

> 결정: 텍스트 RPG의 1차 플랫폼 = **디스코드 봇**. MC는 동일 세계의 2차 인터페이스
> (계정 연동). 기계 판독용: `config/interface.yml`

---

## 1. 왜 디스코드인가

```text
공유 세계와 구조 동형   서버(길드) = 세계 / 채널 = 지역·장소 / 스레드 = 장면 / DM = 은밀
선택지 = 버튼          프리페치와 정확히 결합 — 버튼 노출 시점에 다음 턴이 이미 렌더돼 있다
운영 비용 0           호스팅·클라이언트·계정 체계를 디스코드가 대신 든다
커뮤니티 표준          한국 TRPG·MMO 커뮤니티의 기본 서식지 — 유입 마찰 최소
```

## 2. 상호작용 모델 — 디스코드 문법으로 번역된 세계

```text
서장(개인 시간축)   프라이빗 스레드 — 생성 문답·발단 사건. 출도 전엔 남이 못 본다 (설계 정합)
공유 공간          지역 채널 (#청하현-객잔, #청하현-저자, #북쪽-산길 …)
                  같은 채널에 있는 플레이어는 서로 '보인다' — 조우·동행·엿듣기의 무대
장면(사건)         채널에서 파생되는 스레드 — 장면 단위가 곧 동시성 잠금 단위 (G8의 뼈대)
선택지            버튼 3~5개 (llm.yml 길이 예산과 일치) + 자유 입력은 메시지로 (판정 선언)
판정 공개          embed — 주사위·마진·등급은 공개가 원칙 (신뢰), 서사는 스레드 본문
은밀 행동          DM/개인 스레드로 분기 — 은신·밀담 (같은 채널 타인에겐 '보이지 않는다')
세계 방송          #강호-소문 채널 — 강도 3 소문·세계급 사건 (서버 공지와 동형)
```

## 3. 런타임 스택 — 단일 자바

```text
봇 = Java (JDA) + :core 룰 엔진 직결 + anthropic-java SDK
근거: 룰 엔진이 이미 자바(30/30 검증) — 봇에서 직접 호출하면 패리티 계층이 아예 없다.
     MC 서버(Paper)도 자바 — 코드 공유·계정 연동이 같은 스택 안에서 끝난다.
프로토타입(지금)은 파이썬 CLI — 파이프라인 검증용 (시뮬레이터가 파이썬 스펙인 것과 동형).
영속화: SQLite 단일 파일 — 봇 프로세스가 유일한 작성자 (persistence.md)
```

## 4. MC와의 관계

```text
같은 세계, 같은 원장 — 디스코드 캐릭터로 MC 접속 (계정 연동: /연동 명령 → 코드 확인)
디스코드 = 서사 인터페이스 (장·판정·관계) / MC = 실시간 인터페이스 (전투·탐험)
어느 쪽에서 벌어도 화후·전낭·마크는 하나 — persistence가 공용 원장
```

## 5. 단계

```text
Ⅰ 파이프라인 프로토타입 (파이썬 CLI — 지금): 엔진 사실 → LLM 렌더 실동, 캐시 실측
Ⅱ 봇 알파: 생성 문답 + 서장 (프라이빗 스레드) — 1인 플레이 완주
Ⅲ 봇 베타: 출도 + 지역 채널 + 조우 — 2인 PT-008 무대 (G9)
Ⅳ MC 연동: 계정 연결 + 공용 원장
```
