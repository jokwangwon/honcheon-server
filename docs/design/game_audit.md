# 게임 감사 (game_audit) — 무엇을 왜 재는가

맵에는 `/혼천 검수`(규칙 린트)와 `/혼천 조감`(렌더)이 있다. 리소스팩에는 `tools/texture_audit.py`가 있다.
게임 시스템에는 눈도 자도 없었다. `tools/game_audit.py`가 그 자다.

**이 도구는 재기만 한다. 고치지 않는다.** config 는 이 도구의 소유가 아니다.

```
python3 tools/game_audit.py              # 전체
python3 tools/game_audit.py --lint-only  # ① 정합 린트
python3 tools/game_audit.py --sim-only   # ② 밸런스 시뮬
```
위반(❌) 1건 이상이면 종료 코드 1.

순수 파이썬 — 외부 라이브러리를 쓰지 않는다. YAML 서브셋 파서를 자체 구현했고,
전 config 39종에 대해 PyYAML 과 **전수 대조하여 불일치 0건**을 확인했다 (YAML 1.1 불리언 강제 변환 포함).

## ① 정합 린트 — 참조가 깨지면 조용히 죽는다

config 는 26종이 넘고 서로를 참조한다. 참조는 문자열이다. 문자열은 예고 없이 어긋난다.

| 검사 | 근거 |
|---|---|
| **등록제** — 참조된 명사(세력·NPC·장소·사건·무공·심법·기연·계급)가 등록부에 실재하는가 | `fortune_encounters.yml`: *"등록제: 이 파일에 등록된 기연만 존재한다"* — 등록제는 기연만의 원칙이 아니다 |
| **엔진 키 대조** — `core/rules/*.java` 가 읽는 키가 config 에 실재하는가 | `RulesConfig.java`: *"config/*.yml 이 단일 진실 원천이다 — 엔진은 수치를 하드코딩하지 않는다"*. 단일 원천이면 원천이 없어질 때 엔진이 죽는다 |
| **경지 사다리** — 9경지 이름이 전 파일에서 같은 철자인가 | `cultivation.yml`: *"경지 9단계 — 이름·순서는 전 파일의 참조 축 (lint 검증 대상)"* |
| **생성 산술** — 프리셋이 자기 배분 규칙·경지 상한·나이 브래킷을 지키는가 | `player_creation.yml` v2: *"전원 유년/소년 시작. 성인 시작 폐지"* |
| **게이트 정합** — 경지가 열어준 능력을 실제로 쓸 자원이 있는가 | `internal_energy.yml realm_gates` × `cultivation.yml` 승급 요건 |
| **고아 절** — 아무도 참조하지 않는 최상위 절 | 죽은 설정은 거짓말을 한다 |

엔진 키 대조는 자바 변수 → YAML 노드를 얕게 추적한다 (`section(section(a,"x"),"y")` 중첩 해석 포함).
추적 불가한 변수는 건너뛴다 — 허위 경보는 보고서를 쓰레기로 만든다.

## ② 밸런스 시뮬 — 설계가 실제로 굴러가는가

봇·엔진 코드를 복제하지 않는다. **config 수치만 읽어** 가상 플레이어를 굴린다.
표준 플레이어 = 매일 수련 1회 + 사냥 2회 + 의뢰 1건.

| 측정 | 기준선과 근거 |
|---|---|
| **성장 곡선** — 범인→삼류→이류→일류(개화 포함) 며칠? | 무협의 시간 감각: 일류는 1년(360일) 안팎. 절반 미만이면 ❌, 초과면 ⚠️. `cultivation.yml`(승급 요건·`combat_hwahu`)·`training.yml`(환산표)·`simbeop.yml`(축기 n→n+1 = n년) |
| **경제 수지** — 하루 수입 − 지출 | 적자면 ❌(굶어 죽는 설계). 수입이 생계비의 3배 초과면 ⚠️(긴장이 없다). `economy.yml` — 정본 대조축은 `anchors.서민_1인_월_생활`·`서민_일당` |
| **판정 분포** — 2d6 등급 분포 (**해석적** — 36가지뿐이라 몬테카를로가 필요 없다) | 실패율 5% 미만 또는 40% 초과면 ⚠️. 등급이 **구조적으로 도달 불가**하면 ❌. `judgment.yml` |
| **내력 수지** — 개화 직후(내공 0.33 → 내력 1) 발경 1회면 고갈. 하루 운기 1회로 도는가 | `internal_energy.yml` pool·recovery × `time.yml` 5구간 |

성장 시뮬은 사냥감 선택 정책을 **두 가지** 굴린다(격에 맞는 사냥감 / 늘 격상 도전).
`combat_hwahu.multipliers.상대_격차`가 곱연산이라 사냥감 선택이 성장 속도를 지배하기 때문이다.
`압도적_하수`(적립 0)의 경계는 내가 정하지 않고 config 가 정한다 —
`judgment.yml auto_success_expected_margin(8) ÷ realm_gap_per_stage(2)` = 4단 격차.

## 이 도구가 잡을 수 있는 것

- 죽은 참조: 등록부에 없는 id, 철자가 갈라진 같은 개념, id 공간의 충돌
- 산술 모순: 자기 규칙을 어기는 프리셋, 상한을 넘는 기본값
- **열어놓고 못 쓰는 문**: 경지가 부여한 권한 ↔ 그 권한을 쓸 자원의 부재
- **구조적 불가능**: 주사위 상한이 등급 문턱에 못 미쳐 영원히 안 뜨는 결과 등급
- 시간 감각의 붕괴: 넉 달 만에 오는 일류
- 긴장의 소멸: 며칠 저축이면 사는 무기, 전액 예치가 정답인 사망 리스크

## 이 도구가 못 잡는 것 — 반드시 알고 읽을 것

1. **사건은 못 잰다.** 절정 이상의 승급은 '벽(壁) — 깨달음 사건'이 문이다. 수치가 아니라 서사다.
   시뮬은 하위 3단(자동 승급)까지만 굴리고, 절정 이상은 *수치 요건의 시간*만 표시한다.
2. **위험을 모른다.** 사냥·의뢰의 사망·부상 확률을 모형에 넣지 않았다. 표준 플레이어는 죽지 않는다.
   따라서 성장·경제 곡선은 모두 **낙관 상한**이다 — 실제는 이보다 느리고 가난하다.
3. **플레이어의 선택을 모른다.** '하루 수련 1 + 사냥 2 + 의뢰 1'은 가정이지 관측이 아니다.
   실제 플레이 로그가 생기면 이 가정을 로그로 갈아야 한다.
4. **LLM 층을 모른다.** GM 재량·서사 보정·페르소나는 수치 밖에 있다.
5. **고아 절 판정은 문자열 검색이다.** '미배선'과 '죽은 설정'을 구분하지 못한다 —
   그래서 엔진이 이미 읽는 config 의 고아 절만 경고로 올리고, 나머지는 참고 목록으로 내린다.
6. **판정 분포는 한 표본이다.** 능력치 3 + 기술 2 의 표준 플레이어 대 대등 NPC 하나.
   상황 보정(±5)·경지 격차·재시도 페널티가 붙으면 분포는 통째로 이동한다.

## 기준을 세운다는 것

전부 ✅ 로 끝나는 감사는 기준이 헐거운 것이다.
이 도구는 처음 돌린 날 **위반 48건·경고 18건**을 물어 왔다 —
그중에는 '삼류에게 발경을 열어주지만 삼류에게는 단전이 없다'와
'대등 판정에서 대성공이 구조적으로 불가능하다'가 있었다.
둘 다 사람이 눈으로 읽어서는 찾을 수 없는 종류다. 자가 있어야 보이는 것들이다.
