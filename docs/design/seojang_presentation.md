# 서장 표현 청사진 - 시네마틱 서책

> 상태: 설계 확정, 구현 착수 전
> 현재 정본: `config/seojang.yml`의 이야기·선택지와 봇의 판정
> 표현 정본: 이 문서
> 관련 규정: `platform_decision.md`, `resourcepack_design.md`, `pack_art_direction.md`

## 1. 목표

현재 서장은 Discord 버튼이 아니다. 봇이 장면을 쓰고 판정하며, MVT가 `WRITTEN_BOOK`을
자동으로 펼치고 책 안의 클릭 문구를 선택 입력으로 되돌린다. 이 구조는 유지한다.

개선 목표는 **책을 없애는 것**이 아니라 다음 경험을 만드는 것이다.

> 플레이어가 메뉴를 넘기는 것이 아니라, 자기 과거가 적힌 기억첩을 한 장씩 통과한다.

성공 기준은 화려함이 아니다.

- 첫 장이 왔다는 사실을 채팅을 읽지 않아도 안다.
- 장면 제목, 본문, 선택지가 시선 순서대로 읽힌다.
- 선택을 누른 즉시 입력이 받아들여졌음을 안다.
- 주사위 결과와 다음 장의 온도가 하나의 전환으로 이어진다.
- 팩은 입장 필수지만 글리프·소리가 판정이나 진행의 유일한 전달자가 되지 않는다.
- 재접속, 중복 클릭, 낡은 책에서도 진행 상태가 갈라지지 않는다.

## 2. 잠그는 결정

### 2.1 플랫폼

- 필수 클라이언트 모드를 도입하지 않는다.
- 운영 서버는 리소스팩 적용을 입장 조건으로 삼고, 거절·다운로드 실패는 기존 팩 게이트가 처리한다.
- Paper + 서버 리소스팩 + 바닐라 책 화면을 기본 경로로 유지한다.
- 리소스팩은 글리프, 책 아이템 외형, 소리와 색을 강화하지만 새로운 화면 로직을 소유하지 않는다.
- 진짜 전체 화면 자유 배치 UI는 선택 설치 클라이언트 모드의 후순위 실험으로만 남긴다.

바닐라 책 화면의 배치와 클릭 영역은 서버가 자유롭게 재설계할 수 없다. 리소스팩으로 전역 책
텍스처를 교체하면 다른 비급·서찰에도 영향을 줄 수 있다. 따라서 1차 구현은 **책 내부 조판과
책 전후의 연출**에 집중하며, 전역 책 배경 교체는 별도 오염 검증 전까지 금지한다.

### 2.2 권위 경계

```text
봇    이야기 · 선택지 · 주사위 · 등급 · 진행 상태 · 토큰 검증
다리  봇이 확정한 화면 자료와 플레이어 입력 번호 전달
MVT   책 조판 · 화면 전환 · 소리 · 입력 접수 표시
팩    글리프 · 아이템 외형 · 음원 · 교체 가능한 아트
```

- MVT는 선택의 성공 여부나 판정 결과를 예측하지 않는다.
- 로컬 연출 상태는 `UUID + 장면 토큰`으로만 식별하고 재시작 시 버려도 된다.
- 영구 상태를 MVT에 추가하지 않는다. 서장 시트와 이벤트 원장은 계속 봇 DB에만 산다.
- 낡은 토큰 거부와 중복 사건 멱등성은 기존 계약을 그대로 유지한다.

### 2.3 표현 원칙

- 본문은 읽기 속도를 우선한다. 장식 글리프가 한글 본문 폭을 침범하지 않는다.
- 색만으로 상태를 전달하지 않는다. 선택, 성공, 실패는 글자·형태·소리를 함께 쓴다.
- 주사색은 선택 확정과 출도 인장에만 사용한다.
- 타자 효과를 위해 책을 반복해서 닫고 열지 않는다. 깜빡임과 중복 입력 위험이 더 크다.
- 화면 암전이나 이동 제한은 짧고 취소 가능해야 한다. 접속 직후 플레이어를 오래 가두지 않는다.
- LLM 폴백 표시는 현재 간기 규칙을 유지하며 실패 경고처럼 과장하지 않는다.

## 3. 경험 흐름

### 3.1 장면 도착

```text
새 토큰 수신
  -> 이전 책 회수
  -> 0.8~1.2초 장 제목 연출
  -> 붓 또는 종이 소리
  -> 새 서책 자동 열기
```

장 제목은 `제1장` 같은 번호와 장면 제목만 보여 준다. 본문을 타이틀로 중복 출력하지 않는다.
장식 글리프나 전용 음원이 누락되어도 바닐라 타이틀과 기존 채팅 안내가 같은 사실을 전달한다.
팩 자체가 적용되지 않은 플레이어는 이 흐름에 들어오기 전에 팩 게이트가 이유를 말하고 접속을 막는다.

### 3.2 읽기

책은 다음 순서로 조판한다.

1. 첫 쪽: 장 번호, 장면 제목, 짧은 여백, 본문 시작
2. 가운데 쪽: 본문만 배치, 문단과 문장을 가능한 한 보존
3. 마지막 쪽: 본문 끝 또는 판정의 여운
4. 선택 쪽: 선택지 전용, 본문과 섞지 않음

현재의 단순 130자 분할은 `BookLayout` 조판기로 교체한다. 조판기는 글자 수가 아니라 줄 폭과
줄 수를 계산하고, 첫 쪽의 머리말 공간을 별도로 뺀다. 문단 전체를 무조건 다음 쪽으로 넘기지는
않되 문장 한가운데가 잘리는 일을 우선 방지한다.

본문 한글은 우선 바닐라 글꼴을 유지한다. 전용 한글 글꼴 전체를 팩에 싣는 작업은 용량, 라이선스,
GUI 배율 검증이 선행되지 않으면 도입하지 않는다. 리소스팩 1차 범위는 장 구분선, 붓점, 인장,
선택 표식 같은 소형 비트맵 글리프다.

### 3.3 선택

선택지를 누르면 MVT가 할 수 있는 즉시 피드백만 먼저 보여 준다.

```text
클릭
  -> 같은 토큰의 추가 클릭 잠금
  -> 책 닫기
  -> "선택을 보냈다"는 짧은 낙관·소리
  -> 봇에 선택지 번호 전달
```

이 단계에서 성공·실패 색이나 주사위 숫자를 보여 주면 안 된다. 아직 봇이 판정하지 않았기 때문이다.
전송 실패나 제한 시간 초과 시에는 잠금을 풀고 같은 책을 다시 열 수 있어야 한다.

### 3.4 판정과 다음 장

현재 `SeojangScene`은 다음 장의 본문과 선택지는 전달하지만 직전 판정의 화면 자료는 전달하지 않는다.
판정 연출 단계에서는 봇이 확정한 다음 값을 다리에 추가한다.

```text
result_id       멱등 표시용 사건 ID
choice_label    실제 선택 문구
roll            2d6 결과
total           최종 합계
resist          저항
margin          마진
tier            판정 등급
```

별도 실시간 판정 시스템을 만들지 않는다. 다음 `SeojangScene` 스냅숏에 `previous_result`를 동봉하면
MVT는 그 결과를 한 번만 연출한 뒤 다음 책을 연다. 에필로그 장면에도 같은 구조를 사용한다.

```text
봇 판정 완료
  -> previous_result 수신
  -> 선택 문구 + 주사위 + 등급을 1.2~1.8초 표시
  -> 등급별 소리와 명암 변화
  -> 다음 장 제목 연출
  -> 다음 책 열기
```

수치는 기존 공개 판정 원칙을 따른다. 서사 본문에는 수치를 넣지 않고, 판정 순간에만 합계와 저항을
보여 준다. 소리는 등급을 보조할 뿐 유일한 전달 수단이 아니다.

### 3.5 에필로그와 출도

- 에필로그 선택 쪽에는 선택지 대신 하나의 주사 인장과 `강호로 나선다`를 둔다.
- 출도 확정 전에는 살아 있는 토큰을 유지한다.
- 출도 후 기존 진행용 책은 회수한다.
- 선택 기능과 토큰을 제거한 **서장 필사본**을 기념품으로 남길 수 있다.
- 필사본은 읽기 전용 기록이며 다시 판정하거나 출도를 호출할 수 없다.
- 인벤토리가 가득 찬 경우 지급을 강행하지 않고, 재열람 명령이나 보관함 같은 후속 경로를 사용한다.

## 4. 시각·음향 언어

### 4.1 수묵 기억첩

| 요소 | 규칙 |
|---|---|
| 바탕 | 화선지 여백, 밝은 회황색. 본문 대비를 최우선 |
| 먹 | 제목·본문·구분선. 장식 면적보다 획의 방향으로 분위기 표현 |
| 주사 | 선택 확정·출도 인장에만 사용 |
| 옥빛 | 서장 기본 UI에는 사용하지 않음. 기연·심법 같은 청량 채널과 혼동 방지 |
| 장 표식 | 장 번호 + 짧은 먹 구분선. 대형 삽화 금지 |
| 선택 표식 | 빈 인장 -> 클릭 접수 시 찍힌 인장. 색 없이도 형태가 달라야 함 |

가문·발단별로 다른 장식을 새로 발명하지 않는다. 이미 등록된 발단과 장면 제목에서 고를 수 있는
범위만 사용하며, 1차 구현은 모든 갈래에 같은 기억첩 문법을 적용한다.

### 4.2 소리

필요한 소리 채널은 네 개다.

| 채널 | 용도 | 상한 |
|---|---|---|
| `seojang.open` | 장 도착, 종이와 붓의 시작 | 1.2초 |
| `seojang.choose` | 입력 접수, 마른 낙관 | 0.8초 |
| `seojang.result` | 판정 확정, 등급별 음높이 변주 | 1.2초 |
| `seojang.debut` | 출도, 짧은 종과 책 덮는 소리 | 1.8초 |

배경 음악은 범위 밖이다. 서장 한 번을 위해 긴 음원을 점유하지 않고, 짧은 사건음으로 장면의 경계를
만든다. 음원 파일이 없을 때는 등록된 바닐라 종이·책·종 계열 소리로 폴백한다.

## 5. 구현 단계

### SJ-000 - 청사진과 기준선 계획

산출물:

- 이 문서
- 현재 서장 흐름과 권위 경계의 코드 대조
- 페이지 수·대기 시간·중복 클릭 기준선에서 측정할 항목 목록
- GUI 배율 2·3·4에서 사용할 긴 본문 fixture 요구사항

닫는 조건:

- 이야기와 표현의 소유 경계가 문서와 코드에서 일치한다.
- 순수 리소스팩으로 가능한 범위와 선택 모드의 범위가 섞이지 않는다.
- 실제 기준선 측정과 fixture 작성은 SJ-001의 첫 작업으로 넘긴다.

### SJ-001 - 조판 엔진

대상:

- `SeojangBook.pages/paginate`를 별도 `BookLayout`으로 분리
- 첫 쪽·본문 쪽·선택 쪽 용량을 별도 계산
- 빈 본문, 매우 긴 문장, 여러 문단, 한글·숫자 혼합 fixture

닫는 조건:

- 선택지가 본문에 밀려 잘리거나 빈 페이지 뒤에 놓이지 않는다.
- 같은 입력은 항상 같은 페이지 배열을 만든다.
- 장식 글리프를 쓰지 않는 fixture에서도 클릭 문구가 살아 있다.

### SJ-002 - 장 전환과 리소스팩 자산

대상:

- 장 도착 타이틀, 짧은 지연, 책 자동 열기
- 서장 전용 장식 글리프와 네 개 소리 채널
- 진행용 서책 아이템 외형
- 팩 게이트의 `SUCCESSFULLY_LOADED` 상태와 서장 진입 순서 결선
- 개별 장식·음원 누락 시 바닐라 타이틀·소리·문구 강등

슬롯은 구현 시작 시 `config/resourcepack_design.yml`에 먼저 등록한다. 잠정 후보는 비어 있는
`E0B0~E0BF`이나, 실제 등록부와 빌드 결과를 다시 대조하기 전에는 코드에 값을 박지 않는다.

닫는 조건:

- 기존 HUD·경락도 글리프와 충돌하지 않는다.
- 서장 장식 자산을 비활성화한 시험에서도 클릭과 진행 계약이 통과한다.
- 팩 거절·다운로드 실패·로딩 완료가 서장보다 먼저 기존 게이트에서 판정된다.

### SJ-003 - 선택·판정 피드백

대상:

- 토큰별 입력 잠금과 제한 시간 복구
- `previous_result` 다리 계약
- 권위 결과 타이틀·액션바·소리
- 결과 중복 재생 방지

닫는 조건:

- 연타해도 선택 사건은 한 번만 적용된다.
- MVT가 임의의 주사위나 등급을 만들지 않는다.
- 봇 응답 지연·재시작·플레이어 재접속 후에도 현재 책으로 회복된다.
- 판정 결과를 한 번만 보여 주고 다음 장을 연다.

### SJ-004 - 출도와 필사본

대상:

- 에필로그 전용 인장 연출
- 출도 확정 후 진행용 토큰 폐기
- 클릭 불가능한 서장 필사본 또는 재열람 경로

닫는 조건:

- 필사본에서 `/혼천 서장` 명령이 실행되지 않는다.
- 출도 사건은 기존과 동일하게 한 번만 기록된다.
- 인벤토리 만석과 재접속에서도 필사본 때문에 진행이 막히지 않는다.

### SJ-005 - 선택 모드 연구, 후순위

전체 화면 자유 조판이 여전히 필요할 때만 선택 설치 클라이언트 모드를 검토한다. 서버와 다리 계약은
그대로 사용하고 렌더러만 교체해야 한다. 모드가 없는 플레이어는 언제나 서책 경로를 사용한다.

이 단계는 SJ-001~004의 실기동 결과 없이 착수하지 않는다.

## 6. 시험과 감사

### 자동 시험

- `BookLayoutSelfTest`: 페이지 결정론, 경계 길이, 선택 쪽 보존
- `SeojangPresentationSelfTest`: 토큰 잠금, 시간 초과, 중복 결과, 재접속
- `seojang_presentation_audit.py`: 권위 경계, 등록된 글리프·소리, 팩 게이트, 전역 책 오염 금지
- 기존 서장·브리지·리소스팩 감사 전부 재실행

### 실기동 눈

| 눈 | 통과 기준 |
|---|---|
| GUI 배율 | 2·3·4에서 제목·본문·선택지가 잘리지 않음 |
| 긴 글 | LLM 상한 길이 본문도 마지막 선택까지 도달 |
| 팩 거절 | 기존 게이트가 이유와 재접속 방법을 말하고 입장을 차단 |
| 팩 다운로드 실패 | 기존 게이트가 재시도 방법을 말하고 서장을 시작하지 않음 |
| 장식 강등 | 관리자 fixture에서 전용 글리프·음원 없이도 텍스트 클릭 계약 통과 |
| 연타 | 같은 선택을 빠르게 눌러도 판정 1회 |
| 낡은 책 | 이전 토큰 클릭은 거부되고 현재 책을 다시 열 수 있음 |
| 재접속 | 진행 중 장면과 토큰을 봇에서 다시 받아 복구 |
| 시각 접근성 | 주사색을 구분하지 못해도 인장 형태와 문구로 상태 판별 |
| 음향 접근성 | 소리를 꺼도 타이틀·문구로 전환 상태 판별 |
| 다른 서책 | 비급·서찰·족보 화면과 아이템이 의도치 않게 변하지 않음 |

## 7. 작업 소유와 변경 순서

```text
1. 문서와 fixture             디자인 트랙
2. BookLayout                MVT, 봇·DB 무관
3. presentation config       config/seojang.yml
4. 글리프·소리 슬롯 등록     config/resourcepack_design.yml
5. 팩 컴파일러와 자산         tools/build_resourcepack.py, resourcepack/
6. previous_result 계약      bot + WorldBridge, 판정 로직은 변경 금지
7. 실기동 검증과 감사         tools/, 완료 문서
```

DB 이관이나 연결 풀 작업과 파일이 겹치지 않는 한 병렬 진행할 수 있다. `Db`, PostgreSQL 스키마,
이관 도구는 이 트랙의 소유 파일이 아니다.

## 8. 구현 전 확인할 결정

- 진행용 책과 필사본의 아이템 외형을 같은 계열로 둘 것인가.
- 판정 결과 표시 시간을 1.2초와 1.8초 중 어느 쪽으로 고정할 것인가.
- `previous_result`를 다음 장 스냅숏에 넣을지, 별도 결과 스냅숏으로 둘지 실측할 것인가.
- 전역 책 배경 교체가 다른 서책을 오염시키지 않는 별도 화면 경로가 있는지 클라이언트에서 확인할 것인가.

기본 선택은 각각 **같은 계열·1.5초·다음 장 동봉·전역 배경 미교체**다.
