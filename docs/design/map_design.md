# 맵 디자인 언어 — 무협 수묵 팔레트와 공간 문법

> 자매 문서: `map_generation.md`(파이프라인 — *어떻게* 컴파일하는가)에 대해
> 이 문서는 디자인 언어(*무엇을, 어떤 모습으로* 짓는가)를 정의한다.
> 실물 레퍼런스: `server-mvt/src/main/java/com/honcheon/mvt/CheonghaBuilder.java`
> (청하현 61x61 결정론 조성기 — 이 문서의 문법을 자바로 인라인 구현한 M2b 판본).
> 논리 원천: `config/regions/cheongha_hyeon.yml` — 장소가 config에 있으면 맵에 반드시 선다.

---

## 1. 디자인 원칙

```text
1. 수묵 3색 — 화면의 기본은 목골(짙은 나무)·백벽(흰 벽)·흑와(검은 기와) 세 값.
   채색은 아껴서: 차양·등롱·매화만 색을 갖는다. 색이 귀할수록 색이 말을 한다.
2. 맵도 컴파일한다 — 손건축 금지. 같은 입력 = 같은 마을 (결정론, 시드/난수 불사용 또는 고정).
3. 논리-공간 정합 — 앵커 계약(반환 Map 키)이 config 장소와 1:1. 건물은 장식이 아니라
   시스템의 무대다 (장터에서만 매각, 의뢰소 게시판 = 사건 소문의 물리적 표면).
4. 바닐라 안정 API만 — Paper/Bukkit 1.21.4 안정 API. BlockData는 검증된 인터페이스만
   (Stairs·Leaves·Lantern·Directional). 리소스팩 커스텀 블록은 차후 옵션.
5. 위계는 높이와 지붕으로 — 중요한 건물일수록 풋프린트가 크고 벽이 높고 지붕 층이 많다.
   (객잔 13x9·벽4 > 관청류 9x7·벽3 > 노점 3x2·차양뿐)
```

## 2. 무협 수묵 팔레트 — 블록 대응표

### 2.1 기본 3색 (건물 공통)

| 개념 | 역할 | 블록 | 비고 |
|------|------|------|------|
| 목골(木骨) | 모서리 기둥 | `DARK_OAK_LOG` | 4우 기둥. 대문·각루 기둥도 동일 |
| 목골 | 상인방·도리 | `DARK_OAK_PLANKS` | 벽 최상단 1열 — 목조 테두리 강조 |
| 목골 | 마루·바닥 | `SPRUCE_PLANKS` | 실내 온도감은 가문비로 (흑목보다 밝게) |
| 백벽(白壁) | 회벽 | `WHITE_TERRACOTTA` | 양모(WOOL)는 가연성·채도 문제로 배제 |
| 백벽 | 격자창 | `GLASS_PANE` | 벽 중단(y+2) 격자 패턴 `(x+z)%2==0` |
| 흑와(黑瓦) | 기와면 | `DEEPSLATE_TILE_STAIRS` | 안쪽으로 오르는 방향(facing) 필수 |
| 흑와 | 용마루·추녀마루 | `DEEPSLATE_TILE_SLAB` / `DEEPSLATE_TILES` | 슬래브=마루, 풀블록=모서리 층답 |

### 2.2 기반·가로 시설

| 개념 | 블록 | 비고 |
|------|------|------|
| 광장 포장 | `SMOOTH_STONE` | 회백 — 수묵의 여백 |
| 도로 | `DIRT_PATH` | 흙길. 현성 승격 시 자갈(GRAVEL) 혼합 검토 |
| 담장 | `COBBLESTONE` + `STONE_BRICKS` + `STONE_BRICK_WALL` | 하단 잡석, 상단 전돌, 여장 |
| 우물 | `COBBLESTONE`/`COBBLESTONE_WALL` + 흑와 지붕 | 광장의 심장 — 소문 브로드캐스트 존 후보 |
| 등롱 | `SPRUCE_FENCE` 2단 + `LANTERN` | 길가 조명 리듬 (남북로 6칸, 동서로 7칸 간격) |
| 현수 등롱 | `LANTERN` (hanging=true) | 대문 인방 아래 |

### 2.3 채색 — 아끼는 색

| 개념 | 블록 | 의미 |
|------|------|------|
| 노점 차양 | `RED / YELLOW / LIME / LIGHT_BLUE / ORANGE _WOOL` | 장터의 활기. 붉은 차양 = 가죽 매입(게임 규칙 참조점) |
| 매화(대역) | `CHERRY_LOG` + `CHERRY_LEAVES`(persistent) | 광장 네 귀. 화산파 매화 문양의 시각 복선 |
| 화단 | `GRASS_BLOCK` + `POPPY / WHITE_TULIP / OXEYE_DAISY / AZURE_BLUET` | 광장 모서리 2x2 |

### 2.4 집기 (생업의 흔적)

| 집기 | 블록 | 쓰는 곳 |
|------|------|--------|
| 탁자 | `SPRUCE_FENCE` + `SPRUCE_PRESSURE_PLATE` | 객잔 |
| 화로·국솥 | `CAMPFIRE` + `CAULDRON` | 객잔 |
| 약장 | `BOOKSHELF` (2단) | 의방 |
| 탕약 도구 | `BREWING_STAND` + `CAULDRON` | 의방 |
| 카운터 | `DARK_OAK_PLANKS` 1단 열 | 전장 |
| 장부·대장 | `LECTERN` | 전장·의뢰소 |
| 금고·좌판 | `BARREL` / `CHEST` | 전장·노점·객잔 계산대 |
| 게시판 | `DARK_OAK_PLANKS` 패널 + `OAK_WALL_SIGN`(남향) 여러 장 | 의뢰소 앞 |

## 3. 건물 유형별 스펙

공통 문법: 4우 흑목 기둥 → 백벽(+격자창) → 상인방 → **계단식 팔작지붕**
(처마 1칸 내밀기 → 층마다 1칸씩 좁아지는 스테어 링, 모서리는 풀블록 층답, 꼭대기 용마루 슬래브).
입구는 도로를 바라본다: 광장 북쪽 건물은 남향, 남쪽 건물은 북향. 입구 옆 간판 + 골목길 연결.

| 유형 | 풋프린트 | 벽고 | 내부 집기 | config 대응 |
|------|---------|------|-----------|-------------|
| 객잔 (청하객잔) | **13x9** (최대) | 4 | 화로+국솥, 탁자 4, 계산대 술통 | `cheongha_inn` — 소문·접선 무대. M3에서 2층(묵삼의 방) 승격 |
| 의뢰소 | 9x7 | 3 | 접수 대장(LECTERN) + **옥외 게시판**(간판 3장 = 진행 중 사건 공고) | `request_office` — 게시판 문구는 incidents와 정합 |
| 의방 (약재상) | 9x7 | 3 | 약장 선반 벽면, 탕약 도구 | `medicine_shop` — 열병 사건 무대 |
| 전장 | 9x7 | 3 | 실내를 가로막는 카운터, 장부, 금고 | 전표 시스템 무대 |
| 노점 | 3x2 | — | 기둥 2주 + 색 차양 3x2 + 좌판 술통 | 장터 — 4~5개, 차양색 전부 다르게 |
| 우물 | 3x3 + 지붕 5x5 | — | 기둥 4주 + 흑와 지붕 | 광장 중심 = "장터" 앵커 |
| 대문 (북·남) | 개구 3칸 | 문루 6 | 흑목 기둥 2주, 인방, 흑와 처마, 현수 등롱, 현판 | 북문 → `north_road` (사냥터·도적 사건) |
| 담장 | 둘레 57x57 | 3 | 잡석+전돌+여장, 모서리 각루(목주+등롱) | 마을 경계 = 안전 지대의 시각화 |

향후 유형 (현성 승격분): 관아(마당+담 내곽), 민가(5x5~7x6, 벽고 2~3, 변주 파라미터),
창고(`north_alley_warehouse` — 뒷문 필수, hidden), 사당(폐사당 — 개별 정성 제작), 나루(수변 데크).

## 4. 스케일 계획 — 마을 → 현 → 지역권

```text
계층            규모(블록)   구현체                          상태
─────────────────────────────────────────────────────────────────
마을/거점 견본    61x61      CheonghaBuilder.java (자바 인라인)  M2b ✅ 본 문서 문법 적용
현/도시(청하현성) ~520x520    tools/mapgen/town_compiler.py     골조 ✅ (건물 235채) — 팔레트 미적용
지역권(섬서)     수 km       L1 지형(WorldPainter) + 현·촌락 배치  M3 이후
천하            —           지역권 승격 반복 (스펙만 새로 씀)     M5
```

스케일 불변 문법 (어느 규모든 유지):
- **십자로 + 중심 광장**: 남북대로가 정문(남)·후문(북)을 잇고, 교차점이 광장·우물.
- **문에서 사건으로**: 북문 밖 = north_road(도적·사냥), 남문 밖 = 관도(지역권 연결).
  대문이 곧 지역 그래프의 간선이다.
- **앵커 계약**: 조성기는 `Map<장소명, Location>`을 반환하고 플러그인이 소비한다.
  현 키: `장터 / 청하객잔 / 의뢰소 / 의방 / 전장 / 북쪽_산길` (MvtCommand가 "장터" 참조 — 불변).
- **미배치 장소의 예약**: 흑수나루(수변 필요), 폐사당(외곽 숲), 북쪽 골목 창고(hidden)는
  61x61에 없다 — 현성 스케일에서 배치하되 id는 config에 이미 존재하므로 앵커 키만 추가.

## 5. M3 승격 경로

```text
현재 (M2b): CheonghaBuilder.java — 문법을 자바로 하드코딩. 빠른 검증용.
목표 (M3):  tools/mapgen 컴파일러가 같은 문법을 스펙 구동으로 생성, 플러그인은 바인딩만 소비.

이관 순서
1. 팔레트 이관 — 본 문서 2장 대응표를 generators.py의 팔레트 상수로 옮기고
   town_compiler 건물 235채에 목골·백벽·흑와 + 팔작지붕 적용.
2. 건물 스펙화 — 3장 표를 config/map_spec/*.yml의 파라미터로 (풋프린트·벽고·집기 목록).
   CheonghaBuilder의 house()/hipRoof()가 파라메트릭 생성기의 참조 구현.
3. 바인딩 역전 — 조성기가 반환하던 앵커 Map을 컴파일러 산출 YAML로 대체,
   HoncheonMvt.setAnchors()가 파일을 읽도록 전환. 앵커 키 이름은 그대로 유지.
4. CheonghaBuilder 은퇴 — /혼천 조성이 컴파일러 산출물을 붙여넣는 명령으로 축소.
   (그 전까지 CheonghaBuilder가 시각 검증대 역할)

승격 판정 체크리스트
- [ ] 재조성 2회 → 블록 단위 동일 (결정론)
- [ ] config locations 전부에 앵커 존재 (hidden 포함 — 노출은 게임 로직 몫)
- [ ] NPC 5인이 각자 건물 안에 서 있음 (한백이 객잔에)
- [ ] 장터 반경 15 매각 규칙이 노점 위치와 정합
- [ ] 스크린샷 렌더 검토 — 수묵 3색이 화면 지배, 채색은 차양·등롱·매화뿐
```
