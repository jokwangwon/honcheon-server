# PostgreSQL 전환 설계

## 결정

PostgreSQL을 목표 저장소로 채택한다. 다만 드라이버 교체부터 하지 않는다. 현재 `Db`는 단일 JDBC 연결과 전역 `synchronized`로 읽기와 쓰기를 모두 직렬화하므로, 먼저 저장소 포트와 트랜잭션 경계를 분리한다.

현재 운영 데이터 크기는 전환의 원인이 아니다. 전환 이유는 향후 다중 사용자, 여러 런타임 인스턴스, 행 단위 충돌 제어, 온라인 운영 도구를 수용할 구조가 필요하기 때문이다.

## 불변식

- 세계 상태의 정본은 하나다.
- MVT가 저장소 구현을 직접 소유하지 않는다.
- 이벤트 멱등 키와 업무 트랜잭션은 백엔드 변경 뒤에도 유지한다.
- PostgreSQL에서도 같은 aggregate를 무제한 동시 수정하지 않는다. 행 잠금이나 버전 충돌로 순서를 판정한다.
- 이관 중 dual-write를 기본값으로 삼지 않는다. 작은 데이터는 정지, 백업, 이관, 검산, 전환이 더 안전하다.

## 작업 분해

| 작업 | 내용 | 의존 | 닫는 조건 |
|---|---|---|---|
| PG-001 | 영속화 계약과 SQLite 종속성 기준선 | 없음 | 인벤토리와 자체 시험 통과 |
| PG-002A | 초기화 관리와 부트스트랩 메타 읽기 포트 | PG-001 | `Reset` 구체 의존 제거, 초기화 통합 시험 통과 |
| PG-002B | 브리지 inbox·신원·스냅숏 포트 | PG-002A | 브리지 구체 의존 제거, 원자성 시험 통과 |
| PG-002C | 캐릭터·세계 원장 업무 포트 | PG-002B | `GameListener` 구체 의존 제거, composition root만 `Db` 인식 |
| PG-003 | 업무 트랜잭션과 SQL 방언 경계 | PG-002C | 포트 계약 시험이 SQLite에서 통과 |
| PG-004 | PostgreSQL 스키마, 마이그레이션, 저장소 구현 | PG-003 | 빈 PostgreSQL에서 계약 시험 통과 |
| PG-005 | SQLite 데이터 export/import와 검산 | PG-004 | 행 수, FK, 원장 합계, 멱등 키 일치 |
| PG-006 | 연결 풀, 동시성 제어, 관측 지표 | PG-004 | 전역 직렬화 없이 충돌 시험 통과 |
| PG-007 | 스테이징 전환과 장애 복귀 훈련 | PG-005, PG-006 | 컷오버와 롤백 모두 재현 |
| PG-008 | 운영 전환 후 SQLite 경로 제거 | PG-007 | 복귀 보존 기간 종료와 문서 갱신 |

각 작업은 앞 단계가 닫힌 뒤 하나씩 활성화한다. B-004 같은 DB 비의존 P0 작업만 병렬로 허용한다.

## 현재 기준선

기계 기준선은 `python3 tools/persistence_inventory.py`가 만든다. 수치를 문서에 하드코딩하지 않아 이후 분리 작업이 결합도를 실제로 낮추는지 매 단계 다시 잰다.
