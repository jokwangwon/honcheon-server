# 시각효과 자동 검증 하네스 — 강화 계획 (2026-07-20)

## 왜 강화하는가

검기 작업에서 하네스를 세웠고 실제로 작동했다 — 사람 없이 네 각도를 촬영하고 면적·좌표를
잰다. 그런데 **하루에 일곱 번, 측정이 조용히 거짓말했다.** 전부 측정 *결과*가 아니라
측정 *조건*이 틀린 경우였다:

| # | 무엇이 틀렸나 | 어떻게 드러났나 |
|---|---|---|
| 1 | 검출 문턱(g>150)이 검기 실제 색(g≈86)과 안 맞음 | 모든 측정 0px → "뒤에서 58배 작아진다"는 거짓 결론 |
| 2 | 카메라 봇이 리소스팩을 **무로그로** 무시 (servers.dat acceptTextures) | 모델이 안 뜨는데 "검기 없음"으로 읽음 |
| 3 | HUD 초록 글자(「막기」)를 효과로 셈 | "389프레임 내내 효과가 떠 있다" |
| 4 | 결과 파서 정규식이 실제 출력 형식과 불일치 | 전 조합 0px |
| 5 | 클라 프로세스 52개 누수 | 가용 메모리 1GB → 측정 실패 |
| 6 | 서버가 **기동 때 잰** 팩 sha1 을 계속 씀 (팩을 새로 배포해도 모름) | 옛 텍스처를 보며 "새 형태가 반영 안 됨"으로 오판 |
| 7 | 죽은 서버의 옛 로그를 읽음 (새 서버는 다른 파일에 씀) | 옛 sha1 을 최신으로 착각 |

**결론: 지금 하네스는 「보조 눈」으로는 쓸 만하지만 「판단의 근거」로 단독 신뢰하기엔 이르다.**
숫자를 뱉기 전에 **제 눈이 성한지 스스로 시험하는 층**이 없다.

## 원칙

1. **조용히 틀리지 않는다.** 전제가 깨지면 측정을 **거부하고 소리내어 알린다** (0 을 반환하지 않는다 —
   0 은 "효과가 없다"로 읽히기 때문이다).
2. **눈을 시험하는 눈.** 검출기 자체를 알려진 정답으로 self-test 한다 (이 저장소의 감사 관례와 같다).
3. **일반화.** 검기 전용이 아니라 **임의의 대상·임의의 효과·임의의 발동**을 잴 수 있어야 한다
   (보스·몹 스킬 검증이 다음 용처다).

---

## A. 신뢰성 층 — preflight (최우선)

측정 **직전에** 아래를 검사하고, 하나라도 어긋나면 **중단**한다. `--force` 로만 무시 가능.

| 검사 | 방법 | 실패 시 메시지 |
|---|---|---|
| 팩 사슬 | ① 배포 zip sha1 ② 서버가 로그에 적은 「배급 준비 sha1」 ③ 봇이 받은 `?v=` — **셋이 같은가** | "서버가 옛 팩을 잰다 — 재기동하라" |
| jar | `plugins/*.jar` mtime ≥ `build/libs/*.jar` mtime | "옛 jar 로 돈다 — 재배포하라" |
| config | 시험할 키가 저장소 config 와 플러그인 config 에서 같은가 | "config 미동기화 — 키 X 가 다르다" |
| 로그 | 읽는 로그 파일이 **지금 도는 프로세스**의 것인가 (mtime·PID 대조) | "죽은 서버의 옛 로그를 읽고 있다" |
| 클라 생존 | 창 존재 + **게임 화면 진입**(스플래시·로딩 배제) | 기존 로직 유지·강화 |
| 시점 | 요청한 각도인지 **화면으로** 확인 | 기존 로직 유지 |
| 자원 | 가용 메모리 ≥ 8GB · 누수 클라 0 | "메모리 부족 — 옛 클라를 거둔다" |

## B. 검출 보정 — 문턱을 추측하지 않는다

지금은 문턱이 코드에 박혀 있다(검기 초록 전용). 대신:

1. **기준선 촬영**: 효과 발동 전 유휴 프레임 N장 → 배경·HUD 의 정적 마스크를 만든다 (기존 static_green 일반화).
2. **효과 색 자동 추정**: 발동 후 프레임에서 기준선과 **달라진 픽셀**을 모아 색 분포를 낸다.
   문턱을 사람이 적지 않고 **차분에서 유도**한다.
3. **self-test**: 합성 이미지(알려진 색·면적)를 넣어 검출기가 정답을 맞히는지 매 실행 검사.
   틀리면 측정 거부. — *"눈을 시험하는 눈이 통과할 때만 위반 0 건을 믿어라"*

## C. 일반화 — 보스·몹 스킬 검증

| 지금 | 강화 후 |
|---|---|
| 대상 = kigibot 고정 | `--target <선택자>` — 임의 엔티티(보스·몹)를 카메라가 조준 |
| 발동 = 좌클릭 고정 | `--trigger "<rcon 명령>"` — 임의 스킬 발동 (한글 명령도 RCON 으로는 된다) |
| 무대 = 흰 콘크리트 평지 | `--stage <flat|arena|none>` — 보스전은 넓은 무대가 필요 |
| 1회 측정 | `--repeat N` — 편차가 큰 효과를 반복해 중앙값을 낸다 (검기 회차 편차 2배를 겪었다) |
| 산출 = 면적·좌표 | + **지속시간·색 분포·프레임별 궤적** (스킬은 "얼마나 오래·어디로" 가 중요하다) |

## D. 위생

- **클라 수명 관리**: 새로 띄우기 전 같은 work-dir 의 옛 클라를 거둔다 (구현됨) + 종료 시 정리.
- **로그 지정**: 항상 지금 도는 프로세스의 로그를 찾아 읽는다 (파일명 고정 금지).
- **결과 보존**: 실행마다 `preflight` 결과를 결과 폴더에 함께 남긴다 — 나중에 "그때 조건이 뭐였나"를 답할 수 있게.

---

## 단계

1. **A(preflight) + D(위생)** — 거짓 결론을 막는 것이 최우선. 이것만으로 오늘 실패 7건 중 5건이 막힌다.
2. **B(검출 보정 + self-test)** — 나머지 2건(문턱·파서)을 막는다.
3. **C(일반화)** — 보스·몹으로 확장.

각 단계는 **실제 측정으로 증명**한다 (스크린샷 + 수치). 구현했다는 말로는 닫지 않는다.
