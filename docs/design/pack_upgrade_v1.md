## 1. 원칙

1. **계약 불변**: 슬롯(PUA 코드포인트·CMD 키·파일 경로)·등록부 스키마를 바꾸지 않는다. PNG 내용만 승격 → 코드 무수정으로 아트가 오른다.
2. **결정론 유지**: 빌더는 순수 함수(좌표해시·수학)로만 그린다. 같은 소스 → 같은 zip sha1.
3. **감사 먼저**: 승격 후 `texture_audit`(색 대비 계약: 자연 채도≥46 vs 자재≤25)·`model_key_audit`·`pack_gate_audit` 전부 통과. 자기시험 있는 감사만 믿는다.
4. **사람 눈이 확정**: 아트 품질은 감사가 못 잰다. 트랙마다 오프라인 미리보기 시트(PNG 몽타주)를 뽑아 사용자 확인 → 인게임 확정. (화산 지형의 교훈: 자기시험 통과 ≠ 인상 통과)
5. **지어내지 않는다**: 문파 문양·사운드 성격 등 정본 없는 결정은 잠정 표기 + 사용자 결정 회차.

## 2. 단계

### 0단계 — 빌더 분할 (병렬화의 열쇠, 단일 에이전트)
`tools/build_resourcepack.py`(8789줄 단일 파일)를 `tools/respack/` 패키지로 기계 분할.
- 모듈: `core`(png·팔레트·해시·획) / `weapons`(명병 포함) / `items`(재화·환약·짐승가죽) / `blocks`(+틴트·프롭·파티클) / `entities`(+몹 형체) / `qi`(무공 획) / `gui`(HUD·컨테이너·폰트 글리프) / `sounds` / `dispatch`(바닐라 오버라이드).
- 진입점 `build_resourcepack.py`는 유지(CLI 동일 · `MYEONGBYEONG` 재수출 — texture_audit이 import).
- **검증 = 분할 전후 산출 트리 해시 완전 동일** (결정론이라 가능). 다르면 실패.

빌드 → zip sha1 → 배포(serve) → **사용자 인게임 눈 확정** → 결정 회차(명병 문양·사운드 성격) → 커밋. 확정 전 커밋 금지(Codex-Fable 원칙: 검증 후 Fable이 커밋).
