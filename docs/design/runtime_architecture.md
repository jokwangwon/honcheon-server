# 런타임 아키텍처 — 처리 속도 · 실시간 판정 · 시간 도약의 운영 적용

> PT-005에서 사용자가 제기한 실서비스 3대 우려(F16)에 대한 설계 답변.
> ① 텍스트 생성 로직의 처리 속도 ② 실시간 게임에서의 동작 처리 ③ 시간 도약의 멀티서버 적용성

---

## 1. 텍스트 서비스의 처리 속도 — 느린 것은 서사뿐이다

### 1.1 진단

턴 하나의 비용을 분해하면:

```text
행동 해석         LLM 또는 규칙       (가변)
판정·자원·세계 정산  룰 엔진             < 10ms   ← Java 엔진 실측 영역
서사 생성         LLM               1.5 ~ 5초  ← 유일한 병목
```

**규칙은 이미 빠르다** (전부 산수 + 표 조회 — 패리티 테스트로 검증된 엔진). 병목은 서사 렌더링 하나다. 따라서 아키텍처 원칙: **엔진이 먼저 전부 계산하고, LLM은 계산된 결과를 문장으로 옮기기만 한다.**

### 1.2 턴 파이프라인 (2단 분리)

```text
입력 → [1단: 엔진] 의도 분류(규칙 우선, 모호할 때만 경량 LLM)
                  → 판정·주사위·자원·NPC·세계 정산 → 구조화 결과 JSON
     → [2단: 렌더] LLM이 JSON을 서사로 변환 (스트리밍 — 첫 문장 체감 <1초)
```

2단 분리의 이점: LLM이 규칙을 틀릴 수 없고(계산이 끝난 뒤에 옴), 렌더 프롬프트가 짧고 정형이라 캐시 적중이 높으며, 장애 시 템플릿 폴백이 가능하다.

### 1.3 속도 최적화 4종

```text
① 턴 유형 분기: 정형 턴(이동·상점·확보 정보 확인 = no_judgment_actions)은
   템플릿 즉답 — LLM 호출 0회. 서사 턴만 LLM.
② 선택지 프리페치: 길라잡이 선택지가 제시된 턴은 다음 턴이 예측 가능하다 —
   PT-005 실측: 사용자 입력의 ~90%가 제시된 선택지였다. 각 선택지의 다음 씬
   뼈대를 백그라운드에서 미리 생성해두면 체감 지연 → 거의 0.
③ 세계 배치는 LLM 무관: 일 단위 소문·세력·지역 정산은 순수 수치 (엔진).
   소문 '대사'는 정확도 밴드별 템플릿 풀 + 사전 생성 (핫패스 밖).
④ 동시성: 유저 세션은 독립, 세계 상태 기입만 단일 작성자 큐 (기존 원칙 재사용).
```

### 1.4 비용 모델

턴당 LLM 호출 ≤ 1회 (프리페치 적중 시 0회 체감). 세계 유지비는 LLM 0회/일.
→ 텍스트 서비스의 한계 비용은 "서사 턴 수 × 렌더 1회"로 수렴한다.

## 2. 실시간 게임(MC)에서의 동작 처리 — 판정은 이벤트 훅이다

### 2.1 핵심: 실시간에는 '턴'이 없지만 '판정 순간'은 있다

주사위 판정은 ms 단위 산수이므로 실시간의 적이 아니다. 문제는 "언제 굴리느냐"다.
답: **행동의 이벤트 훅에서 즉시 계산**하고, 결과를 연출로 보여준다.

| 텍스트 메커니즘 | 실시간 처리 |
|---|---|
| 잠입/은신 판정 | 연속 판정이 아니라 **감지 게이지**: 시야·거리·광량·소음이 게이지를 채우고, 임계 도달 순간 1회 판정 (틱마다 굴리지 않는다 — 성능·체감 모두) |
| 설득/떠보기 | 대화 UI 선택지 → 선택 순간 서버가 숨은 판정 → NPC 반응 연출. 단서 제시 = 인벤토리의 '단서' 항목을 대화에 첨부 (정보량 보정의 UI화) |
| 엿듣기 | 가청 반경 + 은신 상태면 대화 텍스트가 보임 — 판정은 접근 시 1회 |
| 조사 | 상호작용 오브젝트 + 감각 수치별 하이라이트 범위 |
| 전투 | 이미 실시간 액션으로 전환 설계 완료 (skill_mechanics) — 아슬아슬한 성공 = 패링 윈도우 |
| 부수 리스크 | 시스템 이벤트로 물화: 소리 발생, 흔적 오브젝트 스폰, NPC 의심 상태 변화 |
| GM 서사 | 연출(파티클·사운드·타이틀·NPC 대사 풀)로 대체. **LLM은 핫패스에 없다** — 핵심 NPC 자유 대화만 비동기 옵션 |
| 5구간·데드라인 | MC 낮밤 주기 + 실시간 예약 이벤트 (기존 설계) |

### 2.2 지연 예산

판정·게이지·대화 응답 전부 서버 내 산수 → 같은 틱 안에 완결 (<1ms). 지연이 생길 수 있는 유일한 요소(LLM 대화)는 선택 사양이며 비동기 — 게임플레이가 기다리지 않는다.

## 3. 시간 도약과 멀티서버 — 도약은 공유 월드에 들어가지 않는다

### 3.1 이미 그어진 선 (training_and_time.md)

```text
공유 월드에서 개인의 시간 도약은 불가능하다. 등가물이 이미 설계되어 있다:
  텍스트 솔로 세션:   장 도약 (GM 선언) — PT-005의 '겨울~봄 5개월'이 이것
  MC 공유 월드:      수련 상태 선언 + 현실 시간 경과 = 같은 환산표의 다른 인터페이스
                    (배율 예: 현실 1일 = 게임 15일 → '5개월 도약' = 현실 10일 오프라인)
  프롤로그 인스턴스:  1인용 개인 시간축 — 유년기 서사 도약은 여기서만
```

즉 PT-005에서 쓴 도약은 **그대로는 멀티서버에 이식되지 않고, 이식할 필요도 없다** — 같은 정산표를 오프라인 경과가 대신 굴린다. 챕터형 콘텐츠는 "도약이 필요 없는 밀도"로 설계하고, 도약은 콘텐츠 사이의 자연 공백(로그아웃)이 담당한다.

### 3.2 시간축 합류 모델 — 서장(序章) · 출도(出道) · 공유 세계 (확정)

개인 시간축을 무한정 허용하면 시차가 되잡을 수 없이 번진다. 해법은 **합류 사건**:
개인 시간축은 '각자의 튜토리얼'이 끝나는 분기까지만 존재하고, 그 뒤로는 폐지되어
공통 시간축의 세계에 합류한다. (이전 절의 '느슨한 동기'는 이 모델로 대체 — 폐기)

```text
[1] 서장 (개인 시간축 — 샌드박스)
    생성 → 발단의 장 → 성장 장들. 장 도약 자유.
    공유 세계와의 관계: 읽기 배경만 — 기입 없음, 공유 기연 접근 불가 (서장 전용 사건만).
    → 샌드박스이므로 개인 시간이 몇 년을 흘러도 공유 상태가 오염되지 않는다.
       '번짐'이 원천 차단된다.

[2] 출도 (出道) — 합류 사건, 시간의 닻
    서장이 끝나고 강호에 나서는 1회성 분기. 게이트 (셋 중 하나):
      a. 약관(16세) 도달 — 아이 보정 해제 시점과 정합
      b. 삼류 도달 + 서장 핵심 사건의 1차 해소
      c. 플레이어 선언 ("이제 강호로") — 13세 이상
    처리: 캐릭터가 세계 달력의 '현재'에 도착한다. 서장의 개인 연표는 '내력(來歷)'으로
    봉인 — 소문·NPC가 참조할 수 있는 과거가 된다. 미해결 훅(부모 구출 등)은
    개인 스레드로 이관되어, 이제부터 공유 세계 상태에 기록되며 진행된다.
    서장에서 태어난 NPC(문 서생 등)는 개인 스레드 소속 — 공유 세계 등록은 등록제 경유.
    출도는 1회. 되돌아가기 없음.

[3] 공유 세계 (공통 시간축 단일)
    개인 시간축 폐지. 장 도약 없음 — 텍스트도 MC와 같은 시간 모델:
    성장의 시간은 '수련 상태 선언 + 달력 경과'가 담당 (같은 환산표).
    조우는 항상 같은 '현재' — 어긋남이 존재할 수 없다.
```

이 모델의 부수 효과: **텍스트와 MC의 구조가 완전히 동형이 된다** —
서장 = MC의 프롤로그 인스턴스, 출도 = 본서버 입장, 공유 세계 = 단일 달력.
텍스트에서 검증한 서장 콘텐츠(집안 6종 × 발단 7종)가 그대로 MC 온보딩이 된다.

### 3.3 요약표

| | 서장 (텍스트/MC 공통) | 공유 세계 — 텍스트 | 공유 세계 — MC |
|---|---|---|---|
| 시간축 | 개인 (도약 자유) | **공통 달력 단일** | 공통 달력 단일 |
| 세계 상태 | 샌드박스 (기입 없음) | 기록·상호작용 | 기록·상호작용 |
| 성장의 시간 | 장 도약 + 환산표 | 수련 상태 + 환산표 | 수련 상태 + 환산표 |
| 플레이어 조우 | 없음 | 같은 '현재'에서 성립 | 실시간 |
| 기연 | 서장 전용만 | 공유 등록분 (선착순) | 공유 등록분 (선착순) |
